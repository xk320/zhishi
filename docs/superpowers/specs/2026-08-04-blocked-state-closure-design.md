# 任务-000041设计：外部阻塞状态自动闭环

## 问题

任务规范允许真实外部条件阻止任务执行，但可信自动合并规则没有对应的状态迁移。结果是任务文件与看板只能在未合并分支上记录阻塞，`main`仍显示待执行，执行器可能重复认领。

## 设计原则

- 任务文件仍是唯一事实来源；看板只做可复算派生视图。
- 阻塞只记录状态、当前阻塞原因和解除条件，不得夹带合同、范围、交付物或研究结论改写；从`待执行`首次阻塞时，可按固定格式追加执行分支、开始时间和结构化执行记录，已有字段不可改写。
- 阻塞证据由PR正文和任务执行记录提供，但可信脚本只解析结构，不执行不可信内容。
- 迁移必须绑定精确base/head、任务编号、看板行和双评审证据。
- 外部恢复后只能通过独立闭环将阻塞任务转回待执行或需修复，不自动解除。

## 允许迁移

```text
待执行 → 阻塞
执行中 → 阻塞
需修复 → 阻塞
阻塞 → 待执行
阻塞 → 需修复
待评审 → 已完成
```

其中阻塞迁移只允许变更三个任务字段：状态、当前阻塞原因、解除条件；首次从`待执行`阻塞且基线没有开始时间或执行记录时，允许新增固定位置的执行分支、开始时间和追加式执行记录。执行记录只能保存固定八字段，网络目标只允许逻辑别名`ubuntu`，不得出现IP、域名、主机地址、原始日志或凭据。看板任务行必须从原分区移动到阻塞分区并保持机器表头。完成迁移继续要求真实合并提交时间、SHA和PR证据；唯一后继解锁继续只允许阻塞→待执行。

## 失败关闭

重复字段、未知状态、多个任务、错误依赖、看板漂移、合同正文改写、同时完成和阻塞、缺少解除条件、非本仓库PR或SHA变化、未脱敏网络目标均拒绝自动合并。该设计不授予服务器、数据库、生产、账户、凭据或原始数据权限。

## 验证对象

以任务-000031的Ubuntu不可达PR作为阻塞迁移复验对象；不读取远端数据，不生成或修改审计批次。
