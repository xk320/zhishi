# 来源身份复采与标的范围证据合同

<!-- markdownlint-disable MD013 -->

本设计文档对应任务-000072，目标是补齐`ZS-DATA-GAP-001`的可复算来源身份证据，
不修改任务-000029历史合同和批次，也不改变阶段2门禁。

## 证据对象

每条身份声明必须绑定以下不可变键：

```text
资产编号 + 标的 + 输入成员SHA-256 + 证明字段 + 证据记录编号
```

证明字段限定为：来源提供者、交易场所、市场类型、标的身份、精确合约、数据对象、
Schema确切版本、授权边界和字段中文映射。字段值必须来自当前版本化结构化证据，
不得由路径、文件名、表名、字段名或市场常识推断。

## 复采流程

1. 冻结最新`main`中的候选清单、任务-000029合同、任务-000037最终审计批次和任务-000071结构支持证据。
2. 校验结构化证据记录的唯一性、成员指纹、字段范围、声明值和内容指纹。
3. 通过任务合同授权的白名单逻辑别名`ubuntu`只读读取固定元数据；不得读取业务正文。
4. 为BTC和ETH分别产生身份状态、证据定位、限制、解除条件和状态计数。
5. 追加发布脱敏批次；历史批次和原始数据保持不变。

## 状态规则

- `已证明`：所有身份字段均有当前结构化证据，且与只读元数据、Schema版本和授权边界一致。
- `拒绝`：存在明确的当前版本拒绝证据，或资源越界、指纹冲突、权限不满足。
- `无法判定`：证据缺失、只读探针失败、身份冲突未能裁决或结构不完整。

`已证明`只表示身份合同成立，不表示数据质量、时间可见性、历史覆盖、研究准入、
预测优势、胜率、收益或交易许可成立。BTC与ETH分别统计，不跨标的补偿。

## 资源与安全

复采必须串行、有总超时和逐成员超时，限制输出、日志和内存；SSH关闭密码、交互和转发。
远端仅允许固定`information_schema`查询。任何写入、原始数据访问、凭据输出、未来数据、
生产权限或未登记主机均失败关闭。

## 解除范围

缺口清单只能写入精确的标的、交易场所、市场类型、合约、数据对象、Schema版本、批次和指纹。
未被本批次覆盖的范围继续阻塞，且必须在下一次阶段1最终审计中重新复核。
