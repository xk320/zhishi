# 任务-000124设计：阶段1覆盖受限完成合同

## 决策

阶段1允许交付已经验证的有限覆盖窗口，但必须把缺失、晚到成员和不可判定状态保留在候选总体中。覆盖受限交付不改变研究准入、交易许可或真实交易准入边界。

## 一次性可信路由

路由变更类型固定为`阶段1覆盖受限完成合同修订V2`，执行任务固定为000124，目标固定为000098和000106。允许路径仅包含可信资格器、其专项测试、两个目标任务、README、总体计划、阶段1最终审计报告、数据缺口报告、任务124执行记录和看板。路由建立后才允许目标合同修订，且必须逐段匹配基线旧文本与固定新文本SHA-256；未知任务、额外路径、状态迁移、执行记录或历史批次改写均失败关闭。

路由本身必须先以负向测试锁定：错目标、错类型、额外字段、分母缩小、跨标的补偿、未来数据和真实交易放行都不得通过。该路由不可复用到其他任务或阶段。

V2只替代两类旧硬门：任务098固定执行方案第2步中“晚到成员即整批失败”的语义，改为保留候选总体并排除可见集；任务106固定执行方案第11、14步、默认工程决策和允许停止条件中“主网历史证据缺失即不得交付/必须阻塞”的语义，改为覆盖受限交付并保留无法判定。替代优先级仅限这些指定段落，其他步骤、输入输出和安全边界仍以旧合同为准；不能因此开启研究准入、交易许可或真实交易。

## 任务-000098修订边界

- 截止时间固定为来源批次记录的精确决策截止时刻，不修改历史`completed_at`。
- `collected_at`晚于截止时刻的成员仍保留在候选总体，标记为时间边界拒绝/无法判定，不进入可见集。
- 可见集、候选总体、拒绝和缺失计数必须守恒；不能通过删除成员让重放变成全量通过。

## 任务-000106修订边界

- 成本、资金费率、价差、深度和冲击按BTC、ETH、4/8/24/48小时及真实覆盖窗口分别报告。
- 多年历史或主网执行生命周期缺失继续标记为`无法判定`，不使用网络往返、Demo或本地模拟替代。
- 覆盖受限完成只表示证据链可审计，不表示研究优势、胜率、收益、研究准入或交易许可。

## 不可变事实

任务-000098/000106既有合同、执行记录、批次、失败证据和原始数据不删除、不覆盖；本设计只通过新任务合同追加修订规则，后续执行另行产生追加式证据。

## 失败关闭

删除晚到成员、缩小分母、跨标的补偿、使用未来数据、把无法判定改成通过或开启真实交易时，资格必须失败关闭。
