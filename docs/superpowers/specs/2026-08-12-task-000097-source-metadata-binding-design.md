# 任务-000097：任务-000095历史执行元数据绑定修复设计

<!-- markdownlint-disable MD013 -->

## 问题

任务-000095是已经合并并闭环的治理授权任务。它的执行分支、开始时间和PR #255属于历史事实。PR #260使用该授权对任务-000094执行固定八段合同替换时，跨载体检查器却把这些历史字段与当前PR的分支和编号比较，产生`PR_BASELINE_DRIFT`。这不是任务合同漂移，而是源任务与目标交付的载体角色混淆。

## 固定边界

修复只接受同时满足以下条件的场景：

1. 变更类型精确为`任务合同冲突修复`；
2. PR正文唯一关联任务-000095；
3. main中的任务-000095状态为`已完成`，历史执行分支、开始时间和PR字段齐全；
4. 自动合并资格层已证明任务-000095逐字不变，目标只允许任务-000094固定八段替换；
5. 任务-000094保持`待执行`且看板不变。

满足时只停止将源任务历史分支和历史PR绑定到当前目标PR。任何未知任务、普通任务交付、未完成源任务、缺失历史字段或目标额外变化仍失败关闭。

## 验证矩阵

| 场景 | 预期 |
| --- | --- |
| 任务-000095已完成且历史字段齐全，当前PR分支/编号不同 | 通过源任务元数据检查 |
| 源任务状态不是已完成 | 失败关闭 |
| 历史执行分支、开始时间或PR缺失 | 失败关闭 |
| 变更类型不是任务合同冲突修复 | 继续要求绑定当前PR |
| 执行任务不是000095 | 不获得该豁免 |
| 任务-000094不是固定完整替换或看板漂移 | 由既有资格硬门失败关闭 |

## 资源与安全

实现只涉及文本校验和单进程测试，不访问外部数据或服务。内存门保持可用内存不低于20%，磁盘门保持可用空间不低于5GiB，Node堆上限256MiB。无生产、数据库、服务器、权限或交易影响。

## 回滚

回滚实现PR即可恢复旧行为。回滚只会重新阻塞任务-000094合同修复，不会影响数据和生产系统。
