# 《知势》研发中心跨载体冲突处理协议 V1

<!-- markdownlint-disable MD013 -->

## 目的

本设计文档对应任务-000049，作为该任务登记阶段的唯一冲突治理设计依据。

本协议把任务文件、看板、规范、研究范围、分支和Pull Request之间可能出现的冲突，转化为
可复现的检查、保守裁决和可逆修复动作。它不增加新的任务事实源，也不授予低权威载体覆盖
任务合同的权限。

## 权威顺序

冲突裁决按以下顺序读取，序号越小越权威：

1. 资金、数据、凭据和生产安全硬边界；
2. `docs/研发中心/任务/任务-NNNNNN.md`中的任务合同与状态；
3. `AGENTS.md`、`docs/研发中心/任务规范.md`和机器看板模式合同；
4. `docs/研发中心/看板.md`等由任务文件派生的视图；
5. `docs/研发中心/总体计划.md`及研究规范文档；
6. Pull Request、Issue、分支、标签、聊天和评论。

低权威载体只能提供讨论或证据附件，不能覆盖高权威载体。任务文件之间的同级冲突不能由
编号、时间、新旧分支或多数意见自动裁决。

## 冲突分类与裁决

| 代码 | 冲突 | 默认裁决 | 是否允许自动修复 |
| --- | --- | --- | --- |
| `BOARD_DERIVED_DRIFT` | 任务文件与看板行、分区或表头不一致 | 以任务文件和机器模式为准，重建看板计划 | 仅限派生看板 |
| `TASK_DUPLICATE` | 编号重复、重复文件或看板重复映射 | 失败关闭，保留全部证据 | 否 |
| `TASK_CONTRACT_CONFLICT` | 同级任务合同目标、范围或安全边界直接冲突 | 阻塞相关任务，等待新治理任务 | 否 |
| `DEPENDENCY_CYCLE` | 依赖环、未知依赖或状态不满足 | 阻塞后继，不猜测依赖顺序 | 否 |
| `SCOPE_BOUNDARY_DRIFT` | 当前前向标的/尺度/阶段越界或历史内容被误读 | 当前合同从严拒绝，历史记录不改写 | 否 |
| `PR_BASELINE_DRIFT` | PR目标、任务状态、分支或基线SHA不一致 | 重新同步并重新验证，不能沿用旧证据 | 否 |
| `REVIEW_EVIDENCE_STALE` | 评审、测试或资格证据不绑定当前头SHA | 证据失效，重新评审 | 否 |
| `RESOURCE_OR_API_FAILURE` | 内存、磁盘、网络、GitHub API或命令失败 | 失败关闭，记录解除条件 | 否 |
| `UNCLASSIFIED_CONFLICT` | 无法映射到已登记类别的冲突 | 阻塞并创建后继治理任务 | 否 |

## 处理流程

1. 在当前只读基线记录仓库、基线SHA、头SHA、任务编号、来源路径和规则指纹；
2. 对输入做确定性解析，按固定成员顺序生成冲突代码和脱敏摘要；
3. 若仅为`BOARD_DERIVED_DRIFT`，生成不覆盖源合同的可逆修复计划；写入前再次校验基线SHA；
4. 其他冲突一律失败关闭或标记`阻塞`，不得用旧报告、PR正文、Issue或聊天补齐缺失事实；
5. 解决后必须重新运行全部检查并生成新的证据指纹；任何新提交、任务合同或规则指纹变化都会
   使旧证据失效。

## 安全与范围边界

- 现行前向研究范围只接受BTC、ETH及4小时、8小时、24小时、48小时主尺度；历史SOL内容
  保持不可变，只能在历史上下文中出现；
- 不访问服务器、数据库、真实市场数据、账户或凭据；不删除、覆盖或迁移原始数据；
- 不由冲突处理结果推导因果、预测优势、胜率、收益、研究准入或交易许可；
- 资源不足、身份变化、敏感信息、未来数据或不可逆操作均失败关闭。

## 机器结果字段

检查器结果至少包含：`protocol_version`、`repository`、`base_sha`、`head_sha`、`task_id`、
`rule_fingerprint`、`conflict_code`、`authority`、`decision`、`repair_mode`、`evidence_fingerprint`
和`release_condition`。结果不得包含原始日志、网络地址、凭据、账户标识或市场记录。

## 完成与回滚

只有全部检查通过、双只读评审批准、可信自动合并完成并由独立状态闭环PR标记任务完成，
冲突治理才可进入已完成。回滚只允许回滚本任务新增提交；若回滚造成协议或测试缺失，
自动合并和任务执行必须恢复失败关闭。
