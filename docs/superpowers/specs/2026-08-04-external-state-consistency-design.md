# 任务-000043设计：统一外部环境事实与阶段状态声明

## 问题

现行入口有“服务器连接已经恢复”的陈述，但任务-000031保存的脱敏执行证据仍为
`ubuntu`不可达。若执行器以入口文案代替任务文件和证据，会错误认领后继数据任务，或在
没有真实批次时宣称阶段推进。

## 设计

以任务文件为唯一事实源，以最新脱敏探针和任务执行记录为外部事实源。现行文本只使用
四个受限词汇：`未验证`、`可达（仅连接）`、`不可达`、`可达但审计未完成`。`可达（仅连接）`
不等于数据闭环通过；任何数据任务仍须按合同生成真实批次。

证据新鲜度固定为：证据时间必须带时区、不得晚于观察时间，且观察时间与证据时间相差不
超过1小时；超过上限、缺少时区或时间倒置一律视为不可用。唯一恢复路径是从`阻塞`出发，
同时具备新鲜探针、任务-000031合同内的真实只读审计证据，并通过独立状态闭环PR转为
`待执行`或`需修复`；文档、聊天、Issue、PR正文或单独网络探针均不能恢复任务。

历史报告、批次和执行记录保持不变，但必须在机器校验中与现行入口区分。恢复条件固定为：
新鲜的逻辑别名`ubuntu`脱敏探针、任务-000031资源边界内的只读审计成功启动，以及独立
状态闭环PR；文档编辑、聊天或Issue不能解除阻塞。

## 变更边界

- 允许：根目录和`docs/**/*.md`现行状态段落、研发中心治理测试和任务记录；
- 禁止：服务器、数据库、原始数据、生产系统、凭据、交易逻辑、历史批次和历史执行记录；
- 当前保守结论：任务-000031保持`阻塞`，任务-000032至000037继续因依赖阻塞。

## 验证与回滚

使用`验证外部状态一致性.py`和一致性专项测试、全量研发中心测试、MarkdownLint及
`git diff --check`。若需要回滚，
回滚本任务交付PR即可恢复原现行文案，不触碰历史证据；之后必须重新通过一致性校验。
