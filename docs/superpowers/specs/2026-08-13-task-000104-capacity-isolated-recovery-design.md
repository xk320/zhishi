# 任务-000104设计：阶段1模拟研究负载容量与隔离恢复

<!-- markdownlint-disable MD013 -->

## 目标

复用任务-000103已经提交并验证的最终脱敏批次，证明当前阶段1模拟研究负载可以在固定本地资源预算内重复处理，并能从隔离副本恢复为文件和语义一致的批次。任务不重新访问Ubuntu或数据库，不再扫描历史盘。

## 固定方案

采用“同一正式批次的1×、2×、4×串行复验 + 文件级隔离恢复”。压力倍数只描述工程工作量，不扩充市场样本；恢复只针对仓库内不可变证据，不冒充数据库或生产灾备。

没有采用并发压测，因为当前目标是证明固定资源内的可重复处理，并发会增加本机内存风险且不改善研究证据。没有采用多年历史扩容，因为任务-000103没有提供多年订单簿，重复或外推都不能替代真实覆盖。

## 数据流

1. `prepare`冻结任务-000103批次身份、清单、摘要、生命周期结果、工作量档位和资源门。
2. `measure`逐档串行回读清单声明的普通文件，复算文件、成员、生命周期、分组、重放与安全裁决，记录耗时、RSS、处理字节和吞吐。
3. `backup`把精确文件集合复制到任务专属临时目录并逐文件回读。
4. `fault-test`只修改另一个一次性副本，验证指纹漂移必然失败。
5. `restore`从未修改的备份复制到新的隔离目录，重新执行文件和语义验证；全部证据暂存在仓库外受控待发布目录。
6. `validate`比较全部规范结果；随后只删除带有效哨兵的任务临时目录并确认任务临时根无残留。
7. `publish`仅在清理成功后原子发布包含清理结果的脱敏摘要；清理失败时不得形成正式批次。

## 资源与安全

- 全流程单进程，RSS上限256MiB，总时限600秒；
- 临时副本总量上限64MiB，本地可用磁盘至少5GiB，可用内存至少20%；
- 不跟随符号链接，不接受路径逃逸、未声明文件或非普通文件；
- 不访问远端、数据库和市场接口，不修改源批次和其他项目；
- 清理仅限本次随机临时目录，且必须通过允许根目录、哨兵和身份三重验证。

## 结论边界

通过只说明当前512成员、6144生命周期事件、1056分组的正式模拟研究负载能在记录的资源预算内稳定处理和文件级恢复。它不说明新增市场证据、多年容量、真实延迟、生产灾备、胜率、收益、研究准入或交易许可。
