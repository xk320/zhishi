# 任务-000084设计：来源身份声明清单接入与不可变冻结

## 目的

任务-000080至任务-000083已确认仓库入口、固定白名单、数据库注释和严格候选`BASE TABLE`均没有可验证的来源身份声明。任务-000084不从结构相似性推断身份，而是登记一个只接受外部结构化证据、可复算、失败安全的接入合同。没有清单时保持阻塞，不以空结果伪造完成。

## 输入边界

输入必须是版本固定的`source-identity-evidence-1.0` JSON，由数据提供方或数据所有者交付并通过独立文件指纹绑定。每条记录至少绑定：资产编号、标的、当前输入成员SHA-256、证明字段、声明值、证据定位和字段中文映射。证明字段集合固定为来源提供者、交易场所、市场类型、标的身份、精确合约、数据对象、Schema确切版本、授权边界和字段中文映射。聊天、Issue、PR正文、自报字符串、路径、表名、字段名和数据库结构均不是输入证据。

## 冻结与校验

1. 以最新`main`和任务-000083的630个BTC/ETH成员清单冻结成员顺序。
2. 校验JSON版本、未知字段、重复记录、成员SHA-256、声明值、证据定位、Schema/授权指纹和字段映射的确定性字节；任何冲突保持失败安全。
3. BTC、ETH分别校验，禁止跨标的补偿；完整字段证据和当前版本绑定才允许`已证明`。
4. 若对象需要远端辅助复核，只读读取`ubuntu`白名单中的固定元数据，不读取业务正文、价格、成交、订单簿、账户或凭据。
5. 生成追加式不可变批次，记录输入、规则、执行器、授权、成员清单和资源指纹；不覆盖历史批次。

## 状态与缺口裁决

保留候选总体、已观察、已证明、拒绝、无法判定、失败、未成熟和失效计数，并逐标的守恒。证据为空、过期、冲突或权限不足时继续保留阻塞和解除条件；仅按有证据的精确成员范围更新`ZS-DATA-GAP-001`。不改写其他缺口、八个研究叶子、阶段1或阶段2结论。

## 安全与资源

本任务不授予服务器或数据库写入、DDL、权限变更、生产服务、原始数据迁移或交易能力。输入和输出不得含地址、用户名、连接串、密码、令牌、密钥、环境变量、原始远端响应或业务记录。复验串行执行，最多630成员，Node堆上限256MiB，超时、超限、指纹漂移和异常均失败安全。

## 验收与回滚

验收必须覆盖专项、数据、审计、研发中心测试、Python编译、MarkdownLint、敏感扫描、差异检查和一次真实只读批次；PR需双只读评审和main可信复验。清单缺失时不进入执行，登记PR回滚不会触碰数据或系统；已发布批次仅可通过独立状态闭环撤销，不覆盖历史证据。

本设计不产生来源身份、质量、时间、因果、预测优势、胜率、收益、研究准入或交易许可结论，也不改变4小时、8小时、24小时、48小时主研究尺度及15分钟/1小时事后观察窗口边界。
