# 阶段1新候选集替代路线设计

<!-- markdownlint-disable MD013 -->

- 设计版本：`stage1-candidate-route-replacement/1.0`
- 关联任务：任务-000093
- 决策状态：已批准执行
- 生效条件：任务-000093登记进入`main`

## 一、决策

阶段1当前正式输入路线改为任务-000092最终批次中的Binance已证明归档成员。任务-000084的Ubuntu旧630成员路线保留为历史事实，但不再决定当前阶段门禁，也不再要求自动执行器继续寻找无法由项目自行生成的外部声明清单。

这项替代只更换“当前正式输入候选”的来源，不回写历史，不把旧路线的拒绝或无法判定迁移到新路线，也不把来源身份通过等同于阶段1或阶段2通过。

## 二、为什么替代

旧路线的解除条件依赖第三方结构化来源身份声明，而项目没有独立数据提供方，重复扫描文件、数据库元数据和目录名称不能产生该声明。任务-000092的新路线则对本地Binance归档完成了以下闭环：

1. 本地ZIP与同名CHECKSUM配对；
2. ZIP内容SHA-256与CHECKSUM全等；
3. Binance公开对象键存在且对象大小一致；
4. 本地CHECKSUM对象内容MD5与官方小对象ETag一致；
5. ZIP结构、Schema指纹、授权边界和中文字段映射可复算。

最终批次候选5387、已证明5180、拒绝207；这比旧路线的“已证明0”形成了新的可执行证据基础。

## 三、正式输入身份

正式输入版本由以下不可变元组确定：

```text
任务编号 + 任务-000092最终批次ID + 任务-000092批次文件SHA集合
+ 成员清单SHA + 规则SHA + 执行器SHA + Schema指纹 + 授权指纹
+ 源目录清单指纹 + 任务-000093采纳规则SHA
```

只有任务-000092最终批次中成员状态为`已证明`、且本地相对路径、文件大小、内容SHA、数据对象、精确合约和Schema全部复验一致的成员才能进入正式输入。拒绝、无法判定、失败、未成熟、失效和观察项不得进入已采纳成员，但必须留在计数和证据中。

成员确定性顺序固定为：

```text
标的 → 精确合约 → 数据对象 → 事件日期 → 相对路径 → 内容SHA-256
```

## 四、旧路线处理

- 不修改任务-000084任务文件、状态、分母、成员或历史批次。
- 不声明旧630成员后来获得证明，不建立新旧成员一一映射。
- 最新README、总体计划、阶段路线、最终审计报告和缺口清单必须把任务-000084标记为“历史非门禁路线”。
- 看板仍可保留任务-000084的阻塞事实，但必须区分“任务自身仍阻塞”和“当前阶段不再被它阻塞”。
- 回滚任务-000093时，派生文档恢复旧路线的门禁地位；历史文件始终不变。

## 五、新路线门禁

每个`BTC/ETH × 4小时/8小时/24小时/48小时`叶子独立裁决以下八门：

| 硬门 | 新路线最低证据 |
| --- | --- |
| 来源身份 | 任务-000092已证明成员及任务-000093正式输入身份闭合 |
| 三类时间 | 事件时间、到达时间、采集时间、时区、可见性与截止时点均可证明 |
| 质量 | 同一正式输入上的断档、重复、乱序、异常和解析结果可复算 |
| 历史重放 | 冻结输入、代码、配置、依赖、随机性和历史决策现场可重建 |
| 成本与执行 | 手续费、价差、深度、冲击、资金费率、延迟来源与时间可用 |
| 血缘 | 原始成员到研究叶子可双向定位，所有转换内容寻址 |
| 容量 | 非零真实成员下的空间、内存、时间、索引和增长证据通过 |
| 恢复 | 不修改原始数据的隔离恢复与重放演练通过 |

任一门为拒绝、无法判定、失败、未成熟或失效，叶子即阻塞。BTC和ETH不得互相补偿，聚合成交和逐笔成交不得互相冒充。15分钟、1小时只能是事后结果观察窗口。

## 六、执行数据流

```text
任务-000092最终批次
  → 只选已证明成员并复验本地内容绑定
  → 冻结阶段1正式输入版本
  → 生成按标的/对象/日期的覆盖与结构证据
  → 逐项匹配同版本历史证据
  → 重算BTC/ETH × 4h/8h/24h/48h八叶子
  → 输出允许研究范围或精确剩余缺口
```

旧任务-000084只进入历史引用，不进入上述数据流。

## 七、真实性边界

- 来源身份闭合只能回答“这些字节来自哪个已验证归档对象”，不能回答数据是否无断档、无重复、无异常或足以研究。
- 首末行和有界结构检查不能替代全量逐行质量审计。
- 公开归档缺少到达时间或采集时间时必须记为无法判定，不能用事件时间复制补齐。
- 描述性覆盖差异不能推导因果、预测优势、胜率、收益、研究准入或交易许可。
- 只有八叶子全部硬门通过，阶段1才完成；路线替代本身不触发阶段2放行。

## 八、资源与安全

执行器使用单进程、流式、有界读取，目标最大RSS不超过256MiB。源目录只读，不解压落盘，不保存价格、数量或成交业务行；仓库交付不超过25MiB。禁止访问Ubuntu、数据库、订单簿、账户、凭据和生产系统，禁止修改原始数据或执行交易。

## 九、成功判据

替代成功必须同时满足：

1. 新正式输入成员和全部指纹可复算；
2. 任务-000092的207个拒绝成员未被漂白；
3. 任务-000084历史字节未改写且不再是当前门禁；
4. 八叶子基于新输入得出真实裁决；
5. 阶段文档只报告有证据的通过项和明确的剩余缺口；
6. 能从新缺口直接形成后续可执行合同，不再回到旧630身份声明循环。
