# 任务-000106：阶段1多年成本与真实执行延迟闭环设计

## 目标

以任务-000105冻结的八叶子和唯一缺口`ZS-DATA-GAP-008`为基线，只补多年成本与真实执行延迟证据，不再扫描任务-000094的854GB成交归档，也不回到旧630成员路线。交付必须区分“公开市场成本事实”“Demo虚拟委托执行代理”和“研究裁决”，任何一层缺证都失败关闭。

## 数据流

```text
                 ↓

```

## 来源与语义边界

- 公开归档只允许Binance官方数据域中事前冻结的BTCUSDT、ETHUSDT精确对象；按月/日清单增量获取并逐文件核对官方校验和，不做桶级、磁盘级或全主机递归扫描。
- `fundingRate`用于资金费率，`bookTicker`用于最佳买卖价差，`bookDepth`只在其字段、抽样频率和覆盖能够支持固定名义规模时用于深度与冲击；不从成交价倒推历史订单簿。
- 手续费仅接受可定位版本的公开非账户费率或能证明覆盖上界的保守费率合同；当前费率不得无证据回填历史，VIP、返佣和账户优惠不得猜测。
- Demo遥测固定为当前非生产代理层，只能校准模拟执行器，不能证明多年正式输入的主网真实执行延迟，也不能让八叶子成本与执行门通过。真实执行延迟通过必须另有与正式输入版本和历史窗口一一绑定的主网委托生命周期证据；本任务不创建主网订单。
- Demo只使用虚拟资产，不连接主网交易端点；不得打印、落盘或提交凭据。凭据缺失不阻止公开成本链完成，但对应代理层和真实执行门都必须保持`无法判定`并输出唯一解除条件。
- 阶段1最终门禁采用新增V2配置和独立批次消费第六项输入；任务-000105的V1配置、五输入验证语义、正式批次和结果SHA必须持续可复验，不以原地升级破坏历史证据。

## 增量与资源策略

执行器先读取任务-000105正式批次和既有来源清单，生成精确缺失对象列表；只对列表中的官方对象执行HEAD/GET，下载到`/Volumes/data/zhishi`的任务专属追加目录。先按月和边界日采样验证Schema与容量，再串行补齐，不并发下载。Ubuntu数据库只允许固定表、固定标的和固定时间边界的索引查询；每条查询先验证计划，禁止`ALL/index`扫描。

测试、下载、转换和裁决均单进程。峰值RSS上限512MiB，本地工作集上限20GiB，单个下载上限2GiB，总网络读取上限20GiB，总时限六小时；可用内存低于20%或项目数据卷剩余空间低于30GiB时不得开始新下载。中断后按内容指纹续跑，不重复获取已验证对象。

## 失败语义

官方校验和、Schema、时间边界、样本频率、标的、合约或输入版本任一漂移时拒绝对应来源；成本要素不得互相补偿。BTC和ETH、四个主尺度分别裁决，15分钟和1小时仅为事后观察窗口。Demo代理无论样本多少都不得升级为主网历史执行证据；不存在合格主网生命周期证据时，任务在交付可执行部分后进入`阻塞`而不是`已完成`。

## 验证策略

- 单元测试覆盖精确前缀、增量清单、官方校验和、Schema漂移、当前值回填、标的隔离、尺度隔离、测试网主网隔离、凭据脱敏、未来数据、资源门和中断续跑。
- 集成验证只运行一条串行管线，并对同一冻结输入完成两次独立重放。
- 两个独立只读评审者分别检查治理/架构与范围/安全；P0或P1问题自动修复后全部重验。
