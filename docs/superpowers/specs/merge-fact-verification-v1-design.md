# 可信合并事实复算 V1 设计

<!-- markdownlint-disable MD013 -->

本设计对应任务-000065。目标是在不信任提交文案、不重写Git历史的前提下，复算已经进入`main`的合并事实。

## 现行路径

标准合并提交主题`Merge pull request #N from ...`仍是首选路径。校验器读取任务文件中的精确SHA、合并时间和PR号，
确认SHA是基线祖先，再以提交主题提取PR号并规范化提交时间。标准路径行为和拒绝条件不变。

## 自定义主题兼容路径

只有标准主题匹配失败时，才允许进入兼容路径。兼容路径必须同时满足：

1. 声明的合并SHA已经是基线祖先；
2. `git show --format=%P`返回恰好两个父提交；
3. 第一父提交属于合并前基线，第二父提交包含任务文件执行记录中的交付提交SHA；
4. 交付提交SHA本身是普通Git提交、位于第二父链且不是未来对象；
5. 任务文件包含唯一PR号、执行分支、交付提交SHA和合并时间；
6. 任何字段缺失、父链不符、SHA不在基线或任务合同重复时立即拒绝。

兼容路径不把提交主题、Issue、聊天或PR描述当作事实来源；PR号仅作为任务合同中的关联标识，实际可验证性来自Git父链、精确SHA和任务交付头。

## 失败安全

单父、三父、空父、交付头不在第二父链、声明SHA不在基线、任务交付SHA缺失、重复PR号和无任务文件均拒绝。
兼容路径不能用于普通任务交付资格，只用于合并后状态闭环的历史事实复算。

## 不变边界

本设计不访问网络或服务器，不修改Git对象，不改变研究范围、数据合同、阶段门或真实交易权限。
