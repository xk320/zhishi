# 任务-000003数据资产发现设计

## 一、目标与已确认环境

本设计服务于任务-000003，只读发现目标主机上的运行环境、服务、接口、数据库候选和
BTC、ETH、SOL相关存储资源，形成可重复执行的数据源清单。目标通过SSH别名`ubuntu`
访问；2026-07-28已验证无交互登录成功。

设计阶段的初始只读画像已确认：

- Ubuntu 22.04，时区为`Asia/Shanghai`；
- MySQL、Nginx及多个市场数据相关服务正在运行；
- 相关应用根目录位于`/opt`下；
- 存在CSV、JSONL和SQLite等候选数据文件；
- MySQL业务库可从存储目录发现；初始临时查询未成功。最终固定探针通过清洁环境、
  本地Unix socket和`--no-defaults`仅查询`information_schema.TABLES`，已成功取得
  库表元数据，结果以数据源清单的发现批次为准。

上述事实只证明资源存在，不证明数据完整、可重放或可用于研究。

## 二、方案选择

### 方案A：本地脚本通过SSH执行固定只读探针（采用）

本地Python脚本调用系统SSH客户端，把固定探针发送到远端标准输入。探针只读取操作
系统、服务、监听端口、目录和文件元数据，结果通过标准输出返回，不在服务器写文件。

优点：可测试、可重复、无需部署、权限边界明确。缺点：依赖SSH与远端Python。

### 方案B：维护Shell命令清单

优点：实现短。缺点：输出解析脆弱，转义风险高，难以证明没有意外读取敏感内容。

### 方案C：部署常驻采集器

优点：可持续采集。缺点：会修改生产环境，引入服务、权限和运维负担，超出本任务。

## 三、组件与数据流

### 3.1 本地命令行工具

文件：`scripts/审计/发现数据资产.py`

职责：

1. 校验SSH目标、超时、输出扩展名、普通文件类型和符号链接边界；
2. 以无交互模式调用SSH；
3. 发送版本固定的只读远端探针；
4. 校验探针返回的JSON对象；
5. 归一化、去重、排序并写出防公式注入的CSV；
6. 从同一结果生成Markdown清单；
7. 对无法确认的字段写`未知`或`无法访问`，不猜测。

### 3.2 远端只读探针

探针不落盘，仅收集：

- 主机逻辑身份、操作系统、内核、时区；
- 文件系统挂载点、类型和只读/读写状态，不记录设备序列号；
- 任务相关systemd服务的状态、运行用户和工作目录；
- 监听协议、端口和进程名，不记录对外地址；
- Docker或LXD实例的名称、镜像和状态，不读取环境变量；
- 白名单根目录下的目录及候选数据文件元数据；
- MySQL服务存在性，以及无需新增凭据即可读取的库表元数据。

白名单根目录：

- `/opt/binance-event`
- `/opt/celueqing`
- `/opt/crypto-radar`
- `/opt/event-prob-lab`
- `/opt/orderbook-intelligence-service`
- `/var/lib/mysql`

候选数据格式仅包含CSV、JSONL、NDJSON、Parquet、SQLite、Arrow和Feather。默认忽略
`.git`、虚拟环境、`node_modules`、缓存、`deploy-staging`、部署备份、测试夹具，以及
文件名中明确带`demo`、`example`、`fixture`或`sample`标记的文件，避免把代码副本或
样例误列为生产数据源。

### 3.3 输出合同

CSV文件：`artifacts/审计/数据源清单.csv`。

每行至少包含：资产编号、资产类型、逻辑主机、服务或项目、资源名称、位置、格式、
标的范围、时间范围、字节数、最后修改时间、访问状态、发现证据、限制和后续任务。

Markdown文件：`docs/审计/数据源清单.md`。

文档包含执行边界、环境摘要、数据源汇总、BTC/ETH/SOL覆盖、已知缺口、数据库访问
限制、不可推导结论和复现命令。Markdown与CSV必须来自同一次探针结果。

## 四、安全边界

禁止：

- 读取候选文件内容或计算内容哈希；
- 读取`.env`、密钥、令牌、密码、SSH私钥或容器环境变量；
- 读取数据库业务记录；
- 从配置文件提取数据库凭据；
- 修改文件、数据库、服务、权限、防火墙、计划任务或系统配置；
- 启停或重启服务；
- 把资源存在写成数据质量、可重放性或研究可用性通过。

数据库元数据查询只允许使用当前无交互身份直接执行。若失败，记录`无法访问`，不得
尝试寻找密码、修改认证或读取配置正文。

## 五、错误处理

- SSH握手失败：不生成成功清单，返回非零状态；
- 单个探针失败：保留其他结果，并为该类别记录失败原因与`无法判定`；
- 路径消失或权限不足：记录路径和状态，不提升权限、不扩大扫描根目录；
- 输出结构非法：拒绝覆盖既有产物；
- 重复资源：按资产类型、规范位置和资源名称去重；完全相同项合并，冲突字段置为
  `未知`并标记`元数据冲突`，不得依赖输入顺序选择任一值；
- 所有时间使用带时区的ISO 8601格式。

两个不同目录下的产物无法形成单次文件系统原子提交。实现保证可捕获异常下同时回滚；
如果回滚自身失败，保留可恢复备份。进程被`SIGKILL`或主机断电时仍可能处于双文件
替换窗口，复核时必须检查CSV与Markdown批次一致。

## 六、测试策略

测试文件：`tests/审计/test_发现数据资产.py`。

按测试驱动顺序覆盖：

1. 固定探针只包含允许的只读能力，不包含写入、服务控制和凭据读取行为；
2. 使用临时假SSH程序返回固定JSON，验证真实命令行流程；
3. CSV列、排序、去重和中文未知状态稳定；
4. Markdown与CSV使用同一批次标识；
5. SSH失败、部分探针失败和非法JSON不会伪造成功；
6. IP地址、凭据模式和环境变量值不会进入交付物；
7. 通过测试后再对`ubuntu`执行一次真实只读发现。

## 七、验收边界

任务-000003只回答“有哪些可验证候选资源、如何重复发现、当前能否读取元数据”。缺失、
重复、乱序、断档、异常、三类时间、历史重放和研究可用性由任务-000004至000006继续
验证。本任务不能形成胜率、收益、交易许可或模型准入结论。
