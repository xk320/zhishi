# 任务-000090 Binance 来源身份自动映射设计

## 目标

在不要求人工逐条映射的前提下，使用仓库已有的 Binance 下载清单、固定本地只读目录和 Binance 公开 `exchangeInfo` 元数据，自动生成可复算的来源身份候选。只有精确证据满足任务-000084的九项身份字段、当前成员 SHA-256、Schema/授权指纹、字段中文映射和唯一证据定位时，才允许产生 `已证明` 候选；其他成员保持 `无法判定`。

## 固定输入

- `/Volumes/data/data/binance/futures/um/klines_1d_manifest.json`
- `/Volumes/data/data/binance/futures/um/full_history_download_summary.json`
- Binance 公开端点：`https://fapi.binance.com/fapi/v1/exchangeInfo`、`https://dapi.binance.com/dapi/v1/exchangeInfo`
- BTC 与 ETH 各 315 个任务-000083成员及其当前成员 SHA-256。

执行器必须拒绝模糊符号、文件名推断、目录推断、聊天说明、跨标的补偿、未来日期、漂移输入和重复绑定。公开接口只能证明当前合约元数据，不能追溯证明历史文件全生命周期。

## 输出绑定

输出严格分成两个相互绑定的层次：

1. `source-identity-evidence-1.0` 保持既有六字段顶层格式：`证据记录编号`、`资产编号`、`标的`、`输入成员SHA-256`、`证明字段`、`声明值`。
2. `来源身份绑定清单-1.0.json` 为每条字段级记录补充 `证据定位`、`字段中文映射指纹`，因此每条绑定记录固定包含八项字段。其 `证据记录编号` 必须等于唯一 `证据定位`，并与六字段顶层记录逐项匹配。

批次元数据必须同时绑定 Schema 确切版本指纹、授权边界指纹、输入清单指纹、规则指纹和执行器指纹。任何绑定清单缺失、重复、漂移或无法复算时，不得把成员标记为 `已证明`。

## 研究与安全边界

- 仅做来源身份和证据结构验证，不读取或保存行情、成交、订单簿、账户、数据库业务记录或凭据。
- 本地目录只读；不得修改、覆盖、迁移原始数据；不访问服务器，不写入数据库，不修改生产服务或权限。
- 不训练模型、不回测、不生成方向、仓位、订单、胜率、收益或交易许可。
- 主研究尺度固定为 4小时、8小时、24小时、48小时；15分钟、1小时只作为事后观察窗口。

## 可复现与失败安全

成员顺序固定按 BTC/ETH、资产编号、成员编号排序；每次批次追加发布、不可覆盖。资源限制为单进程串行、总超时 900 秒、公开接口响应不超过 16MiB、输出不超过 32MiB。超时、超限、输入漂移或字段不全时，清空候选并保留脱敏失败原因。
