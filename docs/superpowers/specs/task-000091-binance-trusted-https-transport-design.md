# 任务-000091 Binance 可信 HTTPS 传输修复设计

<!-- markdownlint-disable MD013 -->

## 问题与目标

任务-000090执行器通过Python `urllib`请求两个固定Binance公开`exchangeInfo`端点时，因本机Python证书信任链报`CERTIFICATE_VERIFY_FAILED`而失败安全；相同端点通过系统`/usr/bin/curl`默认TLS校验返回HTTP 200。故障边界是Python运行时证书信任链，不是网络或Binance端点不可达。

本设计仅替换公开元数据请求的传输适配器，保持任务-000090的输入、成员、九字段证据、匹配、计数、授权、资源和失败安全合同不变。

## 方案比较与固定决策

- 固定系统`curl`传输：复用操作系统可信证书链，当前已实测成功；可固定二进制、参数、超时和指纹，不新增包。采用。
- 为Python显式复制或配置CA文件：不同机器的证书路径和维护方式不一致，可能形成隐式环境依赖；不采用。
- 关闭TLS校验或信任未知自签证书：违反安全边界，不能证明响应来自目标端点；禁止。

固定方案为：通过参数数组直接调用`/usr/bin/curl`，不使用shell、不跟随重定向、不读取账户凭据，保持默认TLS证书和主机名校验。执行器只接收两个配置中全等的HTTPS端点。

## 组件边界

1. 端点校验器：验证协议、主机、路径、HTTP方法和配置白名单全等。
2. 传输适配器：固定`/usr/bin/curl`与允许参数，执行串行请求，输出字节或结构化失败码。
3. 响应边界：在内存中检查退出码、大小、UTF-8、JSON和顶层Schema；完整正文不得进入日志或批次。
4. 既有证据流水线：接收已验证JSON对象，沿用任务-000090的脱敏摘要、SHA-256、精确匹配、身份记录与计数守恒逻辑。
5. 批次发布器：追加不可覆盖批次，绑定输入、规则、执行器、授权、传输器和响应指纹。

每个组件只暴露结构化输入和结果，传输层不得知道成员匹配规则，证据层不得拼接命令或改变TLS配置。

## 数据流

```text
固定配置与端点
    ↓ 全等校验
/usr/bin/curl 默认TLS校验、串行GET
    ↓ 退出码与16MiB边界
内存UTF-8/JSON/Schema验证
    ↓ 响应SHA与脱敏BTC/ETH摘要
任务-000090既有精确映射与九字段门
    ↓ 630成员状态守恒
追加式不可变批次
```

完整API响应不会写盘；批次只保存可复算指纹、脱敏字段摘要、成员状态、计数、错误码和资源事实。

## 传输安全合同

- 固定可执行文件：`/usr/bin/curl`；记录版本、二进制SHA-256和参数指纹。
- 固定端点：`fapi.binance.com/fapi/v1/exchangeInfo`与`dapi.binance.com/dapi/v1/exchangeInfo`，协议仅HTTPS，方法仅GET。
- 禁止shell、重定向、`--insecure`、`-k`、任务生成CA文件、代理凭据和账户接口。
- 单端点连接超时15秒、总超时60秒、响应最大16MiB；批次总超时900秒、日志最大64KiB、输出最大32MiB。
- 标准错误只映射为脱敏错误码与SHA-256，正文截断且不得包含环境变量。

## 错误处理

非白名单端点、TLS失败、curl不存在、非零退出、超时、超限、非UTF-8、非JSON、Schema异常、输入漂移或计数不守恒均返回明确失败码，清空本次证据候选并发布失败安全批次。不得退回未校验TLS，不得在失败后切换端点或缩小成员分母。

公开请求成功只证明当前响应可验证读取，不能单独证明历史文件生成链路、内容、授权或字段映射；这些字段仍由既有九字段合同裁决。

## 测试设计

- 单元测试使用可注入进程运行器，不访问网络，覆盖成功、TLS失败、非零退出、超时、超限、非JSON、非白名单端点和禁用TLS参数拒绝；另以真实本地子进程验证stdout边读边超限终止及stderr截断与完整哈希。
- 回归测试固定630成员与历史批次树指纹，证明传输层变更不改变分母、顺序、匹配和九字段门槛。
- 集成验证执行一次真实串行公开请求和一次本地固定清单只读复验，保存追加批次；不输出完整响应。
- 运行数据、审计、研发中心测试、Python编译、MarkdownLint、敏感扫描和`git diff --check`；main已有失败必须以同命令对照记录。
