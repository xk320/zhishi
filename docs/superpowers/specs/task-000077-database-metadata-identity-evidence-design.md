# 任务-000077：数据库元数据身份与Schema证据复采设计

<!-- markdownlint-disable MD013 -->

本设计对应任务-000077，只补齐任务-000076批次中数据库元数据成员的结构证据，不修改历史批次，不访问业务正文，也不改变阶段1或阶段2门禁。

## 固定方案

唯一方案为方案A“固定information_schema元数据、逐成员失败安全复采与追加式证据快照”。输入固定为任务-000076权威批次中的数据库元数据候选成员，成员按`标的、资产编号、来源成员编号`排序；BTC和ETH分别统计。

## 证据身份

每条证据使用以下不可变关联键：

```text
任务-000076批次ID + 资产编号 + 来源成员编号 + 成员SHA-256 + 数据库/Schema/表/列 + 探针版本
```

结构证据字段限定为数据库逻辑名称的脱敏指纹、Schema和表的存在/类型、列名指纹、列类型指纹、序号摘要、元数据快照时间与授权边界。表名、列名或路径不得单独证明来源提供者、交易场所、市场类型、精确合约或市场时间。

## 复采流程

1. 读取任务-000076批次清单并验证候选成员、SHA-256、标的和确定性顺序。
2. 在本地冻结输入、规则、授权、探针和资源指纹；历史批次只读。
3. 通过逻辑别名`ubuntu`的无交互SSH进入固定入口，仅运行参数化的`information_schema.TABLES`和`information_schema.COLUMNS`查询；禁止业务表正文、价格、成交、订单簿、账户和凭据。
4. 对每个成员串行、有界执行；远端返回只在本地转换为脱敏计数、字段指纹和状态，原始响应不保存。
5. 追加发布批次、统计、失败原因和撤销事实。探针不可达、权限不足、响应冲突或任何越权时保留`无法判定`或失败关闭。

## 状态与解释边界

- `已观察`：成员已进入本批次且输入指纹通过；不等于任何身份或数据质量通过。
- `已证明`：仅表示本合同列明的数据库元数据字段具有当前结构化只读证据，不能推导来源、时间、质量、因果、预测优势、胜率、收益、研究准入或交易许可。
- `拒绝`：明确指纹冲突、作用域越界、权限拒绝或安全规则失败。
- `无法判定`：元数据缺失、探针不可达、字段不完整或结构证据无法裁决。
- `失败`、`未成熟`和`失效`必须保留并计数；不得删除、合并或用其他成员补偿。

## 研究与安全边界

主研究尺度保持4小时、8小时、24小时、48小时；15分钟和1小时只能用于事后结果观察窗口，不能升级为市场状态、事件探测或交易许可尺度。不存在真实阈值、模型、回测、订单或交易信号。远端只读、无凭据、无写入、无原始数据迁移；历史批次追加而不覆盖。

## 验收

输入成员完整、顺序确定、BTC/ETH独立统计、状态计数守恒；每个成员具有可复算的结构证据、指纹、授权和失败原因；只读范围可由执行器和批次指纹复核；未满足身份或其他硬门的范围继续阻塞。验证命令、资源预算和回滚方式以任务-000077合同为准。
