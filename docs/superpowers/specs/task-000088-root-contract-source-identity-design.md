# 任务-000088设计：root兼容只读复验与来源身份输入

## 问题

任务-000085已经固定Binance公开合约元数据与630个BTC/ETH成员的比较逻辑，但专用只读UID=1001不可用时在扫描前失败安全退出。任务-000084现已登记root兼容合同，但该合同只规定边界，不执行复验。若不重新执行，阶段1仍缺少可验证的来源身份输入；若直接把root可读解释为来源证明，则会违反数据证据门槛。

## 设计

本任务采用一个任务专用配置和薄封装入口，复用任务-000085的公开API摘要、成员顺序、字段比较、状态守恒和批次发布逻辑。封装入口只增加显式root兼容身份模式：有效远端事实必须是实际UID=0、逻辑目标`ubuntu`和任务-000084固定探针；普通专用只读模式不被改写。输出只保留脱敏元数据、Schema/路径/成员/规则指纹、计数和失败原因。

候选文件仍限于六个固定根目录、八类固定文件名和`csv/json/sqlite3/db`格式，禁止符号链接和系统目录；数据库候选只读取合同允许的结构/固定字段摘要，不读取业务正文。两个Binance公开`exchangeInfo`端点串行调用，不发送凭据。BTC与ETH各315成员独立统计，只有九项身份字段全部有当前成员绑定、Schema/授权/字段映射和证据定位时才生成`source-identity-evidence-1.0`。

## 失败安全

- UID不是0、SSH失败、协议/路径/字段/分母/指纹漂移、扫描超限、未来日期或敏感输出时清空候选并保留失败原因指纹。
- 失败批次仍记录扫描UID、访问模式、计数、资源事实和接口摘要，但不生成空身份声明文件。
- 候选结构、文件名、表名、字段名、订单簿系统归属或描述性差异不能成为来源身份结论。

## 交付边界

只修改任务-000088允许的配置、脚本、专项测试、合同文档、脱敏批次和任务/看板执行元数据；不修改任务-000084合同/状态、任务-000085历史合同、任务-000086/000087治理合同、可信自动合并脚本或任何生产/数据库/原始数据路径。

## 验证

专项测试必须覆盖root UID正向、UID不匹配、协议/路径/资源漂移、候选为空、九字段完整匹配、
BTC/ETH计数守恒和禁止生成空声明文件；交付前运行任务合同全部命令、真实公开接口、root固定探针、
敏感扫描和`git diff --check`。
