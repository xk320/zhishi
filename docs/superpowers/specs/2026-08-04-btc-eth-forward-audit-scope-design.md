# 前向审计自动化双标的范围收缩设计

## 1. 决策

将当前会生成新验证、审计、发现或容量规划结果的自动化入口统一为 BTC、ETH；SOL
只保留在已发布历史任务、历史批次、历史报告和历史设计记录中，并在规范文本中显式
标记为历史事实。历史文件的内容指纹、计数和结论不回写、不删除、不重算。

## 2. 当前规范性范围

以下文件是本次范围收缩的唯一受控面：

- `config/审计/数据质量持续验证.json`
- `config/审计/最小数据闭环容量.json`
- `scripts/审计/发现数据资产.py`
- `scripts/审计/审计数据质量.py`
- `scripts/审计/持续验证数据质量.py`
- `scripts/审计/验证历史现场重放.py`
- 上述入口的测试和 `docs/研究/数据质量持续验证合同.md`、`docs/架构/最小数据闭环.md`

入口的默认标的列表、作用域校验、报告标题和独立计数只能出现 BTC、ETH。历史产物
仍可包含 SOL，但不能被当前入口作为新研究范围或自动化验证目标。

## 3. 依赖与边界

任务-000028 已建立前向 BTC/ETH 范围和历史证据边界，任务-000041 已建立阻塞状态闭环。
任务-000031 及其后继仍可能因 ubuntu 不可达而阻塞；本任务不访问服务器，也不伪造新的
审计批次，因此不解除这些外部阻塞。

## 4. 验证策略

先为配置和入口增加负向测试：新入口不得接受 SOL，输出不得生成 SOL 统计；再修改实现。
保留历史输入兼容性测试，用来证明历史文件不会被改写。最后运行审计专项测试、研发中心
测试、Markdown lint 和 `git diff --check`。

## 5. 安全与回滚

只修改仓库中的合同、配置、脚本和测试；不读服务器、数据库或真实市场数据，不写原始
数据、生产服务、权限或账户，不训练模型、不回测、不生成交易信号。回滚本任务PR即可
恢复原入口和配置，历史产物始终不变。
