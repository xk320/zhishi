# 任务-000075：来源身份输入指纹漂移修复与复采设计

## 设计结论

任务-000072的复采结果显示身份成员为“已证明0、拒绝12、无法判定618”，任务-000074进一步确认
`ZS-DATA-GAP-001`仍阻塞。下一步必须修复“历史输入与当前main输入指纹不一致”的可验证性问题，
而不是刷新旧SHA或将漂移解释为来源证明。

## 唯一方案

采用方案A“当前main输入重签、逐成员漂移裁决与只读来源身份复采”：

1. 以执行时最新`main`为唯一基线，重新计算资产清单、来源身份合同、结构证据、最终审计和缺口台账指纹。
2. 将历史输入与当前输入的字节差异、允许的规范化差异、真实内容变化、缺失和越界分别记录；历史批次不可覆盖。
3. 在同一冻结版本上复用既有固定来源身份入口，通过`ubuntu`白名单只读元数据获取当前结构化证据；不读业务正文。
4. 以BTC、ETH独立成员顺序追加批次，只把字段齐全且证据绑定当前输入的成员标记为`已证明`。
5. 任何未知、冲突、漂移或越权均保留为拒绝/无法判定并形成解除条件。

## 研究边界

主研究尺度仍为4小时、8小时、24小时、48小时；15分钟和1小时只能作为事后结果观察窗口，不能升级为
市场状态尺度、事件探测尺度或交易许可尺度。本任务不生成研究结果、胜率、收益、方向、仓位或订单。

## 交付与安全

交付为任务专用合同、输入冻结配置、只读执行器/测试、不可变脱敏批次及缺口派生记录。不得修改生产服务、
数据库业务内容、原始数据、订单簿逻辑、权限、防火墙或账户；不得提交凭据、地址、用户名、原始远端响应或未来数据。

## 失败安全

任何指纹漂移、成员遗漏、跨BTC/ETH补偿、远端探针版本不符、输出超限、敏感信息或资源超限都使相关批次
失败关闭；不通过猜测、默认值、共同目录或文件时间补齐来源身份。
