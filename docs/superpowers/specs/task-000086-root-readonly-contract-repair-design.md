# 任务-000086 设计：Ubuntu root 只读兼容模式合同修复通道

## 目标

在不把root解释为专用最小权限账户的前提下，为仍阻塞的任务-000084建立一条可审计、可回滚、单目标的合同修复入口。入口只允许后续PR追加一个完整兼容段落，禁止顺手改写身份合同、状态、数据结论或安全边界。

## 现状证据

- 任务-000084当前要求专用只读UID=1001，并因缺少结构化来源身份清单保持阻塞。
- 任务-000085最终复验记录白名单逻辑别名`ubuntu`实际UID=0，探针在扫描前失败安全，候选和远端追加均为0。
- 历史合约候选文件由root属主维护；这只能解释POSIX访问失败，不能证明来源身份或数据内容。

## 设计

### 两步变更

1. 任务-000086治理交付：在可信规则、文档和测试中固定映射`任务-000086→任务-000084`，定义目标只能新增的单一合同段落，禁止本PR访问远端。
2. 后续合同修复交付：仅新增“Ubuntu root只读兼容模式”段落，记录UID=0与专用UID=1001的差异、固定命令/路径/文件名、无写入和无业务正文边界、资源上限、失败安全和证据字段；目标仍为阻塞。

### root 只读兼容边界

root模式只是执行身份事实，不是授权升级。远端命令必须由固定协议生成，禁止任意shell、任意参数、临时文件、追加、DDL、权限变更、数据库业务记录、凭据、环境变量、价格、成交、订单簿和账户读取。只保存脱敏摘要、指纹、计数、退出码和资源事实；任何异常清空候选并保留失败原因指纹。

### 可复算约束

映射、目标任务编号、目标状态、允许段落的起止标记、段落SHA-256、基线/头SHA、变更类型、PR正文和看板状态由main可信规则复算。Issue、评论和聊天不参与事实判定。

## 测试策略

- 正向：唯一映射、目标保持阻塞、只新增完整段落、固定路径和禁止写入字段均通过。
- 负向：改目标任务、迁移状态、改写其他字段、夹带脚本/配置/数据、扩大根目录/文件名、任意命令、远端写入或敏感字段均失败关闭。
- 回归：任务登记、普通任务交付、状态闭环和既有000056/000068合同修复行为不改变。

## 不执行项

设计和治理实现期间不访问Ubuntu，不创建账户，不读取数据库，不接触真实市场数据，不修改原始数据或订单簿系统。root兼容合同合并后仍需独立任务复验，结果不能解除来源身份缺口。
