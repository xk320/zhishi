# 任务-000113：关闭已取消任务的旧 root 兼容映射

## 目的

任务-000084已由任务-000109替代并进入独立取消闭环。现有任务-000086→任务-000084的阻塞合同修复入口仍要求目标任务保持“阻塞”，与取消后的事实冲突。本设计只关闭该过期入口，防止已取消任务重新获得合同修复资格。

## 方案

在可信资格校验器中明确：任务-000084一旦为“已取消”，任务-000086的旧 root 只读合同修复映射必须失败关闭；测试夹具改为显式合成阻塞基线验证历史允许路径，并新增已取消目标的拒绝断言。不得接受已取消目标、不得恢复状态、不得修改任务084合同或历史批次。

## 范围与安全边界

- 仅修改研发中心可信资格校验器及其测试。
- 不修改服务器、数据库、原始数据、生产服务、权限、凭据或交易逻辑。
- 不放宽 root 兼容模式；root 不等于专用只读身份。
- 失败安全，状态迁移和未知映射一律拒绝。

## 验收

- 基线中任务084为已取消时，任务086 root合同修复资格明确失败。
- 合成阻塞目标的既有正向测试继续通过。
- 研发中心专项测试、Python编译和diff检查通过。
