# 任务-000100成本与执行证据闭环设计

<!-- markdownlint-disable MD013 -->

## 目标

在不修改共享订单簿系统的前提下，把现有Ubuntu订单簿数据库和Binance公开数据接入阶段1新正式输入，形成可复算的成本与执行门证据。

## 数据流

1. 冻结任务-000099结果、探针、SQL模板、公开端点、数据截止和资源预算；
2. 只读探针先返回候选表Schema、授权、估算行数和索引，不对业务表做精确计数；
3. 每个冻结查询先通过`EXPLAIN`索引与扫描成本硬门，再且仅执行一次固定聚合，不导出原始订单簿行；
4. 缺失字段仅从Binance官方公开端点补证，签名或账户端点失败关闭；
5. BTC/ETH八叶分别裁决并原子追加发布。

## 关键设计

- 共享而不侵入：复用同一数据库，但只执行常量化、有界、可审计`SELECT`；
- 事前冻结：任何业务读取前先发布来源和查询意图；
- 历史诚实：当前盘口、当前费率或网络延迟不得回填历史现场；
- 低资源：先元数据后聚合，拒绝`ALL/index`扫描，限定每查询和全批次估算扫描行，不做全盘、全表扫描或导出，原始行不进入Git；
- 语义隔离：三类时间差只是行情可见性延迟；执行延迟等待同现场、版本化模拟委托生命周期证据，不允许替代；
- 失败保守：执行延迟本任务固定无法判定，因此成本与执行总门不得通过。

## 验证重点

验证SQL白名单、表/字段/索引身份、`EXPLAIN`计划与扫描预算、三类时间、行情延迟/执行延迟语义隔离、双标的分组、计数守恒、无写入、输入前后指纹、资源上限、原子发布和派生门禁不越权。

## 回滚

只回滚仓库内新增代码、合同和脱敏批次；远端没有写入，订单簿服务和数据库无需回滚。
