# 任务-000073：三类时间与可见性合同设计

<!-- markdownlint-disable MD013 -->

本设计对应阶段1 P0 缺口`ZS-DATA-GAP-002`。目标是把事件时间、到达时间和采集时间的语义、时区、
时钟漂移、数据截止点、迟到与修订规则固定为可复算合同；不把文件修改时间、路径或字段名称解释为时间证明。

## 固定方案

唯一执行方案为方案A“三类时间语义与可见性冻结”。执行时必须从最新`main`冻结任务-000072来源身份
批次、资产清单、时间相关输入和规则指纹；每个BTC、ETH成员独立登记，禁止跨标的补偿。

## 输出边界

允许交付合同、确定性字段映射、时区与截止规则、时钟漂移证据、失败安全批次和精确缺口范围；不实现运行时、
数据库迁移、模型、回测、模拟交易或交易许可。15分钟和1小时只能作为事后结果观察窗口，4小时、8小时、
24小时、48小时仍是唯一主研究尺度。

## 证据与安全

只允许本地仓库合同和Ubuntu逻辑别名的白名单只读探针，探针串行并有总超时、单成员超时、输出、日志和成员数上限。
不得写入远端、读取凭据或环境变量、修改数据库/原始数据/生产服务、保存业务正文或把未来数据混入当前批次。
无来源、无时区、字段冲突、时钟漂移、截止点未知和修订规则缺失均保持`无法判定`，不得猜测补齐。

## 验收

批次必须保存输入、合同、规则、执行器、成员和结果指纹，BTC/ETH分别计数且覆盖全集；每个成员包含事件/到达/采集
时间状态、时区、截止点、迟到/修订限制和证据定位。`ZS-DATA-GAP-002`只能按标的、市场、合约、数据对象、时间范围和
批次指纹精确部分解除，不能关闭其他缺口或解除阶段2门禁。
