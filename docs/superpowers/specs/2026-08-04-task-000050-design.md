# 任务-000050：跨载体冲突检查完成态回归修复设计

## 设计目的

修复任务-000049合并后在最新`main`上暴露的两项可复现回归：完成态任务在未声明变更类型时
绕过分支与PR绑定，以及历史不可变证据测试依赖运行分支必须存在不同提交。设计保持任务文件
为唯一事实来源，不改变研究范围、历史证据或自动合并工作流。

## 设计边界

- 完成态原交付校验仍要求执行分支、开始时间和Pull Request与当前事件精确一致；
- 只有PR正文严格声明`合并后状态闭环`或`任务登记`时，才使用既有例外；
- 历史证据测试使用合成的基线/头引用和确定性mock，不读取或改写历史文件；
- 不访问服务器、数据库、真实市场数据、账户或凭据。

## 验证设计

1. 以已完成任务的错配分支和PR元数据作为负向夹具，必须产生`PR_BASELINE_DRIFT`；
2. 以明确的状态闭环正文验证例外仍不产生冲突；
3. 以不同与相同Git引用分别运行历史证据变更夹具，均必须产生`SCOPE_BOUNDARY_DRIFT`；
4. 串行运行研发中心、数据、审计、Markdown和差异检查，记录真实结果。

## 回滚与影响

实现只涉及冲突检查器和测试；回滚任务交付提交即可恢复现状。无数据、生产服务、权限、
凭据或外部系统影响。
