# 任务-000076：来源身份字段级证据与授权边界复采设计

## 设计结论

本任务采用唯一方案A：冻结字段映射，复用任务-000075的当前成员和输入指纹，通过Ubuntu白名单只读入口获取字段级身份摘要、Schema/授权快照与脱敏指纹，并逐成员失败安全裁决。它只解决来源身份证据可复算性，不把结构存在性解释成数据质量或交易优势。

## 证据对象

每个BTC/ETH成员固定绑定：来源提供者、交易场所、市场类型、标的、精确合约、数据对象、Schema确切版本、授权边界、字段中文映射、任务-000075成员SHA、当前输入SHA、规则SHA、授权快照SHA、执行器版本和批次身份。成员顺序由`资产编号、标的、数据对象`确定性排序；BTC与ETH不合并、不互相补偿。

## 只读复采边界

- 允许读取`information_schema.TABLES`、`information_schema.COLUMNS`、`information_schema.TABLE_PRIVILEGES`及配置显式登记的身份元数据列。
- 每成员只取一条固定排序摘要，输出只保留值指纹、字段存在性、类型/版本摘要和授权快照指纹，不保存原始值、价格、成交、订单簿、持仓量、资金费率或账户信息。
- 禁止写入服务器、数据库、临时文件或权限；不读取环境变量、凭据和非白名单主机。

## 状态与失败安全

`已证明`要求身份字段、结构证据和授权边界同时完整且指纹一致；任一缺失为`无法判定`，显式冲突、漂移、越权或输入拒绝为`拒绝`或`失败`。批次必须保留候选总体、已观察、拒绝、无法判定、失败、未成熟和失效计数并守恒。没有证据不发布通过；没有成员通过也属于可接受的真实结果。

## 不改变的边界

主研究尺度仍是4小时、8小时、24小时、48小时；15分钟和1小时只作为事后结果观察窗口。任务不实现运行时、模型、回测、模拟交易、真实交易、方向、仓位、订单、胜率、收益或研究准入，也不关闭其他阶段1缺口。所有批次追加发布并保留历史指纹，阶段2继续被最终审计硬门阻塞。
