# 阶段1未完整扫描对象正文授权与资源预算合同 V1

<!-- markdownlint-disable MD013 -->

本设计对应任务-000064，只定义后续正文级审计的治理合同，不执行服务器访问、数据库查询或日志正文读取。
任务-000063已确认97个未完整扫描对象：3个普通文件输入漂移、92个数据库元数据对象、2个敏感系统日志。

## 一、授权分层

| 对象层 | 当前状态 | 后续最低授权 | 本任务动作 |
| --- | --- | --- | --- |
| 3个普通文件输入漂移 | 身份拒绝 | 重新发现后冻结新版本、对象级只读`stat`和内容指纹 | 不读取正文，保持拒绝 |
| 92个数据库对象 | 仅Schema元数据 | 对象白名单、只读账户、最小字段、查询超时和脱敏规则 | 不访问正文，记录未执行 |
| 2个敏感系统日志 | 正文禁止 | 最小必要字段、脱敏方案、只读路径、时间范围和审批记录 | 不访问正文，记录未执行 |

授权必须逐对象绑定资产编号、标的标签、交易场所、合约、版本、路径/表标识的脱敏指纹、授权主体、开始/截止时间和撤销条件。
任何未列对象、未列字段或超出截止时点的读取均视为越界并失败关闭。

## 二、资源预算

后续执行任务必须在执行前冻结以下字段，并在执行后保存实测值：

| 字段 | 要求 |
| --- | --- |
| 最大读取字节 | 按对象设置硬上限，超限停止，不截断为通过 |
| 最大耗时 | 单对象和批次总耗时均有上限，超时状态为失败 |
| 最大并发 | 默认单进程、单对象顺序执行；合同未批准不得并发 |
| 最大内存 | 记录峰值和采样方式，超限失败安全 |
| 临时空间 | 明确是否允许临时文件；默认不允许远端临时写入 |
| 资源实测 | 保存开始/结束时间、退出码、读取量、峰值、超时和清理结果 |
| 停止条件 | 漂移、权限不足、脱敏失败、指纹不一致或输出不完整立即停止 |

资源预算不是取得授权的替代物。没有授权时，即使资源充足也必须保持未执行。

## 三、输入与版本绑定

每个后续批次必须绑定任务-000062/000063的不可变对象清单、成员顺序、规则版本、审计器版本、授权合同版本、
截止时点和内容指纹。事件时间、到达时间、采集时间须分别记录时区、精度、字段来源和可见性；缺失时标记无法判定。
批次只能追加新版本，不能覆盖历史批次或更换分母。

## 四、脱敏输出与状态守恒

允许写入Git的内容仅限资产编号、标的标签、脱敏指纹、版本、计数、资源事实、状态和结构化错误。
禁止写入IP、域名、用户名、密钥、令牌、密码、原始日志、业务正文、账户信息和可逆推出敏感内容的样本。

逐对象状态固定为：`通过`、`拒绝`、`无法判定`、`失败`、`未成熟`、`失效`、`未执行`。每个对象只能有一个最终状态，
成员顺序确定，状态计数之和必须等于候选总体；未知、拒绝、失败和未执行不得填零或被排除。

## 五、研究边界与失败安全

- BTC、ETH分别统计，不能跨标的补偿；SOL不进入前向范围。
- 主研究尺度固定4小时、8小时、24小时、48小时；15分钟、1小时只能作为事后结果观察窗口。
- 描述性差异不能直接解释为因果、预测优势、胜率、收益、研究准入或交易许可。
- 结果可见后不得更换状态分类、筛选对象、修改分组或缩小分母。
- 任一硬门无法证明时，批次和阶段门保持`阻塞`，不得放行阶段2、模型、回测或交易。

## 六、后续执行前核验清单

1. 任务合同引用本设计并列出精确对象集合；

4. 输出目录、成员顺序、版本指纹和追加式批次标识已冻结；
5. 失败、超限、漂移和泄漏均有停止与回滚路径；
6. 若任何一项不满足，任务保持阻塞，不通过猜测补齐。

本设计不授予任何服务器、数据库、日志或生产权限，也不构成阶段1通过证据。
