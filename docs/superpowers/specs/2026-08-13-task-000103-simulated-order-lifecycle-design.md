# 任务-000103设计：版本化模拟委托生命周期证据

<!-- markdownlint-disable MD013 -->

## 目标

为阶段1建立一个可重放、不下真单的模拟委托生命周期，分别记录意图、发送、确认、排队、成交评估、成交或撤销时间。它只解除任务-000100的“模拟执行生命周期缺失”，不用模拟时钟冒充真实交易所延迟，不回填历史成本缺口。

## 方案取舍

- 采用：对现有订单簿快照做有界只读抽样，在本地内存中运行确定性模拟器，仅保存脱敏聚合、状态、时间边界与指纹。
- 不采用真实交易所测速：需要账户、签名端点或真实委托，超出阶段1和安全边界。
- 不采用全历史回放：既有订单簿只覆盖短窗口，扫描854GB成交归档也不能还原历史订单簿，会浪费资源并伪造深度证据。

## 架构

1. `prepare`先冻结任务-000100正式批次、模拟器版本、场景、时间截止、SQL、分组和资源上限。
2. `probe`只读确认Ubuntu逻辑别名、UID=0 root兼容事实、订单簿表Schema、表级`SELECT`和复合索引；MySQL客户不读取默认配置或登录路径。
3. `plan`为BTCUSDT、ETHUSDT分别选取事前截止前的确定性有界快照，只允许命中`symbol+capture_ts_ms`复合索引，并以`capture_ts_ms+snapshot_id`形成唯一全序；复合身份重复时失败关闭。
4. `simulate`对每个成员构造无方向优势的对称审计场景：买/卖、进取型市价/限价与被动限价撤销；时钟使用固定基准/压力场景，不说明真实延迟分布。
5. `replay`从冻结输入重放两次，规范结果指纹必须一致；发布仅追加脱敏证据。

## 生命周期和时间

- 市场事件时间：只接受payload内经来源语义证明且唯一映射的Binance事件时间字段；不得从`capture_ts_ms`、批次时间或模拟时间回填，缺失或歧义时记为未知并关闭市场事件时间门；
- 系统到达／最早可见时间：只在订单簿采集实现或来源合同证明`capture_ts_ms`是在完整响应到达后记录时，才将其绑定为保守最早可见边界；否则记为未知并关闭可见性门；
- 批次采集时间：本批次本地读取、观测和发布的UTC时间，只描述证据生成，不替代前两类来源时间；
- 模拟生命周期时间：在冻结输入及最早可见边界之后生成的意图、发送、确认、排队、成交评估、成交／撤销单调时间线，只表示版本化审计场景。

`capture_ts_ms`的角色必须由来源实现证据裁决，禁止直接称为市场事件时间。任何模拟动作只能消费市场事件时间和最早可见时间均已知且不晚于动作时间的快照；缺任一语义时不得标记防未来数据或生命周期时间门通过。被动限价没有逐笔队列身份时必须进入“撤销／无法判定”，不可根据之后的价格穿越倒推成交。

## 输出

- 不可变意图、来源与查询身份、模拟成员清单、生命周期事件聚合、重放证明、状态分母、资源记录和批次清单；
- BTC和ETH独立保存，4/8/24/48小时主尺度独立引用同一版本执行证据；
- 仅提交计数、时间边界、状态、原因、资源和SHA-256，不提交价格、数量或订单簿正文。

## 保守语义

本任务可证明“模拟委托生命周期可运行且可重放”，不能单独证明真实交易所延迟、多年历史成本、预测优势或交易许可。任务-000100其他未知项保持未知；下一任务只使用本批次和既有正式批次做容量/隔离恢复，不回到旧来源声明循环。

## 验证

验证未来数据拒绝、时间单调、非法状态转移、输入/规则漂移、跨标的补偿、无队列身份伪成交、SQL写入、无索引计划、资源超限、重复发布和敏感输出均失败关闭。

## 回滚

只回滚仓库内模拟器、配置、测试、合同和追加证据；Ubuntu和共享数据库无写入，不需要数据回滚。
