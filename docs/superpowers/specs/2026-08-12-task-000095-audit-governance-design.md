# 任务-000095：任务-000094审计交付治理修复设计

<!-- markdownlint-disable MD013 -->

## 设计结论

采用最小治理修复：只允许`任务-000094`所需的`scripts/审计/*.c`文本源码进入受控数据审计交付；运行拓扑固定为Python主控、固定解压子进程和固定扫描子进程，成员严格串行；资源门使用主进程与子进程峰值之和的保守上界。通过任务-000095到任务-000094的一次性可信映射修复基线合同，不建立通用合同编辑能力。

## 失败事实

PR #252第一轮被路径门拒绝独立`.c`文件；改为`.py`源码载体后虽通过机器资格，但双评审认定为扩展名规避，并发现批次的单进程与RSS事实不真实、合同和执行器指纹没有绑定最终头提交。PR #253尝试如实进入阻塞，又因任务登记基线缺少`解除条件`而被状态闭环拒绝。

## 信任边界

- 仅`main`上的可信校验器可以解释新白名单和一次性映射。
- `.c`只允许位于`scripts/审计/`，必须是普通`100644 blob`、严格UTF-8、小于5MiB且通过敏感扫描。
- 编译与执行仍受任务-000094固定工具路径、源码SHA、进程数、串行顺序、时间、内存和输出硬门约束。
- 任务合同修复只接受固定旧全文片段到固定新全文片段，目标状态和看板不变。

## 资源合同

任务-000094每个时刻最多存在三个相关进程：Python主控、一个解压进程、一个扫描进程。不得并行成员。批次必须记录主进程峰值RSS、全部子进程峰值RSS、两者保守求和、进程拓扑和测量平台；保守和不得超过512MiB。缺失或无法验证时批次失败关闭。

## 回归边界

测试必须证明：审计`.c`允许；其他目录`.c`、`.cc`、头文件、对象、动态库、可执行位、删除、重命名和符号链接拒绝；目标合同额外改一字即拒绝；任务编号、状态、看板或安全范围漂移即拒绝；未知任务不能复用一次性入口。
