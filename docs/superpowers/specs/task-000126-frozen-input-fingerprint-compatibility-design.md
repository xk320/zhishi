# 任务-000126设计：阶段1覆盖受限派生文档的冻结输入指纹兼容

## 设计目的

任务-000124追加覆盖受限说明后，旧来源身份/时间质量合同仍按原始文档SHA拒绝加载。需要增加版本化、追加式兼容映射，而不是删除冻结检查或修改历史批次。

## 固定边界

- 唯一执行任务：任务-000126。
- 唯一输入来源：任务-000124最终头中的两个固定派生追加段。
- 允许配置：`config/数据/三类时间与可见性复采.json`、`config/数据/来源身份复采.json`、`config/数据/来源身份输入指纹复采.json`、`config/数据/数据来源与资产身份.json`中的受影响输入项。
- 旧SHA、旧批次、成员清单和历史合同语义保留；新SHA只对精确追加式正文有效。

## 校验模型

1. 读取旧版本SHA和新版本SHA，验证新版本正文以旧版本正文为前缀并只增加任务-000124固定追加段。
2. 验证追加段完整指纹、任务编号、路径和版本关系；任意中段插入、删除、重排或未知文字失败。
3. 全量审计/数据测试必须在仓库离线环境通过；不得以跳过测试或放宽安全规则替代。

## 不改变的事实

本设计不补采数据、不访问Ubuntu/数据库、不修改任务-000124/000098/000106合同、不迁移任务状态，不产生研究准入、交易许可或真实交易结论。

## 交付验收

配置兼容映射可复算，旧版本可追溯，新增负向边界测试存在，全量测试和格式检查通过后，才允许任务-000124重新进入评审。
