# 任务-000115设计说明：覆盖受限成本证据门

## 决策

阶段1采用“覆盖受限模式”，不再把多年完整成本历史和多年主网真实执行延迟作为当前研究交付的硬门。系统只在已验证的实际覆盖窗口内使用证据；窗口外、对象缺失、时间无法对齐或执行遥测不存在时，结构化结果必须是`无法判定`，而不是通过、估算或填充。

## 适用边界

| 维度 | 规则 |
| --- | --- |
| 标的 | BTC、ETH分别统计，禁止跨标的补偿 |
| 主研究尺度 | 4小时、8小时、24小时、48小时 |
| 事后观察窗口 | 15分钟、1小时，仅用于结果观察，不升级为状态或许可尺度 |
| 成本对象 | 手续费、资金费率、价差、深度、冲击；逐对象记录覆盖与缺失 |
| 执行延迟 | 当前阶段不作为研究硬门；无合格主网生命周期证据时为无法判定 |
| 真实交易 | 当前关闭；本设计不新增账户、权限、订单或生产能力 |

## 覆盖记录合同

每个标的×数据对象×主研究尺度×结果窗口必须保留：

- 固定版本、来源和内容指纹；
- 覆盖起止、事件时间/到达时间/采集时间语义；
- 候选总体、已观察、拒绝、无法判定和失败计数；
- 缺失日期、连续段、样本量和分母；
- 是否允许在该窗口内进入研究计算。

覆盖外不允许缩小分母、插值、回填当前值、跨BTC/ETH补偿或事后选择最佳窗口。描述性差异不等于因果、预测优势、胜率、收益、研究准入或交易许可。

## 主网执行延迟处理

任务-000106已有Demo/代理和投递确认事实可作为限制说明，但不能称为多年主网真实执行延迟。当前研究可以明确记录“未纳入/无法判定”，不再因该缺失阻断覆盖窗口内的成本描述性研究。真实交易或生产部署前，必须另行建立版本化、分标的、可复算的执行生命周期证据合同。

## 历史不可变性

任务-000106原有执行记录、批次、SHA、失败叶子和数据事实保持字节不变。任务-000115只改变当前适用治理解释及派生入口，不追溯改写过去的失败原因，不把旧批次重新声明为通过。

## 失败安全与回滚

若覆盖字段缺失、时间边界冲突、指纹漂移、未来数据或分母不守恒，相关对象保持无法判定并关闭对应研究准入。治理PR回滚后恢复旧硬门语义；不删除任何数据和历史证据。
