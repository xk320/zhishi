# 《知势》研发中心跨载体冲突处理协议 V1

<!-- markdownlint-disable MD013 -->

本协议对应任务-000049的正式交付，统一处理任务文件、看板、规范、研究范围、分支和Pull
Request之间的冲突。它不增加新的任务事实源，也不授予低权威载体覆盖任务合同的权限。

## 权威顺序

1. 资金、数据、凭据和生产安全硬边界；
2. `docs/研发中心/任务/任务-NNNNNN.md`中的任务合同与状态；
3. `AGENTS.md`、任务中心规范和机器看板模式合同；
4. `docs/研发中心/看板.md`等任务文件派生视图；
5. 总体计划和研究规范文档；
6. Pull Request、Issue、分支、标签、聊天和评论。

低权威载体只能提供讨论或证据附件，不能覆盖高权威载体。任务文件之间的同级冲突不能由
编号、时间、新旧分支或多数意见自动裁决。

## 冲突代码与裁决

| 代码 | 触发条件 | 默认裁决 | 可逆修复 |
| --- | --- | --- | --- |
| `BOARD_DERIVED_DRIFT` | 任务文件与看板行、分区或表头不一致 | 以任务文件和机器模式为准，生成看板计划 | 仅派生看板 |
| `TASK_DUPLICATE` | 编号重复、重复文件或无任务看板行 | 失败关闭，保留全部证据 | 否 |
| `TASK_CONTRACT_CONFLICT` | 同级任务合同目标、范围或安全边界冲突 | 阻塞相关任务，登记治理修复 | 否 |
| `DEPENDENCY_CYCLE` | 依赖环、未知依赖或状态顺序不可证明 | 阻塞后继，不猜测顺序 | 否 |
| `SCOPE_BOUNDARY_DRIFT` | 当前范围越界或历史内容被误读 | 从严拒绝，历史记录不改写 | 否 |
| `PR_BASELINE_DRIFT` | PR目标、分支、基线或头SHA变化 | 旧证据失效，重新同步和评审 | 否 |
| `REVIEW_EVIDENCE_STALE` | 评审证据未绑定当前base/head | 旧证据失效，重新评审 | 否 |
| `RESOURCE_OR_API_FAILURE` | 内存、磁盘、网络、API或命令失败 | 失败关闭，记录解除条件 | 否 |
| `UNCLASSIFIED_CONFLICT` | 无法映射到已登记类别 | 阻塞并登记后继治理任务 | 否 |

## 确定性处理流程

1. 记录仓库、base SHA、head SHA、任务编号、规则指纹和允许路径；
2. 以固定成员顺序解析任务文件和机器看板模式，只输出冲突代码、来源路径、裁决、修复模式、
   解除条件及证据指纹；
3. 只有`BOARD_DERIVED_DRIFT`可以生成从任务文件重建看板的可逆计划，写入前必须再次确认
   base SHA未变化；
4. 其他冲突全部失败关闭或标记`阻塞`，不得用Issue、PR正文、聊天、旧报告或猜测补齐事实；
5. 任何新提交、合同、规则指纹、资源状态或评审结果变化都会使旧证据失效。

任务-000049是检查器首次进入`main`的唯一引导例外：可信基线尚无检查器时，自动合并资格
校验器只在同一PR同时新增检查器、正式协议并引用任务-000049的条件下允许继续；它不执行
PR头部代码，而以PR内本地专项验证和双独立评审作为交付证据。该例外一次性使用，后续任何
检查器缺失、路径被替换或入口无法加载均按`UNCLASSIFIED_CONFLICT`失败关闭。

任务交付或状态闭环还必须对base/head中的同一任务合同正文做冻结比较：状态、执行分支、
开始时间、Pull Request、合并SHA和`## 执行记录`属于允许变化的执行证据；目标、固定方案、
输入输出、范围、安全边界、验收标准和历史`## 交付与验收记录`不得在同一PR静默改写。任务文件
中的执行分支、开始时间和PR编号必须分别与GitHub事件的头分支、时间记录和PR编号精确一致。
该精确绑定仅适用于`任务交付`；`合并后状态闭环`使用独立PR，必须保留原交付分支和PR，
并由合并事实校验器绑定新的闭环PR与合并提交。

`阻塞任务合同修复`仅允许main可信规则列出的精确目标字段例外：当前由任务-000056合同
证明任务-000055为唯一目标，只能新增治理自动化授权字段；目标状态、其余合同和历史记录
仍按冻结比较校验，错目标或夹带路径必须失败关闭。

看板修复入口只生成脱敏的演练摘要，不直接写入文件；只要任一已完成任务缺少完整PR与合并
证据，或执行任务缺少分支与开始时间，就拒绝生成修复计划，避免把历史证据替换成占位文本。
评审证据必须恰好包含两个独立评审，资源测量与评审均通过同一检查器的SHA和资源门。

## 当前研究与安全边界

- 当前前向研究范围只接受BTC、ETH及4小时、8小时、24小时、48小时主研究尺度；15分钟、
  1小时只能是事后观察窗口；历史SOL记录保持不可变，只能在历史上下文中出现；
- 不访问服务器、数据库、真实市场数据、真实账户或凭据；不删除、覆盖或迁移原始数据；
- 不由描述性差异推导因果、预测优势、胜率、收益、研究准入或交易许可；
- 资源不足、身份变化、未来数据、敏感信息或不可逆操作均失败关闭。

## 机器结果合同

冲突检查结果至少包含：`protocol_version`、`repository`、`base_sha`、`head_sha`、`task_id`、
`rule_fingerprint`、`conflict_code`、`authority`、`decision`、`repair_mode`、
`evidence_fingerprint`和`release_condition`。结果不得包含原始日志、网络地址、凭据、账户标识
或市场记录。

## 回滚与完成

回滚只允许回滚本任务新增提交，不触碰历史任务、报告或数据。协议、检查器、受限修复入口、
自动合并集成和回归测试均进入`main`，并经双独立只读评审、精确SHA复验、可信自动合并和独立
状态闭环后，任务才能标记`已完成`。未覆盖的新冲突必须保持`阻塞`并登记后继任务。
