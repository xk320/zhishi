# 《知势》最小数据闭环 V1.0

<!-- markdownlint-disable MD013 -->

> 最小不是少保存数据，而是只建设能够证明来源、时间、质量、成本、重放和研究输入
> 血缘的必要链路。

- 文档性质：阶段1数据闭环、存储和恢复合同
- 合同版本：`minimum-data-loop-1.0`
- 容量配置版本：`minimum-loop-capacity-1.0`
- 适用标的：BTC、ETH、SOL
- 适用研究尺度：4小时、8小时、24小时、48小时
- 当前实现状态：架构与容量规划已形成，生产闭环未部署
- 当前阶段权限：不允许进入简单基准模型阶段

## 一、目标与边界

### 1.1 目标

本合同把数据来源、不可变原始记录、标准化对象、质量与血缘、冻结快照、研究只读输入
和审计产物连接为一个可追溯闭环，使系统能够回答：

1. 一条研究输入来自哪个来源、市场、标的和合约；
2. 事件时间、到达时间、采集时间和数据截止时间分别是什么；
3. 原始内容、标准化规则、质量结果和派生过程属于哪个不可变版本；
4. 历史现场是否只使用当时已到达的数据；
5. 手续费、滑点、资金费率、流动性和执行延迟是否进入成本证据；
6. 输入失败、迟到、重复、修订、冻结、查询和失效如何处理；
7. 3个月、6个月和12个月规划容量如何由参数重算；
8. 哪些标的、尺度和研究问题有资格进入下游。

本闭环增强数据门、样本门和成本门，减少来源混用、时间穿越、静默修订、成本遗漏和
不可恢复数据导致的错误交易。

### 1.2 不在范围

本合同不：

- 采集、补采、清洗、迁移、删除或覆盖原始市场数据；
- 实现生产数据库、对象存储、队列、调度、采集服务或特征平台；
- 规定未经试采校准的生产频率、压缩比、保留期或硬件容量；
- 训练模型、运行正式回测、计算胜率或收益；
- 生成研究准入、知识激活或交易许可；
- 用规划容量证明当前服务器具备部署能力。

## 三、核心不变量

1. **原始只读：** 已登记原始段只追加、不覆盖；修订形成新版本。
2. **身份双层：** 逻辑标识表示同一对象，内容指纹表示确切不可变版本。
3. **三类时间独立：** 事件、到达、采集时间不得互相替代。
4. **可见性闭区间：** 历史现场只接受`到达时间 <= 数据截止时间`的记录。
5. **完整血缘：** 任一研究输入可反查全部上游版本，上游失效也能定位下游影响。
6. **质量不改原始：** 去重、填补、重排和异常处置只能生成新标准化版本。
7. **成本不可省略：** 手续费、滑点、资金费率、流动性和执行延迟缺失时，不形成成本后结论。
8. **标的独立：** BTC、ETH、SOL分别验证；BTC或ETH不能补偿SOL。
9. **尺度独立：** 4小时通过不能替代8小时、24小时或48小时证据。
10. **结果只追加：** 成功、失败、拒绝、无法判定和中止均保留。
11. **恢复先验证：** 备份存在不等于可恢复，恢复演练和指纹复核必须通过。
12. **硬门优先：** 任一关键门失败或无法判定，基准模型阶段固定为禁止。

## 四、最小对象与版本合同

### 4.1 数据来源版本

每个来源版本至少记录：

```text
来源逻辑标识与版本标识
提供者、交易场所、市场类型、标的和合约
接口、频道或文件协议
授权边界引用（不保存秘密值）
原始字段与中文语义映射版本
类型、单位、精度和空值语义
三类时间、时区和时钟漂移规则
预期频率、延迟、迟到、补录、修订和撤销规则
有效时间、失效条件和SHA-256
```

### 4.2 不可变原始段

原始段是一次有界接收窗口内的原始记录集合，至少包含：

```text
原始段逻辑标识与内容版本标识
来源版本、市场、标的和合约
事件、到达和采集时间范围
数据截止时间
分区边界和记录数
原始模式版本
接收结果、失败原因和重试关联
前序段或修订来源
成员清单指纹和内容SHA-256
```

逻辑分区建议使用：

```text
raw/<来源版本>/<市场>/<标的>/<UTC日期>/<原始段版本>
```

该路径只用于组织，不能替代内容版本身份。

### 4.3 标准化对象

标准化对象必须引用一个或多个原始段版本，并记录：

- 字段映射、单位、精度和时区规则版本；
- 业务键、排序、重复判定和保留策略；
- 缺失、异常、迟到和修订处置；
- 处理代码、配置、运行环境和执行记录版本；
- 输入与输出记录数、差异清单和内容指纹。

无法证明业务键或时间语义时不得生成正式研究输入。

### 4.4 质量与血缘记录

每个原始段和标准化对象均绑定独立质量记录：

| 维度 | 最小证据 |
| --- | --- |
| 缺失 | 字段、时间段、数量、分母和原因 |
| 延迟 | 到达延迟分布、阈值版本和超时记录 |
| 乱序 | 数量、允许窗口和排序规则 |
| 重复 | 业务键、数量、保留版本和处置血缘 |
| 断档 | 预期频率、范围、数量和解除条件 |
| 异常 | 规则版本、数量、严重度和处置 |
| 修订 | 前序版本、差异、原因和下游影响 |
| 一致性 | 来源、结构、内容和跨分区指纹 |

### 4.5 派生对象与成本证据

派生对象包括K线、特征、标签、成本和执行上下文。最低数据族为：

| 数据族 | 最小作用 | 缺失时处理 |
| --- | --- | --- |
| 成交与价格 | 价格、数量、成交额、主动方向及可复算K线 | 不得形成价格或成交特征 |
| 订单簿与流动性 | 买卖价差、深度、冲击和流动性状态 | 不得形成滑点或执行可行性结论 |
| 衍生品与资金 | 未平仓量、资金费率、基差、爆仓和多空结构 | 不得形成衍生品资金行为结论 |
| 成本与执行 | 手续费规则、滑点、资金费率、延迟和失败 | 不得形成成本后优势 |

派生对象必须保存公式、参数、单位、精度、代码版本、全部上游版本和内容指纹。

### 4.6 冻结快照

冻结快照只引用通过前置门的确切对象版本，至少包含：

```text
快照逻辑标识与版本标识
研究编号和研究版本
数据截止时间
数据对象版本有序集合
标的、市场、合约、尺度和时间范围
质量与成本证据版本
纳入与排除规则版本
成员清单指纹、记录数和SHA-256
冻结时间和失效条件
```

冻结后不得补入晚到或修订记录；需要变化时创建新快照。

### 4.7 研究只读输入

研究运行只能通过快照版本读取数据，不允许：

- 直接读取“最新”表、目录或接口；
- 在运行时根据文件名猜标的和时间；
- 把当前修订版本补入旧快照；
- 跳过质量、成本、重放或作用域检查。

## 五、数据状态路径

### 5.1 正常进入

```text
来源版本登记
  → 原始段只追加并计算指纹
  → 模式与三类时间校验
  → 标准化新版本
  → 质量、成本和血缘记录
  → 冻结快照
  → 研究只读输入
  → 审计与复盘引用
```

### 5.2 失败与重试

- 接收失败生成失败记录，不创建假空段。
- 重试生成新执行编号，引用前次失败，不覆盖日志。
- 部分写入不得发布清单或成功指纹。
- 超时、权限不足、结构漂移和未知响应均失败安全。
- 失败信息只保存分类、范围和脱敏摘要，不回显正文或凭据。

### 5.3 迟到、补录与修订

- 迟到记录进入新原始段并保留真实到达时间。
- 补录必须注明来源、发起原因和补录时间。
- 修订生成新对象版本，保存前序版本和差异指纹。
- 旧快照保持不变；新数据只能进入新快照。
- 受影响的研究、知识、决策和复盘对象必须可反查。

### 5.4 查询与失效

- 查询必须指定确切版本、截止时间和作用域。
- 来源、模式、时间、质量、代码、成本或规则变化使旧结论失效，不会自动迁移。
- 指纹不一致时冻结查询，输出固定原因并重新审计。
- 失效对象不得进入新研究；历史引用保留。

## 六、存储方案

### 6.1 逻辑分层

| 层 | 内容 | 可变性 | 恢复优先级 |
| --- | --- | --- | --- |
| 原始层 | 原始段、接收状态和成员清单 | 只追加 | 最高 |
| 标准层 | 字段统一、单位、时间和去重后的新版本 | 只追加新版本 | 高 |
| 质量血缘层 | 质量、修订、成本、运行和上下游引用 | 只追加 | 最高 |
| 快照层 | 研究可读取的不可变版本集合 | 不可变 | 最高 |
| 派生层 | 特征、标签、报告和可复算中间结果 | 只追加新版本 | 中 |
| 审计层 | 清单、门结果、阻塞和复验记录 | 不可变批次 | 最高 |

当前阶段采用文件分区、内容指纹和小型清单即可表达合同，不引入分布式数据平台。生产
介质、压缩格式、索引和部署由后续独立任务依据试采证据选择。

### 6.2 容量公式

每个数据族的基础容量：

```text
向上取整(86400 / 采样间隔秒数)
× 期限天数
× 标的数
× 每标的数据流数
× 单记录预算字节数
```

随后依次计算：

```text
质量血缘字节数 = 向上取整(基础字节数 × 15 / 100)
副本后字节数 = (基础字节数 + 质量血缘字节数) × 2
安全余量后字节数 = 向上取整(副本后字节数 × 130 / 100)
```

全部计算使用整数，不使用浮点近似。配置中的假设为：

| 数据族 | 每标的数据流数 | 采样间隔 | 单记录预算 |
| --- | ---: | ---: | ---: |
| 成交与价格 | 2 | 1秒 | 256字节 |
| 订单簿与流动性 | 1 | 5秒 | 4096字节 |
| 衍生品与资金 | 4 | 60秒 | 512字节 |
| 成本与执行 | 2 | 60秒 | 512字节 |

这些数字是保守的工程规划输入，不是交易所实测记录大小、生产采样合同或压缩后容量。

### 6.3 规划结果

| 期限 | 天数 | 安全余量后字节数 | 十进制GB | GiB |
| --- | ---: | ---: | ---: | ---: |
| 3个月 | 92 | 98,566,137,448 | 98.566 | 91.797 |
| 6个月 | 183 | 196,060,903,835 | 196.061 | 182.596 |
| 12个月 | 365 | 391,050,436,608 | 391.050 | 364.194 |

结果由`config/审计/最小数据闭环容量.json`和
`scripts/审计/评估最小数据闭环.py`生成。部署前必须用只读试采批次校准频率、实际
记录大小、压缩率、索引、日志、峰值和恢复副本；未经校准不能声称服务器容量充足。

### 6.4 保留、备份与恢复

1. 原始段、来源合同、血缘和快照按不可变版本保留；不得为了腾空间覆盖旧版本。
2. 至少保留两个独立副本；同一磁盘的两个目录不构成独立恢复副本。
3. 备份清单绑定所有成员版本、大小和SHA-256。
4. 每次恢复演练使用隔离目录，不覆盖原始数据。
5. 恢复后逐成员校验指纹、记录数、三类时间范围和快照清单。
6. 任一成员缺失或指纹不一致，恢复结果为失败且不得进入研究。
7. 容量不足时停止新研究输入冻结并记录阻塞，不自动删除原始版本。

## 七、六道闭环门

| 阶段门 | 允许条件 | 当前状态 |
| --- | --- | --- |
| 资产身份门 | 来源、市场、标的、合约和字段合同完整 | 无法判定 |
| 时间门 | 三类时间、时区、截止时间和修订语义完整 | 无法判定 |
| 质量门 | 缺失、延迟、乱序、重复、断档和异常可量化 | 无法判定 |
| 重放门 | 原版本可取得、输入身份稳定且未来数据被拒绝 | 失败 |
| 最小闭环门 | 来源至研究输入及成本证据双向可查 | 无法判定 |
| 研究范围门 | 前五门全部通过并冻结精确作用域 | 禁止 |

后续门可以收集诊断证据，但不能补偿前序硬门。

## 八、失败代码

| 代码 | 含义 | 安全处理 |
| --- | --- | --- |
| `source_identity_unproven` | 来源、市场、标的或合约身份未证明 | 禁止进入标准化与研究 |
| `time_semantics_unproven` | 三类时间或时区不完整 | 禁止历史可见性结论 |
| `input_identity_drift` | 结构、质量或重放阶段身份变化 | 新批次重新冻结 |
| `input_scan_incomplete` | 正文未完整审计 | 保持无法判定 |
| `decision_record_missing` | 缺少来源可证明的历史决策记录 | 不进入正式重放 |
| `cost_evidence_missing` | 成本或执行输入缺失 | 禁止成本后结论 |
| `lineage_incomplete` | 上下游版本无法双向追溯 | 禁止冻结快照 |
| `capacity_unverified` | 容量仅有规划假设或恢复未验证 | 禁止部署结论 |
| `hash_mismatch` | 内容、清单或恢复指纹不一致 | 冻结并重新审计 |

## 九、复验与变更

以下任一变化必须创建新验证批次：

- 新来源、市场、标的、合约、字段或时间尺度；
- 来源模式、频率、三类时间、修订或授权变化；
- 原始、标准化、质量、成本或快照版本变化；
- 容量参数、备份介质、恢复方式或完整性算法变化；
- 审计、重放、标准化或研究输入代码变化。

旧报告和旧快照保持不可变。新批次通过后也不能补写旧研究或旧决策现场。

## 十、当前判断

本合同定义了未来最小闭环，但现有冻结证据没有证明任一BTC、ETH或SOL验证单元同时
通过资产、时间、质量、重放、成本和血缘硬门。因此：

```text
进入简单基准模型阶段：禁止
允许预测性研究范围：无
真实资金交易：关闭
```

解除条件见`docs/审计/数据缺口与补采清单.md`。任何解除都必须形成新任务文件、新验证
批次和新审计结论，不能直接修改本合同的历史判断。
