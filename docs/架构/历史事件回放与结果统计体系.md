# 《知势历史事件回放与结果统计体系》V1.0

<!-- markdownlint-disable MD013 -->

> 回放只重建历史现场并报告差异；结果只追加事后观察；统计不能反向改写事件事实。

- 文档性质：历史事件回放、结果窗口评价与集合统计的技术中立合同
- 适用标的：BTC、ETH、SOL
- 项目主研究尺度：4小时、8小时、24小时、48小时
- 辅助结果观察窗口：15分钟、1小时；仅用于事后标签，不是主研究尺度
- 当前状态：理论架构；未实现回放器、标签程序、统计服务、数据库、模型或交易能力
- 当前数据结论：315个质量验证单元均为`无法判定`；历史重放4个拒绝、311个无法判定、0个通过；简单基准模型阶段为`禁止`
- 真实资金状态：关闭

## 一、目标、边界与决策问题

### 1.1 目标

本体系承接《知势市场事件层架构》的事件事实、确认、结果、失效和事件簇对象，回答：

1. 能否只使用原截止时间前已经到达的冻结输入，确定性重建原事件现场；
2. 重建结果与原事件在成员、顺序、版本、状态和指纹上是否完全一致；
3. 结果窗口何时成熟、读取什么独立快照，以及缺失、拒绝和无法判定如何保留；
4. 如何按事件类型、标的、交易场所、主研究尺度、市场状态版本和结果窗口形成可复算统计；
5. 如何保证15分钟和1小时只描述事后短期反应，不进入事件探测、状态判断或交易许可；
6. 上游版本失效或回放不一致时，如何查询影响并停止未来预测性使用。

本体系主要减少未来数据污染、当前版本替换历史版本、选择性保留成功事件、跨尺度合并、
分母漂移和把事后反应误当预测优势等错误，增强数据门、样本门和研究准入的证据约束。
它不证明任何事件具有稳定胜率、收益、因果关系或交易价值。

### 1.2 不在范围

本体系不：

- 实现事件探测器、回放运行时、标签程序、数据库、服务、队列或调度器；
- 访问、补采、清洗、迁移、删除、覆盖或修订真实市场数据；
- 规定事件规则、价格阈值、结果标签阈值、排除阈值或生产统计门槛；
- 运行正式回测、模型训练、参数优化或收益研究；
- 把15分钟或1小时新增为事件探测、市场状态、研究结论或许可的主时间尺度；
- 生成预测胜率、赔率、净期望、买卖方向、首选标的、仓位、订单或交易许可；
- 用统计结果自动升级研究生命周期、知识关系、质量门或许可状态。

### 1.3 与权威合同的职责边界

| 合同或层 | 本体系读取 | 本体系输出 | 不得替代 |
| --- | --- | --- | --- |
| 最小数据闭环 | 数据来源、质量、快照、三类时间、血缘和指纹确切版本 | 输入清单与版本差异证据 | 不宣布数据可用，不修改上游数据 |
| 市场状态层 | 事件发生时引用的市场状态报告确切版本 | 按确切状态版本分组的统计引用 | 不重算或改写市场状态 |
| 市场事件层 | 事件事实、确认、结果、失效、事件簇及规则版本 | 回放比较、结果评价和统计快照 | 不覆盖任何原事件对象 |
| 研究数据合同 | 冻结方案、快照、环境、评价和血缘语义 | 可申请成为研究输入的版本化材料 | 不批准研究或放宽样本标准 |
| 研究准入 | 假设、基准、成本、样本外、稳健性和淘汰规则 | 覆盖率、失败样本和描述性统计证据 | 不生成准入结论 |
| 决策复盘 | 原决策现场与事后结果分离规则 | 可重放现场与结果集合引用 | 不改写历史决策 |
| 七道质量门与交易许可 | 精确评议和许可边界 | 只提供证据与硬失败引用 | 不判定门通过，不生成许可 |

发生冲突时，资金与数据安全、当时可见性、不可变历史、任务合同、上游对象合同、研究
准入和交易许可硬门依次优先。本体系只能从严停止，不能选择较方便的版本继续。

## 二、核心不变量

未来实现必须同时满足：

1. **原事件不可变：** 回放输出、结果标签和统计快照都不能修改原事件事实。
2. **两阶段隔离：** 历史现场重建与事后结果评价使用不同请求、快照、截止时间和权限域。
3. **原版本优先：** 回放必须加载原Schema、规则、参数、代码、数据、状态和环境版本。
4. **无“最新”回退：** 任一原版本缺失时输出`无法重放`，不能自动使用当前版本。
5. **到达时间约束：** 原事件输入必须满足`到达时间 <= 原事件数据截止时间`。
6. **结果单向引用：** 结果窗口只引用原事件确切版本，原事件不能引用后生成的结果对象。
7. **窗口预先冻结：** 锚点、时长、边界、标签、单位、精度和排除规则在读取结果前冻结。
8. **短窗不扩尺度：** 15分钟和1小时只属于事后观察，不改变事件的主研究尺度字段。
9. **全状态保留：** 观察到、拒绝、冲突、无法判定、失败、未成熟和失效均进入清单或计数。
10. **统计分母冻结：** 统计计划先冻结总体、分组、窗口、标签和排除规则，再读取结果。
11. **拒绝不删除：** 被拒绝对象保留身份、输入、原因和解除条件，不能从分母静默消失。
12. **无法判定不是零：** 缺失、时间不可证明或作用域冲突不能写成无事件、零变化或失败。
13. **统计不证明因果：** 任何窗口反应只描述观察结果，不自动解释事件导致了结果。
14. **作用域不外推：** 交易场所、市场、合约、标的、尺度、状态版本和窗口必须逐项匹配。
15. **确定性排序：** 成员和分组顺序来自冻结合同，不依赖数据库、文件或并发返回顺序。
16. **失效只追加：** 上游失效创建新失效记录和统计修订版本，不删除旧报告。
17. **原始数据只读：** 全部对象只引用确切版本，不覆盖、迁移或纠正原始记录。
18. **许可保持唯一：** 回放一致、结果完整或统计显著都不能跳过七道质量门。

## 三、对象模型与追加式数据流

### 3.1 核心对象

| 对象 | 职责 | 关键身份 | 禁止行为 |
| --- | --- | --- | --- |
| 回放方案 | 冻结请求范围、原版本、比较字段和确定性规则 | 方案逻辑标识、方案版本、内容指纹 | 看到差异后修改通过标准 |
| 回放输入清单 | 列出实际加载的全部对象、成员、时间和指纹 | 清单版本、成员清单指纹 | 用相似或最新版本补缺 |
| 回放运行 | 记录一次执行尝试、环境、状态和输出引用 | 运行标识、方案版本、输入清单版本 | 覆盖失败或重试记录 |
| 回放比较 | 逐项保存原对象与重建输出的差异和结论 | 比较标识、运行标识、原对象版本 | 用摘要相似替代逐项一致 |
| 结果窗口合同 | 冻结锚点、时长、边界、成熟、标签和排除语义 | 合同逻辑标识、合同版本、指纹 | 读取结果后调整窗口或标签 |
| 结果评价 | 记录窗口资格、成熟、独立快照和事件结果引用 | 评价标识、原事件版本、窗口合同版本 | 把结果写回原事件或状态 |
| 统计方案 | 冻结总体、分组、指标、分母和修订规则 | 统计方案逻辑标识、版本、指纹 | 看到统计后筛选分组或样本 |
| 统计输入清单 | 保存候选事件、结果、拒绝、失效和实际纳入状态 | 清单版本、有序成员指纹 | 只登记成功或已观察样本 |
| 统计快照 | 保存计数、覆盖、描述性结果、限制和血缘 | 快照标识、方案版本、输入清单版本 | 宣称因果、优势或许可 |
| 统计失效 | 追加记录上游失效、方案缺陷和影响范围 | 失效标识、目标快照版本 | 删除或覆盖旧统计快照 |

### 3.2 对象关系

```text
原事件事实确切版本 ───────┐
原市场状态确切版本 ───────┼→ 回放方案 → 回放输入清单 → 回放运行 → 回放比较
原规则与数据快照版本 ─────┘

原事件事实确切版本 → 结果窗口合同 → 独立结果快照 → 结果评价 → 事件结果确切版本

统计方案
  → 统计输入清单（原事件 + 结果评价 + 事件结果 + 拒绝 + 失效）
  → 统计快照
  → 可选统计失效
```

箭头只表示单向版本引用和处理顺序。重建输出是回放运行的独立产物，不成为原事件的新
版本；事件结果仍服从市场事件层Schema，本体系只增加窗口资格、集合统计和比较合同。

### 3.3 两个隔离域

| 隔离域 | 允许读取 | 明确禁止 |
| --- | --- | --- |
| 历史现场域 | 原事件截止时间前已到达且属于原清单的输入、原规则、原状态和原环境 | 确认数据、结果数据、成熟标签、晚到数据、事后修订和当前版本 |
| 事后评价域 | 原事件只读引用、已冻结窗口合同、窗口内独立快照和相应截止时间 | 改变原事件成员、类型、状态、规则、证据、反证或指纹 |

访问边界必须能证明结果域对象不能进入历史现场域。仅靠字段命名、目录约定或开发者自律
不构成隔离证据；未来实现必须使用独立输入清单和指纹检查。

## 四、身份、版本与作用域

### 4.1 双层身份

- **回放逻辑标识：** 由原事件逻辑标识、对象类型、作用域和比较合同逻辑标识组成。
- **回放运行标识：** 标识一次执行尝试，绑定方案、输入清单、代码、环境和开始时间。
- **结果评价逻辑标识：** 由原事件确切版本、结果窗口合同逻辑标识和标签合同组成。
- **统计逻辑标识：** 由冻结总体、分组维度、窗口集合、指标集合和统计规则组成。
- **对象版本标识：** 精确绑定前序版本、全部输入版本、规则版本和内容指纹。

逻辑标识相同但任一输入、规则、窗口、标签、分组、指标、单位、精度或失效范围变化时，
必须生成新版本。创建时间、文件路径、数据库自增号或自然语言标题不能替代版本标识。

### 4.2 必需作用域

每个回放、结果评价和统计对象至少冻结：

```text
交易场所
市场类型与精确合约定义
标的冻结有序集合及单标的成员
事件类型
原事件主研究尺度：4小时 / 8小时 / 24小时 / 48小时
原观察窗口与数据截止时间
市场状态报告确切版本集合
结果窗口身份（适用时）
时间范围、时区、日历与时钟规则版本
```

15分钟或1小时只能出现在`结果窗口身份`，不能写入或替换`原事件主研究尺度`。现货、
永续、不同交易所、不同合约、不同标的或不同主尺度不能静默合并。

### 4.3 新版本触发

以下任一变化必须创建新版本并记录差异原因：

- 原事件、确认、结果、失效、事件簇或市场状态引用变化；
- 数据来源、快照成员、三类时间、截止时间、质量、血缘或指纹变化；
- Schema、事件规则、回放代码、参数、公式、环境或依赖变化；
- 结果锚点、窗口时长、边界、成熟条件、标签、单位、精度、成本或排除规则变化；
- 统计总体、分组、分母、指标、聚合、最小样本或修订规则变化；
- 发现上游失效、未来数据、作用域冲突或重放不一致。

新版本不自动取代旧版本。下游必须显式选择经评审版本，历史引用保持不变。

## 五、历史事件回放合同

### 5.1 回放请求类型

| 请求类型 | 重建对象 | 允许截止时间 | 结果数据是否可见 |
| --- | --- | --- | --- |
| 事件事实回放 | 原事件事实及其拒绝、无法判定或失败状态 | 原事件数据截止时间 | 否 |
| 事件确认回放 | 原确认对象 | 原确认数据截止时间 | 只允许确认窗口数据，不允许结果窗口数据 |
| 事件结果回放 | 原事件结果对象 | 原结果数据截止时间 | 只允许该结果窗口合同内数据 |
| 事件簇回放 | 原事件簇成员和稳定顺序 | 事件簇数据截止时间 | 取决于成员对象类型，禁止跨域混用 |
| 批次回放 | 冻结请求范围内的多个对象 | 每个成员各自原截止时间 | 按成员独立隔离，不共享更晚截止时间 |

批次回放不能用批次最大截止时间覆盖较早成员。成员缺失或失败时必须保留该成员位置和
结论，不能缩小批次后声称完全一致。

### 5.2 回放方案最小合同

```text
回放方案逻辑标识与版本标识
请求类型、请求原因与执行授权引用
原对象类型、逻辑标识和确切版本有序集合
原Schema、规则、参数、公式与代码确切版本
原数据快照、质量、血缘、三类时间和截止时间
原市场状态报告确切版本集合
原证据、反证、异常、排除和同源关系版本
原运行环境、依赖、随机性与确定性声明
比较字段、稳定排序和指纹合同
允许差异：事件对象固定为不允许；环境审计字段须逐项声明
停止条件、原因代码与输出Schema版本
创建、批准、冻结时间及执行主体引用
内容完整性指纹
```

事件对象的成员、顺序、状态、身份、版本和内容指纹不接受数值容差或“语义等价”。若未来
派生计算存在预注册非确定性，只能在独立研究重放合同中管理，不能降低事件事实比较标准。

### 5.3 输入清单与可见性校验

每个实际输入成员必须同时满足：

```text
输入确切版本属于原冻结成员清单
输入事件时间属于该对象允许窗口
输入到达时间 <= 该对象原数据截止时间
输入作用域与原对象逐项一致
输入内容指纹与原清单一致
```

事件时间早但到达时间晚的数据仍属于未来可见信息。晚到、补采、事后修订、成熟K线、
当前市场状态或当前规则只要进入原事件事实回放，必须拒绝整个相关成员并记录证据。

### 5.4 回放结论

回放结论只允许：

| 结论 | 条件 | 后续处理 |
| --- | --- | --- |
| 完全一致 | 全部必需成员、顺序、状态、版本、内容和集合指纹一致 | 可作为可重放证据，不代表事件有效或有优势 |
| 不一致 | 任一必需比较项不同 | 保存差异，触发失效评估，停止预测性使用 |
| 无法重放 | 必需版本、权限、环境、时间或指纹无法取得或证明 | 保存断点和解除条件，不使用替代版本 |

回放成功只证明原合同下可复现。原事件为`拒绝`、`无法判定`或`失败`时，完全一致地重建
这些状态同样是成功回放；不能只把`观察到`事件计为回放成功。

### 5.5 稳定顺序与幂等

批次成员至少依次按以下冻结键排序：

```text
原事件时间
事件类型固定枚举序
交易场所与市场规范序
标的冻结集合规范序
主研究尺度固定序：4小时、8小时、24小时、48小时
原事件版本标识
```

同一幂等键、方案版本和输入清单版本的重试可以返回已有不可变运行身份；实际执行发生后
仍须保留独立尝试记录。并发完成时间、数据库返回顺序和文件遍历顺序不得影响输出指纹。

## 六、结果窗口合同

### 6.1 窗口目录

| 窗口标识 | 固定经过时长 | 类别 | 允许用途 | 禁止用途 |
| --- | ---: | --- | --- | --- |
| 结果观察-15分钟 | 900秒 | 辅助短期结果观察 | 生成事后短期反应标签和覆盖统计 | 事件探测、市场状态、主研究尺度、回测策略或许可 |
| 结果观察-1小时 | 3600秒 | 辅助短期结果观察 | 生成事后短期反应标签和覆盖统计 | 事件探测、市场状态、主研究尺度、回测策略或许可 |
| 结果观察-4小时 | 14400秒 | 主研究尺度对应结果观察 | 描述4小时结果，不自动代表4小时事件有效 | 跨尺度外推或许可 |
| 结果观察-8小时 | 28800秒 | 主研究尺度对应结果观察 | 描述8小时结果，不自动代表8小时事件有效 | 跨尺度外推或许可 |
| 结果观察-24小时 | 86400秒 | 主研究尺度对应结果观察 | 描述24小时结果，不自动代表24小时事件有效 | 跨尺度外推或许可 |
| 结果观察-48小时 | 172800秒 | 主研究尺度对应结果观察 | 描述48小时结果，不自动代表48小时事件有效 | 跨尺度外推或许可 |

固定经过时长按绝对秒计算，不按自然日、交易日或本地夏令时伸缩。显示时区可以转换，
身份和边界计算必须保留UTC时间、原时区和时钟规则版本。

### 6.2 锚点与边界

每个结果窗口使用半开区间：

```text
[结果锚点时间, 结果锚点时间 + 固定经过时长)
```

结果锚点必须在读取结果前由结果窗口合同冻结：

- 不以确认作为前置条件时，锚点不得早于原事件观察窗口结束；
- 以确认作为前置条件时，锚点不得早于确认窗口结束；
- 同一统计方案内同类事件必须使用同一锚点规则版本；
- 锚点变化必须生成新窗口合同和新结果版本，不能覆盖旧结果；
- 不允许按事后最大涨跌、局部高低点或最佳表现选择锚点。

本体系不替项目选择生产锚点规则。未来规则必须通过独立研究和架构评审，且不得让结果
信息进入原事件事实。

### 6.3 成熟与可评价是两道门

窗口的时间成熟条件为：

```text
评价时刻 >= 结果窗口结束
```

时间成熟不等于数据可评价。窗口评价必须依次检查：

1. 原事件、窗口合同、锚点和作用域版本完整；
2. 评价时刻已达到窗口结束；
3. 结果输入快照只包含相应结果截止时间前已经到达的数据；
4. 必需成员、三类时间、质量、单位、精度和指纹完整；
5. 排除、失效、重复和冲突规则能够确定执行。

未达到第2项时为`未成熟`；达到时间但第3至5项缺少证据时为`无法判定`或`失败`，不能
继续等待并在同一对象中回填。后续数据到达只能创建新评价版本。

### 6.4 窗口资格与事件结果状态

结果评价先形成`窗口处理状态`：

| 窗口处理状态 | 语义 | 是否创建或引用事件结果 |
| --- | --- | --- |
| 已接受 | 身份、作用域、成熟、时间、质量和规则均满足 | 是，事件结果状态按市场事件层合同记录 |
| 未成熟 | 窗口尚未结束 | 可记录`未成熟`事件结果，不提前生成标签 |
| 拒绝 | 明确违反预注册资格、作用域、时间或失效规则 | 不伪造结果；保留正式拒绝记录和原因 |
| 无法判定 | 必需事实缺失或无法证明，且不能确认违规 | 记录`无法判定`事件结果或评价记录及解除条件 |
| 失败 | Schema、指纹、未来数据或未知异常等硬失败 | 记录失败，不自动重试为成功 |

市场事件层的事件结果状态仍只使用`已观察 / 未成熟 / 无法判定 / 失败`。`拒绝`属于结果
评价资格记录，不新增或偷改原Schema枚举；统计输入清单必须同时保留评价拒绝和事件结果。

### 6.5 结果标签合同

任何结果标签必须在读取受保护窗口数据前冻结：

```text
标签逻辑标识与版本
中文名称与严格可观察定义
原始字段、计算公式和代码版本
方向口径、单位、精度与舍入规则
结果窗口合同版本与锚点规则
缺失、重复、异常、冲突和排除规则
成本或执行口径版本（适用时；不适用须写原因）
标签状态、禁止解释与失效条件
内容完整性指纹
```

`已观察`只表示标签能够按合同计算。`上涨`、`下跌`、`有利`、`不利`、`成功`或`失败`
都不是本体系的默认标签；如需这些语义，必须在独立研究方案中定义方向、基准、成本、
风险和反证，并通过研究准入。

## 七、结果评价Schema

```text
结果评价逻辑标识与版本标识
前序评价版本（没有时写不适用及原因）
原事件逻辑标识与原事件确切版本
原事件类型、交易场所、市场、合约、标的与主研究尺度
原市场状态报告确切版本有序集合
结果窗口合同、锚点规则和标签合同确切版本
窗口开始、结束、固定经过秒数、边界和时区
窗口成熟时间、评价时刻与结果数据截止时间
结果输入快照版本、成员清单指纹与三类时间范围
窗口处理状态：已接受 / 未成熟 / 拒绝 / 无法判定 / 失败
事件结果逻辑标识与确切版本（没有时写不适用及原因）
支持证据、主要反证、失败样本、异常和失效引用
资格比较、缺失字段、拒绝原因、解除条件和禁止解释
生成、冻结时间与执行主体引用
内容完整性指纹
```

拒绝原因必须指向预注册规则和实际证据。`无法判定`必须写明缺少什么、影响什么、当前
安全降级和可验证解除条件。未知异常不能归类为普通缺失。

## 八、事件结果统计合同

### 8.1 统计方案先于结果

统计方案必须在读取受保护结果前冻结：

```text
统计方案逻辑标识与版本标识
统计问题、用途与明确禁止推导
候选总体生成规则与时间范围
事件、状态、窗口、标签、Schema和规则允许版本
必需分组键、稳定顺序和空组保留规则
分母、分子、覆盖率和状态计数定义
描述性指标、单位、精度、聚合和缺失规则
失效、重复、冲突、排除和修订规则
最小样本披露规则（不是准入或显著性门槛）
输入清单、输出Schema和指纹合同
创建、批准、冻结时间与执行主体引用
内容完整性指纹
```

看到结果后新增分组、删除失败样本、缩短时间范围、改窗口、改标签或改分母，必须创建
新统计方案版本并披露变更；旧统计快照保持可查询。

### 8.2 必需分组键

每个正式统计行至少由以下键唯一确定：

```text
事件类型
单一标的
交易场所
市场类型与精确合约定义
原事件主研究尺度：4小时 / 8小时 / 24小时 / 48小时
原市场状态报告确切版本（或冻结有序版本集合身份）
结果窗口标识：15分钟 / 1小时 / 4小时 / 8小时 / 24小时 / 48小时
结果标签合同确切版本
统计时间范围与统计方案版本
```

跨标的事件必须同时保留事件的有序集合身份，并按合同生成单标的结果成员；缺少任一成员
时不能用总体或其他标的补齐。不同状态版本可以另有经预注册的上位类别汇总，但必须保留
精确版本底表，不能只保存归并结果。

### 8.3 冻结分母与状态漏斗

每个统计分组至少记录：

| 计数 | 定义 |
| --- | --- |
| 候选事件数 | 满足统计总体生成规则的全部原事件版本数，包括非观察到状态 |
| 观察到事件数 | 原事件事实状态为`观察到`的数量 |
| 原事件拒绝数 | 原事件事实状态为`拒绝`的数量 |
| 原事件无法判定数 | 原事件事实状态为`无法判定`的数量 |
| 原事件失败数 | 原事件事实状态为`失败`的数量 |
| 窗口未成熟数 | 结果评价为`未成熟`的数量 |
| 窗口拒绝数 | 结果评价资格为`拒绝`的数量 |
| 窗口无法判定数 | 结果评价或事件结果为`无法判定`的数量 |
| 窗口失败数 | 结果评价或事件结果为`失败`的数量 |
| 已观察结果数 | 事件结果状态为`已观察`且标签完整的数量 |
| 已失效数 | 统计冻结时已有适用失效记录的数量 |

推荐覆盖率只表达数据覆盖，不表达预测质量：

```text
结果可观察覆盖率 = 已观察结果数 / 候选事件数
窗口评价覆盖率 = (已观察结果数 + 窗口拒绝数 + 窗口无法判定数 + 窗口失败数) / 候选事件数
```

分母为零时比率必须为`无法判定`并保留零分母原因，不能填0或100%。若统计方案选择不同
分母，必须以新指标名称和版本明确披露，不能复用上述名称。

### 8.4 描述性统计与禁止结论

在结果标签合同允许且样本完整时，可以记录：

- 样本数、缺失数、拒绝数、无法判定数、失败数和覆盖率；
- 标签值的计数、总和、最小值、最大值、中位数或分位数；
- 预注册分组间的描述性差异和对应完整底表引用；
- 失败样本、主要反证、异常值和敏感性说明。

均值、分位数或其他聚合必须冻结算法、数值精度、排序、并列和空值规则。未经独立研究
方案、简单基准、成本、样本外、稳健性和校准验证，禁止输出或暗示：

- 预测胜率、命中率、策略收益、赔率、净期望或最大回撤；
- 事件导致结果、事件可以预测方向或某状态必然有效；
- 15分钟或1小时成为新的研究尺度；
- 最佳窗口、最佳标的或最佳状态可以进入交易许可。

### 8.5 统计输入清单Schema

```text
统计输入清单逻辑标识与版本标识
统计方案确切版本
候选总体生成规则和冻结时间范围
原事件确切版本有序清单及成员指纹
原市场状态确切版本有序清单
结果评价与事件结果确切版本有序清单
事件确认、事件失效和统计失效引用（适用时）
每个成员的纳入、拒绝、无法判定、失败或未成熟状态
每个成员的分组键、重复处理和排除证据
输入、成员和清单完整性指纹
生成、冻结时间与执行主体引用
```

输入清单必须能从每个统计行反查全部候选成员，也能从任一事件版本正向查询受影响统计
快照。只保存聚合数字而不保存精确版本清单，不构成正式统计证据。

### 8.6 统计快照Schema

```text
统计快照逻辑标识与版本标识
前序快照版本（没有时写不适用及原因）
统计方案与统计输入清单确切版本
分组键、窗口和标签合同确切版本
候选、观察到、拒绝、无法判定、失败、未成熟、已观察和失效计数
覆盖率分子、分母、值与零分母状态
描述性指标、单位、精度、聚合算法和结果
失败样本、主要反证、异常、限制与禁止推导
数据、时间、作用域、重放和血缘完整性摘要
生成、冻结时间与执行主体引用
内容与输出集合完整性指纹
```

统计快照是不可变对象。后续数据到达、失效、规则修复或窗口成熟只能生成新快照版本，
并引用前序版本及变化成员，不能覆盖旧数字。

## 九、缺失、拒绝、无法判定与失效

### 9.1 语义区分

| 状态 | 使用条件 | 必需记录 | 禁止替代 |
| --- | --- | --- | --- |
| 未成熟 | 评价时刻早于窗口结束 | 窗口、成熟时间和最早复验时刻 | 失败、零结果或已观察 |
| 拒绝 | 已有证据证明违反冻结资格或硬规则 | 规则版本、证据、原因和影响 | 静默排除或无法判定 |
| 无法判定 | 必需事实缺失或不可证明，但不能确认违规 | 缺失、影响、安全降级和解除条件 | 0、无事件、失败或通过 |
| 失败 | 指纹、Schema、未来数据或未知异常等执行硬失败 | 停止代码、证据和调查入口 | 自动重试成成功 |
| 已失效 | 后续证据证明对象不能继续用于明确的未来用途 | 目标版本、影响范围和复验入口 | 删除或改写历史对象 |

### 9.2 失效与修订

以下情况触发回放、结果评价或统计失效评估：

- 上游数据来源、质量、三类时间、快照、血缘或指纹发现缺陷；
- 事件、状态、窗口、标签、统计Schema或规则存在语义错误；
- 发现未来数据进入历史现场，或结果数据反向影响事件选择；
- 回放成员、顺序、状态、版本或指纹不一致；
- 统计分母、分组、重复、排除或缺失规则被错误执行；
- 作用域发生不兼容变化，或原对象已有适用失效记录。

失效记录只限制明确的未来使用。修复必须创建新方案、输入清单、评价、结果或统计快照
版本；旧版本及其历史引用继续保留。

## 十、原因代码与安全降级

| 原因代码 | 含义 | 对象结论 | 安全降级 |
| --- | --- | --- | --- |
| `原版本缺失` | 原Schema、规则、数据、状态或环境版本不可取得 | 无法重放 | 不使用当前版本替代 |
| `时间可见性不可证明` | 三类时间或截止时间缺失、冲突 | 无法判定或失败 | 数据门不得视为通过 |
| `未来数据被拒绝` | 后置信息进入原现场域 | 失败或拒绝 | 隔离输入并触发失效评估 |
| `输入清单不一致` | 实际成员、顺序或指纹与冻结清单不同 | 不一致或失败 | 不缩小总体重跑 |
| `回放不一致` | 原输出与重建输出的必需比较项不同 | 不一致 | 停止预测性使用 |
| `窗口未成熟` | 评价时刻尚未达到窗口结束 | 未成熟 | 不提前生成标签 |
| `窗口合同缺失` | 锚点、边界、标签或排除规则未冻结 | 拒绝 | 不读取结果数据 |
| `结果数据不完整` | 成熟窗口的必需成员或质量证据缺失 | 无法判定 | 不补零或沿用其他窗口 |
| `结果作用域不符` | 市场、合约、标的、尺度、状态或窗口不匹配 | 拒绝或无法判定 | 不跨范围外推 |
| `统计分母漂移` | 候选总体或成员在结果可见后发生未版本化变化 | 失败 | 冻结新方案并保留旧快照 |
| `统计零分母` | 分组没有候选事件 | 无法判定 | 比率不填0或100% |
| `上游对象已失效` | 事件、状态、结果或规则已有适用失效记录 | 拒绝或已失效 | 从未来统计或研究中停止使用并保留计数 |
| `未知异常` | 无法归入已知原因且不能证明安全 | 失败 | 停止并保留审计记录 |

错误记录不能包含秘密值、账户凭据、不必要的个人信息或原始市场数据正文。

## 十一、技术中立接口语义

未来实现至少提供以下原子能力；名称和技术可以不同：

| 能力 | 必需输入 | 输出 | 失败时 |
| --- | --- | --- | --- |
| 冻结回放方案 | 原对象版本、原环境、比较与排序合同 | 不可变回放方案 | 不形成半套方案 |
| 解析回放输入 | 方案版本和原版本集合 | 输入清单版本与指纹 | 列出缺失，不替代版本 |
| 执行事件回放 | 方案、输入清单和环境版本 | 回放运行与重建输出 | 保留失败尝试 |
| 比较回放输出 | 原对象、重建输出和比较合同 | 完全一致、不一致或无法重放 | 不使用摘要相似 |
| 冻结结果窗口 | 原事件、锚点、窗口、标签和资格规则 | 结果窗口合同版本 | 读取结果前失败关闭 |
| 评价结果窗口 | 窗口合同和独立结果快照 | 结果评价及事件结果引用 | 未成熟、拒绝、无法判定或失败 |
| 冻结统计方案 | 总体、分组、窗口、标签、分母和指标 | 统计方案版本 | 不读取受保护结果 |
| 生成统计输入清单 | 方案和精确事件、评价、结果、失效版本 | 有序清单与指纹 | 不静默删除成员 |
| 生成统计快照 | 方案和输入清单 | 不可变统计快照 | 不发布部分聚合 |
| 追加统计失效 | 目标快照、失效证据和影响范围 | 不可变失效记录 | 不覆盖原快照 |
| 查询影响与血缘 | 精确版本和查询方向 | 版本化路径、成员和断点 | 不按名称猜测 |

写入必须支持幂等请求、基于前序版本的条件写入、唯一身份冲突拒绝和整组失败回滚。
缓存只能保存不可变对象；缓存缺失或过期时不能返回旧结果或旧统计作为安全默认值。

## 十二、研究、复盘、AI与交易许可边界

### 12.1 研究与复盘

回放比较、结果评价和统计快照只有在版本、时间、作用域、血缘和失效状态完整时，才可
申请成为研究或复盘输入。申请仍须满足：

- 假设在结果可见前预注册且可证伪；
- 简单基准、样本外、成本、稳健性和反证合同完整；
- 失败、拒绝、无法判定、失效和空仓样本没有被删除；
- BTC、ETH、SOL及4小时、8小时、24小时、48小时分别报告；
- 结果不足时允许结论为`无法判定`、`不支持`或`淘汰`。

复盘可以引用后续结果解释过程与结果差异，但不能改写原事件、原决策或原许可。

### 12.2 AI决策推理

AI只能引用确切版本，复述结构化计数、差异、反证和限制。AI不得：

- 补齐缺失事件、结果或统计成员；
- 把回放一致解释为事件有效；
- 把描述性反应解释为预测胜率或因果；
- 选择最佳窗口后反向修改统计方案；
- 用自然语言覆盖拒绝、无法判定、失效或质量门失败。

### 12.3 七道质量门与唯一许可

| 本体系材料 | 可能支持的质量门 | 仅允许作用 | 不得推导 |
| --- | --- | --- | --- |
| 回放输入、三类时间和比较结论 | 数据门 | 证明历史现场能否重建 | 数据门或其他门自动通过 |
| 冻结总体、全状态计数和覆盖率 | 样本门 | 说明样本定义和缺失结构 | 样本充分或可外推 |
| 结果标签、反证和描述性统计 | 优势门 | 提供候选研究材料 | 正净期望或预测优势 |
| 成本口径版本（适用时） | 成本门 | 证明统计是否引用成本合同 | 成本已经充分覆盖 |
| 失效、冲突和不一致记录 | 风险门 | 提供否决和复验上下文 | 风险可接受 |
| 市场、合约和结果作用域 | 执行门 | 核对上下文是否一致 | 真实市场可执行 |
| 事件频度与统计时间范围 | 频率与纪律门 | 提供历史分布证据 | 自动决定交易次数 |

任一硬门失败时，唯一交易许可保持：

```text
交易许可：禁止
建议仓位：0
```

## 十三、未来实现验收场景

未来实现至少覆盖：

1. 原规则、Schema、数据或状态版本缺失时结论为无法重放；
2. 当前最新版本不能替代原版本；
3. 事件时间早但到达时间晚于原截止时间的数据被原现场拒绝；
4. 确认、结果、成熟标签、晚到和事后修订数据不能进入事件事实回放；
5. 原事件为拒绝、无法判定或失败时能够完全一致地重建该状态；
6. 相同最终事件类型但证据、成员、顺序、状态或指纹不同判为不一致；
7. 批次回放不会用最大截止时间覆盖较早成员；
8. 批次成员失败后仍保留位置、状态和原因；
9. 回放不一致触发失效评估且不覆盖原事件；
10. 15分钟窗口严格等于900秒，1小时窗口严格等于3600秒；
11. 4小时、8小时、24小时、48小时窗口按固定经过秒数计算；
12. 15分钟和1小时不会写入原事件主研究尺度；
13. 未达到窗口结束时只生成未成熟，不提前读取标签；
14. 时间成熟但数据缺失时输出无法判定而不是未成熟；
15. 锚点、标签或排除规则未冻结时拒绝读取结果；
16. 确认作为前置条件时结果锚点不早于确认窗口结束；
17. 看到结果后修改锚点、窗口、标签或精度会生成新版本；
18. 结果评价拒绝与事件结果状态分开保存；
19. 已观察结果不会自动解释为成功、有利或可交易；
20. 每个统计行包含事件类型、标的、交易场所、主尺度、状态版本和结果窗口；
21. 现货、永续、交易所、标的、尺度或状态版本不会静默合并；
22. 候选分母保留原事件拒绝、无法判定和失败；
23. 窗口统计保留未成熟、拒绝、无法判定、失败和失效计数；
24. 分母为零时比率为无法判定而不是0或100%；
25. 统计输入清单能从聚合行反查全部候选成员；
26. 删除失败样本或改变分组会生成新统计方案版本；
27. 统计成员和输出顺序不依赖并发、数据库或文件返回顺序；
28. 上游失效生成新统计失效或快照版本，不覆盖旧数字；
29. 描述性统计不会输出未经研究准入的胜率、收益、赔率或净期望；
30. BTC或ETH结果不能补偿SOL缺失，辅助短窗不能替代主尺度证据；
31. AI不能补齐缺失、选择最佳窗口或授予交易许可；
32. 当前数据审计未放行时不生成真实事件结果或真实统计结论；
33. 未知异常安全停止，不返回缓存结果、默认零值或上一统计快照；
34. 真实资金关闭时任何回放、结果或统计对象都不能触发账户写入。

## 十六、最终判断

历史事件回放的价值不是把旧结论再计算一遍，而是证明系统能否在不借用未来信息的前提
下重建当时现场。结果统计的价值也不是挑出表现最好的窗口，而是用冻结分母保存全部事件
及其拒绝、缺失、失败和反证，让后续研究面对完整事实。

在版本、时间、作用域、成员、成熟、质量或指纹不能证明时，正确输出是拒绝、无法判定、
失败、未成熟或不一致。宁可没有统计结论，也不得用事后结果补写一个看似成功的历史事件。
