## 背景

任务规范已经定义`已取消`及“任一未完成状态→已取消”，但可信自动合并资格只实现了阻塞、
恢复和完成迁移。任务-000050的测试合同要求直接修改可信检查器，因自动合并范围不匹配而
失败关闭；同一修复已由任务-000051以治理自动化范围交付。若没有有证据的取消闭环，任务-000050
只能永久停留在阻塞，形成合法状态与可信实现之间的治理漂移，也无法安全裁决被替代的重复任务。

## 任务目标

1. 为`合并后状态闭环`实现从`待执行`、`执行中`、`阻塞`、`待评审`或`需修复`到`已取消`的
   单任务终止迁移；已完成任务不得被取消，取消不得自动解除其他依赖。
2. 定义并校验不可伪造的取消证据：取消原因、取消时间、替代任务编号、替代PR和已进入`main`
   的替代合并提交SHA；证据必须绑定当前基线和PR元数据。
3. 使任务文件、看板、跨载体检查器和自动合并资格对`已取消`使用同一机器合同；取消看板行必须
   可由任务文件中的证据确定性复算。
4. 通过独立状态闭环PR将任务-000050标记为`已取消`，保留PR #86失败关闭和任务-000051成功交付
   的事实，不伪造任务-000050已执行或已合并。

## 固定执行方案

1. 复现任务规范与可信状态闭环对`已取消`迁移支持不一致的测试缺口；冻结取消证据字段、顺序和
   替代任务/合并事实来源。
2. 修改可信自动合并资格与跨载体检查器，使取消迁移仅允许一个未完成任务、严格正文和完整
   证据，禁止完成态取消、合同改写、伪造替代合并或夹带其他迁移。
3. 更新任务规范、Codex自动执行提示词和研发中心测试，覆盖正向取消、缺证据、伪造SHA、完成态
   取消、依赖误解锁和看板漂移等失败安全路径。
4. 在任务-000052交付合并并闭环后，使用任务-000051的真实PR #89合并证据，独立关闭任务-000050；
   保存精确基线、头SHA、评审证据和资源证据。
