## 目标

建立适用于当前 GitHub 套餐的轻量 PR 自动化机制，使已完成架构评审、提交未变化
且满足低风险边界的变更可以自动合并。任何无法证明安全资格的变更默认转人工，
不得为追求自动化而放宽《知势》的研究、风险或数据纪律。

目标流程：

任务中心
↓
Codex执行
↓
创建PR
↓
自动检查
↓
架构评审通过
↓
自动Merge
↓
Codex按任务中心协议更新任务状态

## 工作范围

1. 定义文档、治理、研究规范三类低风险任务的自动合并资格。
2. 定义仓库所有者针对当前提交 SHA 的可审计架构批准指令。
3. 建立只读资格检查工作流和最小写权限合并工作流。
4. 合并前重新检查PR状态、基线、来源仓库、任务合同、变更路径、批准SHA和资格检查。
5. 对高风险、无法分类、提交变化、检查失败或合并冲突统一拒绝自动合并并转人工。
6. 保持Codex完成任务后自动创建PR的既有流程。
7. 把付费平台保护能力登记为阶段2治理增强。

## 不在范围

- 不升级 GitHub 套餐，不改变仓库可见性。
- 不建立复杂审批系统、外部机器人、数据库或服务。
- 不自动合并任务-000013自身的引导PR。
- 不让GitHub Actions直接修改`main`中的任务状态；合并后的状态证据仍由Codex按
  任务中心协议提交，阶段2再评估端到端状态自动化。
- 不修改生产代码、交易代码、资金管理、生产配置或数据流程。

## 安全边界

- 合并工作流只接受`xk320`以`OWNER`身份创建的精确架构批准评论。
- 批准指令必须包含40位PR头提交SHA；PR提交变化后必须重新评审。
- 合并工作流只能运行已进入`main`的可信脚本，不执行PR分支中的代码或工作流。
- 自动合并只允许任务文件已在`main`存在、任务类型明确为`文档`、`治理`或
  `研究规范`，且变更全部属于允许的Markdown路径。
- `.github/`、脚本、源代码、配置、数据、数据库迁移和任何无法分类的路径禁止
  自动合并。
- 工作流令牌使用最小权限，不读取或提交自定义密钥、密码、令牌或账户凭据。
- 不访问服务器、数据库、市场数据或真实交易账户，不执行真实资金交易。

## 自动合并边界

允许自动合并：

- `类型：文档`
- `类型：治理`
- `类型：研究规范`

禁止自动合并：

- 交易执行代码
- 资金管理代码
- 生产环境配置
- 数据删除或迁移
- 涉及真实资金风险的修改
- 缺少任务文件、任务类型或架构批准SHA的修改
- 修改`.github/`、脚本、源代码、配置或数据文件的PR
- 来自外部仓库、存在合并冲突、提交已变化或资格检查未通过的PR
