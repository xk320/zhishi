# 任务-000008：完成《知势决策委员会》V1.0

- 状态：待执行
- 优先级：P1
- 阶段：0.5 理论体系建设
- 依赖：可与任务-000007并行，但最终须校验一致性
- 建议分支：`agent/000008-decision-committee-v1`

## 任务目标

把“委员会”从概念比喻固化为可实现、可测试、可追溯的逻辑职责体系，明确每个评议单元的输入、输出、否决权和最终裁决规则。

## 输出合同

- `docs/决策/知势决策委员会.md`
- 必要时更新《知势词典》《知势决策标准》和《系统蓝图》

## 最低委员会结构

- 数据质量评议
- 市场状态评议
- 相关状态评议
- 资金行为评议
- 标的比较评议
- 机会与成本评议
- 风险评议
- 执行条件评议
- 纪律评议
- 最终交易许可裁决

## 每个评议单元必须定义

1. 职责和明确不负责的事项；
2. 输入字段及来源；
3. 输出字段、取值和缺失处理；
4. 支持证据与主要反证；
5. 是否拥有一票否决权；
6. 上下游依赖；
7. 冲突处理与降级规则；
8. 可测试的验收场景。

## 设计约束

- 委员会是逻辑职责划分，不默认等于多个大模型或多个代理。
- 第一阶段应优先支持规则、统计和简单模型实现。
- 最终只允许“允许交易”或“禁止交易”；信息不完整默认禁止。
- 不允许简单多数票越过数据门、风险门或执行门。
- 必须区分评分、确定性、预测胜率和否决状态。

## 验收标准

- [ ] 形成完整流程图和职责矩阵。
- [ ] 所有硬否决路径明确。
- [ ] 冲突、缺失、超时和异常输入均有降级结果。
- [ ] 能覆盖做多、做空和空仓决策。
- [ ] 与七道交易许可质量门一一对应。
- [ ] 不引入无法验证的拟人化投票机制。
- [ ] 文档可直接指导后续接口和测试设计。

更新任务和看板为执行中 → 独立分支实现 → 自审一致性 → 提交、推送、创建PR → 更新为待评审。不得自行合并。
