# 任务-000024：历史事件回放与结果统计体系

- 状态：待执行
- 类型：研究基础设施 / 历史验证
- 阶段：阶段3 市场事件验证阶段
- 优先级：P0
- 执行方案：不可变事件事实、结果标签分离与历史窗口统计合同
- 方案状态：已批准执行

## 依赖任务

- 任务-000006：最小数据闭环
- 任务-000021：Market Regime 市场状态架构
- 任务-000023：市场事件层架构设计

## 目标

建立历史事件回放与结果统计体系，将市场事件事实、市场状态和未来结果进行可重复验证。

## 输入合同

输入仅允许使用事件发生时已经存在的信息：

- 市场事件事实；
- Market Regime 状态；
- 事件时间戳；
- 当时可获得的市场数据快照。

禁止使用事件发生后的信息生成事件事实。

## 输出合同

输出：

- 事件结果记录；
- 结果窗口统计；
- 无法判定原因；
- 拒绝原因。

结果窗口：

核心窗口：

- 15分钟；
- 1小时；
- 4小时；
- 8小时；
- 24小时。

扩展观察窗口：

- 48小时（非核心）。

## 核心链路

事件事实
→ 市场状态
→ 结果窗口
→ 统计分析

## 安全边界

禁止：

- 交易信号生成；
- 收益优化；
- 模型训练；
- 自动下单；
- 真实交易执行。

## 数据原则

- 禁止未来数据污染；
- 事件事实与结果标签必须分离；
- 历史状态只能使用当时可获得信息；
- 不允许使用成熟后K线替代历史现场。

## 验收标准

- 完成历史事件回放架构；
- 定义事件结果统计合同；
- 支持15分钟、1小时、4小时、8小时、24小时结果统计；
- 保留无法判定和拒绝记录；
- 通过研发中心测试；
- 通过Markdown检查与diff检查。
