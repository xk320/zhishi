## 固定执行方案

1. `prepare`进程只允许读取配置、Git固定身份和预登记SHA声明，并对固定路径执行不打开载荷的逐级`lstat`/类型检查；在打开或解码任何成员、连续段、叶子或来源拒绝载荷前记录精确UTC`data_cutoff_at`，将不可变`decision_intent.json`追加式发布后退出；目标已存在时失败。
2. `decide`进程只接受已发布意图，先复核意图与固定7文件的精确字节SHA、输出载荷指纹、完整批次指纹和任务合同指纹，再独立加载全部成员。
3. 每个成员必须满足`source_visible_at <= data_cutoff_at`且`collected_at <= data_cutoff_at`；晚于事前截止点的成员必须失败关闭。决策完成后记录精确`decision_at`，且必须满足`intent_created_at <= data_cutoff_at < decision_at`。
4. 决策身份绑定意图SHA、数据截止、来源提交、批次、成员清单SHA、确定性成员顺序SHA、规则/配置/合同/执行器版本和规范结果SHA；源清单指纹变化时整批失败，不允许把新成员追加到旧决策。
5. 两个`replay`进程必须在不可变决策发布后分别启动，各自重新读取意图、决策和全部上游字节，不复用决策或另一重放的派生对象；规范输出、计数、成员顺序、分组和叶子必须一致。
6. 只允许仓库根目录下的相对路径；逐级拒绝路径组件符号链接、非普通文件、输出目标已存在和越界路径。
7. `prepare`发布意图时不得打开任务-000094成员、连续段、叶子或来源拒绝载荷；`decide`和两个`replay`的正式输出先写同父目录临时批次并逐文件回读，第三次复核全部来源后重新测量运行时间、RSS与输出总量，最终硬门通过且目标仍不存在时才原子发布。
