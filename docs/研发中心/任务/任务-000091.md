## 背景

任务-000090已交付确定性来源身份映射执行器，但真实批次中的Python `urllib`请求因本机Python证书信任链报`CERTIFICATE_VERIFY_FAILED`而失败安全。相同端点通过系统`curl`在默认TLS校验下返回HTTP 200，说明网络与Binance端点可达，故障边界位于Python运行时证书信任链，而不是Binance服务或任务证据规则。

本任务只修复公开HTTPS传输层，不修改任务-000090的成员、身份字段、映射规则、分母、授权边界、研究尺度、阶段门禁或历史批次。禁止通过`--insecure`、`-k`、未验证SSL上下文或自签证书信任注入绕过证书校验。

## 任务目标

1. 为任务-000090执行器增加固定、可测试、失败安全的系统`curl` HTTPS传输适配器。
2. 固定可执行文件、端点、协议、证书校验、超时、响应体上限、日志上限、串行行为和退出码映射，并将传输器版本与参数指纹写入批次。
3. 保持公开响应只在内存中解析，只保存响应SHA-256、Schema指纹、BTC/ETH脱敏合约摘要、计数和错误事实，不保存完整响应。
4. 运行一次真实、串行、无认证的Binance公开元数据复验与本地只读清单复验，追加一个不可覆盖批次。
5. 按任务-000084既有九字段合同如实报告BTC与ETH各315个成员的`已证明`、`拒绝`和`无法判定`；不得因传输成功自动推断历史文件来源或授权。

2. 先新增可注入的传输适配器专项失败测试，覆盖Python证书失败基线、系统`curl`成功、非零退出、超时、超限、非JSON、非HTTPS、非白名单端点、重定向和禁用证书校验参数拒绝。
