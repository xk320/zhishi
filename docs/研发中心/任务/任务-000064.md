## 背景

任务-000063确认92个数据库元数据对象和2个敏感系统日志未形成正文级质量证据，3个普通文件身份已漂移。
现有白名单只支持受限只读探针，不能据此推断业务正文可读、资源可用或阶段1门禁通过。本任务只补齐
后续正文级审计所需的最小合同，防止在授权、资源和敏感信息边界不清时扩大扫描。

## 任务目标

1. 为数据库业务正文和敏感日志正文分别定义对象级授权、最小必要字段、脱敏方式和禁止字段。
2. 为每个对象冻结最大读取字节、最大耗时、并发数、内存、临时空间和停止条件，并记录资源实测。
3. 定义事件时间、到达时间、采集时间、时区、精度、截止时点和版本指纹的输入合同。
4. 定义逐对象状态集合：`通过`、`拒绝`、`无法判定`、`失败`、`未成熟`、`失效`、`未执行`，并要求失败安全和确定性成员顺序。
5. 明确后续审计不得修改原始数据、覆盖历史批次、缩小分母、跨BTC/ETH补偿或把描述性结果升级为研究准入。

## 固定执行方案

1. 只根据任务-000062、任务-000063的不可变清单和缺口报告起草合同，不新增对象、不读取正文。
2. 将数据库对象、敏感日志对象和漂移普通文件分成互斥授权层；未获授权层只能记录未执行。
3. 用标准库和仓库既有审计格式定义输入绑定、资源预算、脱敏输出和追加式批次指纹。
4. 在设计文档中给出后续执行任务的前置核验清单和失败关闭规则；不生成任何市场统计或交易结论。
