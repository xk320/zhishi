## 背景

任务规范和任务-000041允许一个已取得新鲜外部证据的任务从`阻塞`恢复为`待执行`。当前
`scripts/研发中心/验证自动合并资格.py`把所有`阻塞→待执行`都当作“完成任务后的唯一后继
解锁”，当没有完成任务时错误拒绝，导致合法的外部恢复状态闭环无法进入`main`，形成新的
状态漂移风险。PR #95提供了真实失败证据，但不应通过伪造完成任务或改用错误状态绕过。

## 任务目标

1. 使可信资格脚本区分“直接阻塞恢复”为`待执行`和“完成任务后唯一后继解锁”为`待执行`；
2. 保留两种路径各自的字段、看板、依赖和不可变合同校验；
3. 增加正向和反向回归测试，防止恢复路径再次被误判或用于夹带迁移；
4. 不改变任务文件唯一事实源、研究范围、数据门槛或自动合并安全边界。

## 固定执行方案

1. 先在现有研发中心测试中加入直接`阻塞→待执行`的失败夹具，确认当前资格器拒绝原因；
2. 将资格判断拆分为直接恢复计数与完成后继解锁计数，并复用不可变字段校验；
3. 为直接恢复增加唯一迁移、看板一致、依赖不变和合同正文不可改写的正反测试；
4. 保持完成态后继解锁的原有规则与失败原因不变；
5. 运行任务要求的全量研发中心验证、Markdown和差异检查，提交引用本任务的PR。
