# 任务-000084：来源身份声明清单接入与不可变冻结

- 并行规则：禁止并行；必须在任务-000083完成后执行；不得与其他来源身份、时间、质量、重放、成本或阶段门禁任务并行

## 依赖与阻塞条件

- 唯一前序依赖：任务-000083完成后执行
- 当前阻塞原因：任务-000083最终批次确认严格候选声明表数量为0、候选声明行数量为0，BTC与ETH各315个成员仍无可验证的完整来源身份声明；当前没有符合`source-identity-evidence-1.0`、绑定最新成员SHA-256并包含授权边界与字段中文映射的外部结构化证据清单，不能从表名、字段名、路径、订单簿结构或聊天内容推断身份
- 解除条件：由数据提供方或数据所有者交付可验证的结构化身份声明清单；清单版本、记录顺序、资产/标的绑定、九项身份字段、当前成员SHA-256、Schema/授权指纹、字段中文映射和证据定位全部可复算，且不包含凭据、原始业务记录或未来数据

## 背景

阶段1最终审计的八个BTC/ETH研究叶子全部阻塞，`ZS-DATA-GAP-001`要求冻结来源提供者、交易场所、市场类型、标的身份、精确合约、数据对象、Schema确切版本、授权边界和字段中文映射。任务-000080至任务-000083已按允许范围复核仓库入口、固定白名单、数据库元数据和严格候选表，但最新批次仍为入口空集，已证明成员为0。没有新的结构化身份声明输入时，继续扩大读取范围会把结构观察误当成身份证明，因此本任务先登记解除条件并保持阻塞。

## 任务目标

1. 接收一份版本固定、内容寻址、可撤销但历史不可覆盖的结构化来源身份声明清单。
2. 对BTC、ETH各315个成员逐项校验来源提供者、交易场所、市场类型、标的身份、精确合约、数据对象、Schema确切版本、授权边界和字段中文映射，并绑定当前输入成员SHA-256。
3. 仅将全部字段和证据定位均通过的成员标记为`已证明`；证据缺失、冲突或失效继续标记为`无法判定`、`拒绝`或其他合同允许状态。
4. 生成可复算的不可变批次，并按精确成员范围更新`ZS-DATA-GAP-001`；不改变其他缺口或阶段门禁。

## 固定执行方案

1. 从最新`main`冻结任务-000083最终批次、任务-000029来源身份合同、资产/成员顺序、清单版本和本任务输入指纹。
2. 只接受顶层为`source-identity-evidence-1.0`的结构化JSON；每条记录必须绑定唯一资产编号、标的、当前成员SHA-256、证明字段、声明值、证据定位和字段中文映射指纹，不接受聊天、Issue、PR描述、文件名或调用方自报。
3. 按合同顺序逐成员校验九项身份字段、Schema确切版本、授权边界、字段映射、撤销/失效事实和证据文件SHA-256；拒绝未知字段、重复记录、跨BTC/ETH补偿、结果可见后改分组或更换分母。
4. 如需远端复核，只使用逻辑别名`ubuntu`的专用只读身份和任务登记的固定`information_schema`元数据查询；不读取价格、成交、订单簿、账户、凭据或其他业务正文。
5. 以追加式、原子、不可覆盖目录发布脱敏批次；输入缺失、权限不足、指纹漂移、超时或计数不守恒时失败安全并保留阻塞。

## 默认工程决策

- 复用任务-000029、任务-000081至任务-000083的标准库、成员顺序、状态守恒、批次和敏感扫描规则，不修改历史合同或批次。
- 证据优先于描述；不把候选表、路径、表名、字段名、数据库结构、订单簿系统归属或Ubuntu可达性解释为身份结论。
- 测试串行、最多两个只读评审者、Node堆上限256MiB、不创建额外工作树；BTC与ETH独立统计。
