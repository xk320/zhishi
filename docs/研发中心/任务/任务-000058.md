# 任务-000058：对齐阻塞任务合同证据与可信资格规则

- 状态：待执行
- 类型：治理
- 阶段：阶段1 研发自动化治理
- 优先级：P0
- 执行方案：方案A“复用现有合同语义的精确证据绑定修复”
- 方案状态：已批准执行
- 执行授权：Codex直接执行，不得再次要求用户选择方案或批准合并
- 自动合并范围：治理自动化
- 并行规则：禁止并行；必须先完成本任务，再恢复任务-000056；不得与任务-000055的范围文档修复并行

## 依赖与阻塞条件

- 唯一前序依赖：任务-000057已完成并进入main；任务-000056当前处于阻塞状态。
- 当前阻塞原因：无；本任务只修复治理资格规则与回归测试，不访问服务器、数据库或真实市场数据。
- 解除条件：修复后的可信规则、回归测试和治理文档进入main，并通过独立评审与精确SHA复验。

## 背景

PR #127按任务-000056方案仅为任务-000055增加唯一治理自动化授权，但任务-000057的
`阻塞任务合同修复`资格器额外要求任务-000056合同出现“任务-000055当前阻塞合同”这一
未登记的固定原文，导致现有任务合同已经明确的输入、输出和固定方案无法通过可信复验。
该冲突必须修复为可由现有合同语义确定目标的规则，不能通过修改任务状态、放宽路径或绕过
失败关闭来推进。

## 任务目标

1. 让可信资格器从任务-000056现有输入、输出和固定方案中确定任务-000055唯一目标；
2. 保持单目标、单字段、阻塞状态、路径白名单、精确SHA和双评审门槛不变；
3. 增加真实合同语义与缺失证据的正反回归测试，防止再次引入未登记固定措辞；
4. 解除任务-000056因规则—合同证据不一致形成的阻塞，随后由任务-000056重新执行。

## 固定执行方案

1. 将资格器的合同证据匹配改为接受任务-000056现有的“更新后的任务-000055文件”输出证据、
   “只在任务-000055增加唯一自动合并范围字段”方案证据和“任务-000055最新阻塞状态”输入证据；
2. 保留现有目标状态、字段白名单、任务引用、路径硬门和失败关闭逻辑；
3. 增加使用当前任务-000056合同语义的通过测试，以及缺少任一证据时的失败测试；
4. 运行研发中心全量验证、Markdown、敏感信息和差异检查，创建引用本任务的PR。

## 默认工程决策

- 仅使用Python标准库和现有可信资格器，不引入依赖或外部服务；
- 以任务文件现有语义为证据，不新增聊天、Issue或硬编码状态来源；
- 不扩大自动合并路径，不改变普通任务交付、状态闭环和任务登记规则；
- 测试单进程，Node堆上限256 MiB，不创建额外工作树。

## 允许停止条件

- 需要修改生产、服务器、数据库、原始数据、权限、凭据或交易路径；
- 现有任务合同语义无法在不放宽单目标和失败关闭门槛的情况下证明唯一目标；
- 发现规则修复会迁移任务-000055或任务-000056状态，或改变研究安全边界。

## 输入合同

- 最新main上的`AGENTS.md`、任务规范、PR自动合并策略和可信资格器；
- 任务-000056完整合同，尤其是其固定执行方案、输入合同和输出合同；
- 任务-000055当前阻塞合同及任务-000057已合并的受控资格路径；
- 现有研发中心自动合并正反测试。

## 输出合同

- 更新后的`scripts/研发中心/验证自动合并资格.py`及必要的跨载体检查；
- 任务-000056现有合同语义的正反回归测试；
- 本任务设计文档、任务记录、看板、提交、PR、双评审和验证证据。

## 工作范围

- 仅修改阻塞任务合同修复的证据匹配、研发中心测试和治理文档；
- 仅验证任务-000056→任务-000055这一既有单目标授权路径；
- 保持任务-000055、任务-000056状态、研究范围、安全边界和数据事实不变。

## 不在范围

- 不执行任务-000056或任务-000055的合同授权、范围文档或服务器验证；
- 不修改任务状态、任务合同正文、原始数据、服务器、数据库、生产系统、账户或交易逻辑；
- 不放宽普通任务交付、状态闭环、路径白名单、双评审或精确SHA门槛。

## 安全边界

3. 任务-000055与任务-000056状态和合同正文未被修改；
4. 研发中心测试、Python编译、Markdown、敏感信息、跨载体和`git diff --check`通过；
5. 双只读评审均通过，PR引用任务-000058并按精确SHA自动合并。
