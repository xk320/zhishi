## 任务目标

建立《知势》核心概念、证据、状态、风险和决策之间的正式关系图，使新增指标、特征、模型和规则能够被定位、追溯和审查。

## 输出合同

- `docs/架构/知势知识图谱.md`
- 图谱节点清单与关系清单，可使用Markdown表格和Mermaid
- 必要时更新《知势词典》和《系统蓝图》

## 必须覆盖的节点域

- 数据与数据质量
- 事件时间、到达时间和可重放性
- 市场状态与波动环境
- 相关状态
- 资金行为与资金轮动
- 相对强度、持续性和加速度
- 承接能力、成交扩张和资金效率
- 机会、成本、赔率和净期望
- 风险预算、止损距离和组合风险
- 执行条件与纪律约束
- 支持证据、反证、失效条件和退出条件
- 交易许可、空仓和复盘结果

## 关系要求

至少定义：

- `依赖于`
- `支持`
- `反对`
- `约束`
- `否决`
- `派生自`
- `适用于`
- `在某状态下失效`
- `进入复盘`

每个核心节点必须说明：中文定义、数据来源或证据来源、输出用途、可能误用、验证方式和所属决策质量门。

## 设计约束

- 图谱是治理和解释工具，不宣称因果关系已被证明。
- 相关关系、假设关系和已验证关系必须明确区分。
- 新指标无法挂接到决策问题、证据和验证路径时，不得进入主图谱。
- 不为了图形复杂度引入无业务价值节点。

## 验收标准

- [ ] 核心概念均可追溯到词典或正式定义。
- [ ] 节点和关系不存在明显循环定义或术语冲突。
- [ ] 每个特征能够说明它影响哪个决策问题。
- [ ] 支持证据和反证均有表达位置。
- [ ] 能表示空仓、否决、失效和复盘。
- [ ] 与系统蓝图和决策委员会结构一致。
- [ ] 提供新增节点的准入模板。
