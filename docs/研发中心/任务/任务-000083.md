## 依赖与阻塞条件

- 唯一前序依赖：任务-000082完成后执行
- 当前阻塞原因：任务-000082已冻结仓库声明入口和数据库注释候选为空；本任务等待严格候选表元数据筛选及已批准只读权限复验，不得把表名、列名或结构观察直接解释为来源身份。
- 解除条件：候选对象可由固定元数据签名定位，声明列可在无业务列读取的范围内只读复验；或形成可复算的空集/权限不足失败安全批次并记录新的解除条件。

## 背景

任务-000082在固定白名单文件和数据库注释范围内未发现结构化九字段声明入口。用户已批准进一步使用专用只读身份，对共享数据库中严格匹配九字段签名的候选声明对象做最小列读取。本任务只补充这一层证据，不放宽研究范围，不修改数据，不进入阶段2。

## 任务目标

1. 冻结最新`main`、任务-000081的630个BTC/ETH成员顺序、任务-000082批次和本任务配置指纹。
2. 仅通过`information_schema.TABLES`和`information_schema.COLUMNS`发现候选`BASE TABLE`，并按固定中文/英文别名映射冻结Schema指纹；视图、物化视图、同义词和外部表一律拒绝。
3. 对严格签名通过的候选对象，只读取成员编号和九字段声明、版本、内容/成员/Schema/授权指纹及可撤销事实；不读取其他列。
4. 逐成员验证BTC、ETH各315成员，输出守恒状态、不可变批次和`ZS-DATA-GAP-001`精确更新。

## 固定执行方案

1. 从最新`main`加载任务-000081最终成员清单、任务-000082最终批次、来源身份合同、缺口台账、候选字段别名配置和本任务设计文档，复算字节指纹。
2. 使用`ubuntu`无交互、串行、有界探针查询数据库元数据；候选表必须满足设计文档规定的全部逻辑字段，拒绝未登记对象、符号链接、隐藏路径和未知列。
3. 只对候选对象执行固定列白名单、参数化成员编号和资源上限内的`SELECT`；原始声明正文不落盘，只保存脱敏值和指纹。
4. 进行字段完整性、成员绑定、版本、Schema/授权指纹、撤销事实、敏感扫描、状态守恒和计数守恒校验；任一失败安全条件停止相关发布。
5. 追加不可变批次和审计台账；空集、权限不足或证据不足时保留`未登记`/`无法判定`/`失败`，不得虚构已证明。
