## 背景

PR #44 将看板“待评审”表头写成“Pull Request”，而`main`可信校验器只接受“PR”。这使
任务-000029的合并后状态闭环在实现已经合并后仍无法通过自动资格检查。若继续依赖散落在
脚本、测试和文档中的重复表头，未来状态迁移、任务登记和看板更新仍可能产生同类漂移。

## 任务目标

建立任务中心看板模式的单一、可机器验证合同，使任务登记、状态闭环、任务状态映射和可信
自动合并校验器使用同一规范；修复当前表头冲突，并让未来的模式漂移在进入评审前失败关闭。

## 固定执行方案

1. 冻结看板各状态分区的规范表头、分隔行和任务行字段顺序，规范“PR”为唯一列名；
2. 将规范保存为仓库内可审计的机器合同，并由可信校验器从该合同加载；
3. 更新看板、任务规范、状态闭环与任务映射测试，禁止隐式接受未登记别名；
4. 为任务登记、任务交付和合并后状态闭环分别增加模式漂移回归用例；
5. 对当前`main`和PR #48重跑资格、状态映射、Markdown和差异验证，不修改任务交付数据。
