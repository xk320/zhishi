- 解除条件：在固定六个根目录和八类候选文件名/格式内发现可读取、版本固定、成员绑定完整的结构化身份输入；否则发布失败安全批次并保持任务-000084阻塞

## 背景

任务-000088的root-v5批次因固定扫描文件上限触发失败安全，候选为0，不能证明固定目录中不存在候选身份输入。继续扩大路径、文件名或读取业务正文会违反任务-000084合同。因此本任务仅优化候选索引：按固定候选名称识别文件，避免把普通文件数量误当作候选分母，同时保留有界、可复算和失败安全约束。

## 任务目标

1. 在实际UID=0且专用UID=1001不可用时，按任务-000084固定root兼容模式建立候选文件索引。
2. 只对固定候选文件进行脱敏元数据和允许字段摘要复验，记录目录遍历完整性、候选计数、路径指纹、Schema指纹和资源事实。
3. 以任务-000083冻结的BTC/ETH各315成员为固定分母，逐标的复验候选身份字段；不跨标的补偿、不缩小分母、不事后改分组。
4. 只有完整九字段、当前成员SHA-256、Schema/授权/字段映射和证据定位全部满足时，才允许生成任务-000084要求的结构化输入；否则只追加失败安全批次。

## 固定执行方案

1. 从最新`main`冻结任务-000084 root段落、任务-000088最终批次、任务-000083成员清单、Binance公开接口合同和现有规则指纹。
2. 复用既有身份字段、成员顺序、状态守恒、敏感扫描和不可变批次规则；新增入口只替换候选索引方式，不替换身份字段或分母。
3. 远端固定探针只遍历任务-000084列出的六个根目录，跳过符号链接和固定排除路径，仅识别八类候选名称/格式；索引上限固定为目录16,384个、目录条目262,144个、待处理目录16,384个、单路径4,096字节、候选摘要聚合32MiB，并同时遵守候选4,096个、单候选16MiB、输出32MiB、日志64KiB和总时限900秒上限。
4. 所有身份、协议、路径、权限、计数、指纹、时间或资源异常均清空候选并记录失败原因指纹；不得把索引结果写成来源身份声明。
5. 追加唯一批次并运行专项、数据、审计、研发中心、编译、MarkdownLint、敏感扫描和差异验证；若输入完整，才按任务-000084合同另行更新其状态闭环。
