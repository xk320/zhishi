# 《知势》研发中心

> **宁可错过，不做低胜率交易。**

`docs/研发中心/任务/`中的任务文件是《知势》任务合同与状态的唯一事实来源。
所有工作必须先形成任务文件，再由 Codex 执行，通过 Pull Request 交付，经过架构评审后
才能进入主分支。GitHub Issue只能用于讨论和关联，不能创建可执行任务。

## 一、目录结构

```text
docs/研发中心/
├── README.md              # 工作规则
├── 任务规范.md            # 唯一事实来源、状态与交付规则
├── 看板.md                # 从任务文件汇总的状态视图
├── 总体计划.md            # 阶段与方向，不承载实时任务状态
└── 任务/
    ├── 任务-000001.md
    └── ...
```

任务文件优先于看板、总体计划、Issue、PR描述、标签、聊天和评论。完整规则见[《知势》任务中心规范](./任务规范.md)。

## 二、标准状态

任务只能处于以下状态之一：

- `待执行`：任务合同完整，可以开始。
- `执行中`：已有执行分支，Codex 正在处理。
- `阻塞`：存在明确外部依赖，暂时不能继续。
- `待评审`：已有提交和 Pull Request，等待架构评审。
- `需修复`：评审未通过，等待按意见修改。
- `已完成`：验收通过并已合并主分支。
- `已取消`：经证据证明不应继续。

禁止使用“基本完成”“差不多完成”等模糊状态。

## 三、任务执行闭环

```text
架构层创建任务文件并进入main
    ↓
任务进入待执行
    ↓
Codex读取最高优先级且无阻塞任务
    ↓
更新为执行中并创建独立分支
    ↓
实现、测试、自审、提交、推送
    ↓
创建Pull Request
    ↓
更新为待评审
    ↓
双子智能体评审
    ├── P0/P1为零 → main可信复验 → 精确SHA自动合并 → 状态闭环
    └── 存在P0/P1 → Codex自动修复 → 新SHA重新评审（最多三轮）
```

## 四、Codex 自动执行规则

Codex 每次运行必须：

1. 读取根目录 `AGENTS.md`、本文件、`看板.md` 和 `总体计划.md`。
2. 读取`任务规范.md`并扫描`任务/`下全部任务文件；没有任务文件的Issue禁止执行。
3. 只选择一个最高优先级、状态为`需修复`或`待执行`、依赖全部满足的任务。
4. 认领前检查是否存在同任务的远程执行分支或未关闭PR，并以该分支中的任务文件确认在途状态，防止重复执行。
5. 任务写明`方案状态：已批准执行`时直接按唯一方案推进，不再向用户提供A/B/C选项；
   普通工程取舍由Codex按最安全、简单、可验证和可回滚原则自主决定。
6. 执行前将任务状态改为`执行中`，记录分支和开始时间。
7. 严格遵守任务中的输入合同、输出合同、安全边界和验收标准。
8. 完成后运行验证命令，记录真实结果，不得伪造通过。
9. 提交、推送并创建引用任务编号的 Pull Request。
10. 将任务状态更新为`待评审`，写入提交 SHA、PR、交付物和已知限制。
11. 同步更新 `看板.md`。
12. 未通过验收时不得标记`待评审`或`已完成`。
13. 创建PR后由Codex组织两个独立只读子智能体评审；发现P0/P1后自动修复，新SHA重新
    评审，最多三轮。两者批准、主执行器串行验证和`main`可信复验全部通过后，以精确
    头SHA自动合并，不再等待仓库所有者逐PR批准。完整规则见
    [《PR自动合并策略》](../治理/PR自动合并策略.md)。

## 五、受控研发自动合并

`任务登记`只允许一个完整新任务合同、看板和对应设计文档；编号必须为基线最大编号加一，
历史缺号不得复用。任务交付的允许类型为文档、治理、研究规范、数据治理、数据审计、
数据工程、基础设施验证、策略研究、研究工程、模拟交易、测试和工具。除任务类型外，还要
通过路径、扩展名、普通Git对象、文件数量、体积和敏感信息检查，最终绑定精确头SHA。

《知势》当前只进行策略研究和基于实时数据的模拟交易，不连接真实资金。生产写入、凭据、
原始数据破坏和不可逆操作不会因白名单扩大而获得授权；相关任务必须失败关闭并按安全合同
请求额外决策。

## 六、任务优先级

- `P0`：安全、数据可信度或阶段硬门槛。
- `P1`：当前阶段核心能力。
- `P2`：重要增强。
- `P3`：可延后优化。

选择顺序：优先级高者优先；同优先级按任务编号从小到大。被阻塞任务不得跳过依赖强行执行。

## 七、完成定义

任务只有同时满足以下条件才算完成：

- 所有必要交付物存在；
- 验收标准逐项通过；
- 验证命令和结果已记录；
- Pull Request 已通过评审并合并；
- 任务文件和看板已更新；
- 数据、安全、风险和已知限制已披露。

没有 Git 提交不算完成；没有 PR 不算完成；没有验收不算完成；没有证据不算完成。
