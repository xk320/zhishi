# 任务-000107：首次阻塞解除条件字段死锁修复设计

<!-- markdownlint-disable MD013 -->

## 问题

任务-000106登记时已有唯一`当前阻塞原因`，但没有独立`解除条件`。其合同又要求执行证据不足时首次进入`阻塞`并记录解除条件。现行可信校验器要求基线与头提交的两个字段布局完全相同，导致合法状态闭环无法完成。

## 唯一方案

在可信状态闭环的基线/头提交成对校验中增加窄兼容：只有基线为`待执行`、无首次执行元数据和执行记录、`依赖与阻塞条件`内恰有一个阻塞原因且零个解除条件时，允许头提交转为`阻塞`并在同章节增加恰好一个非空解除条件。规范化后其余合同必须全等。

该方案不按任务编号写特例，不允许普通交付修改合同，也不降低阻塞原因、看板、八字段记录、路径、安全或研究门槛。

## 状态流

```text
基线：待执行 + 唯一阻塞原因 + 无解除条件 + 无执行元数据
  -> 头：阻塞 + 同位置阻塞原因 + 唯一非空解除条件 + 固定首次执行记录
  -> 其余合同规范全等
  -> 可信资格通过
```

任何前提不满足均沿用现有失败关闭。

## 测试边界

- 正向：任务-000106式首次阻塞补齐唯一解除条件。
- 负向：头部仍缺失、字段为空、重复、跨章节、已有字段改写、第二次阻塞、额外合同变化、看板不一致。
- 回归：现有完成、恢复、取消、任务交付和登记测试全部保持通过。
