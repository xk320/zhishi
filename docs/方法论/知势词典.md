# 《知势词典》

本词典用于统一《知势》在界面、代码、日志、研究、回测和决策输出中的中文术语。除数据源原生字段、协议字段和第三方接口字段外，系统对用户展示的指标、参数、状态和决策名称原则上全部使用中文。

## 一、核心决策术语

| 术语 | 定义 | 使用要求 |
| --- | --- | --- |
| 市场之势 | 当前市场整体方向、波动结构与风险偏好的综合状态 | 不等同于单一趋势指标 |
| 市场状态 | 五个状态轴共同描述的版本化市场环境 | 只约束研究适用性及风险和执行权限，不产生方向或许可 |
| 状态轴 | 对市场状态中一个独立环境维度的分类结果 | 各轴必须分别保留证据、反证、冲突和无法判定，不能被综合分掩盖 |
| 市场状态置信等级 | 对冻结状态证据质量的分级 | 不等于预测胜率、模型概率或确定性，不能覆盖质量门 |
| 方向结构 | 指定时间尺度内趋势上行、趋势下行、区间震荡、方向冲突或无法判定的结构类别 | 不等于未来方向预测，不能单独授予交易许可 |
| 波动环境 | 指定尺度内低波动、常态波动、高波动、高波动混沌或无法判定的环境类别 | 高波动不等于高机会，低波动不等于低风险 |
| 流动性状态 | 指定交易场所、市场、标的与计划规模下深度、价差、冲击和退出能力的综合类别 | 不得只用成交额替代盘口、冲击和退出压力 |
| 风险偏好状态 | 由价格、成交、持仓、资金成本和跨标的扩散等多类证据描述的风险承担意愿状态 | 不得由单一指标决定，不等于标的排序或买卖方向 |
| 宏观事件状态 | 对合格事件源所证明的事件常态、观察、限制、冻结或无法判定状态 | 不预测事件结果或行情方向，无来源不等于无事件 |
| 市场事件 | 在冻结交易场所、市场、标的、尺度和观察窗口内，由当时可见市场数据按版本化规则记录的市场行为 | 不等于市场状态、信号、预测、机会或交易许可 |
| 事件事实 | 只使用原数据截止时间前已经到达的信息形成的不可变事件观察、拒绝、无法判定或失败记录 | 后续确认、结果和失效不得覆盖原事实 |
| 事件确认 | 在独立确认窗口成熟后，对原事件是否满足预注册确认合同形成的不可变评价 | 已确认不等于预测有效、方向成立或允许交易 |
| 事件结果 | 在独立结果窗口成熟后，对原事件后续可观察结果形成的不可变记录 | 不得进入原事件身份或被直接解释为因果和稳定优势 |
| 历史事件回放 | 用原冻结版本重建并比较历史现场 | 不得用当前版本替代原版本 |
| 结果窗口合同 | 预先冻结结果窗口与标签语义的合同 | 15分钟和1小时不是主研究尺度 |
| 事件结果统计快照 | 保留全状态分母的不可变结果汇总 | 不等于因果、预测优势或交易许可 |
| 事件失效 | 因输入、规则、Schema、作用域、重放或语义缺陷而追加的影响记录 | 只限制明确的未来使用，不删除或改写历史对象 |
| 事件成熟时间 | 确认或结果窗口结束且相应合同允许开始评价的最早时刻 | 不等于原事件时间，未成熟时不得提前生成标签 |
| 事件簇 | 按冻结关联规则和稳定顺序组织的多个精确事件版本集合 | 不合并成员身份，不以多数票产生方向、预测或许可 |
| 资金之势 | 新增资金更偏向进入、退出或停留在哪一类资产 | 必须结合价格、成交、持仓和资金成本判断 |
| 标的之势 | 单一资产在当前时间尺度上的相对优势 | 必须与 BTC、ETH、SOL 横向比较 |
| 承接能力 | 面对卖压时，价格被持续买盘吸收的能力 | 不得只以“跌得少”作为结论 |
| 扩散程度 | 资金是否由核心资产向高风险资产扩散 | 用于判断风险偏好与轮动阶段 |
| 相关状态 | BTC、ETH、SOL 之间联动强弱及其变化 | 分为高相关、中相关、低相关 |
| 确定性 | 当前支持证据的一致性、完整度和冲突程度 | 不等于预测胜率 |
| 预测胜率 | 历史同类、样本外、计入成本后的成功概率估计 | 必须记录样本、区间和校准状态 |
| 预测胜率区间 | 预测胜率的不确定性范围 | 优先使用置信区间或重采样区间 |
| 赔率 | 预期平均净盈利与预期平均净亏损的比例 | 必须计入全部交易成本 |
| 盈亏平衡胜率 | 在给定净盈利与净亏损下，使净期望等于零的胜率 | 用于判断预测胜率是否具有安全边际 |
| 净期望 | 单笔交易计入成功概率、失败概率和全部成本后的预期收益 | 必须高于已验证门槛才能进入交易许可 |
| 证据完整度 | 必要数据、特征、风险检查和反证是否齐全 | 数据齐全不代表方向正确 |
| 决策问题 | 某项数据、特征、关系或规则需要帮助系统回答的唯一业务问题 | 无法对应明确决策问题的能力不得进入主决策链路 |
| 图谱节点 | 在知识图谱中具有唯一标识、正式定义、来源、用途和验证路径的业务概念 | 节点存在不代表对应能力已经验证或准入 |
| 关系声明 | 两个图谱节点之间带方向、适用范围、证据状态和版本的连接 | 不得把相关、假设或规范约束写成已证明因果 |
| 关系证据状态 | 关系当前属于规范约束、派生定义、待验证假设、相关观察或已验证关系的明确标记 | 状态变更必须附研究证据、适用范围和版本 |
| 证据引用 | 指向可重放数据、研究结果、规则或评议报告的版本化引用 | 摘要不能替代原始来源，同源证据不得冒充独立证据 |
| 逻辑标识 | 跨版本稳定、用于确认同一业务概念或关系的唯一身份 | 不得由名称或创建时间推断 |
| 版本标识 | 精确定位某一不可变对象版本的唯一身份 | 决策、证据和血缘引用必须指向确切版本 |
| 生命周期状态 | 节点或关系所处的提议、验证、候选、试运行、纳入、淘汰或失效阶段 | 与证据状态分离，不得互相推导 |
| 激活清单 | 在明确作用域和有效时间内允许被知识快照选择的版本集合 | 清单更新不得覆盖对象或历史清单 |
| 知识快照 | 为一次决策冻结的节点、关系、证据和激活清单版本集合 | 冻结后不得补写，变更必须生成新决策 |
| 血缘记录 | 连接来源、派生过程、对象版本与下游决策的不可变引用 | 必须支持从决策反查来源及从失效证据查询影响 |
| 回滚 | 通过新激活清单使未来快照恢复选择已评审旧版本的治理动作 | 不删除历史版本，不改写既有决策 |
| 质量门 | 决策进入下一阶段前必须通过的硬检查 | 任一硬门失败时禁止交易 |
| 交易许可 | 系统是否允许发起新交易 | 只有“允许”与“禁止”两种最终状态 |
| 交易许可协议 | 把冻结上下文、版本、评议报告和七道门绑定为不可变许可的合同 | 只能输出允许或禁止，不能替代研究、风险评议或交易执行 |
| AI决策推理 | AI在冻结上下文内形成结构化分析、证据检查、风险与反证记录的受约束过程 | 只生成评议材料，不能替代委员会报告或最终交易许可 |
| 空仓建议 | 系统明确建议不持有新方向仓位 | 空仓是正式决策，不是缺失输出 |
| 失效条件 | 原交易逻辑不再成立的可观测条件 | 必须在下单前定义 |
| 退出条件 | 获利、时间、结构或风险条件触发后的离场规则 | 不得在持仓后临时补写 |
| 风险等级 | 对潜在损失、波动和不确定性的综合分级 | 至少分为低、中、高、极高 |
| 风险预算 | 某笔交易、单日或组合允许承担的最大损失额度 | 必须由账户权益和风险比例推导 |
| 资金占用 | 交易使用的保证金或现金比例 | 不等于最大可能损失 |
| 名义仓位 | 计入杠杆后的市场风险敞口金额 | 必须受风险预算、流动性和交易所限制 |
| 目标波动 | 计划在指定时间尺度内捕捉的价格波动幅度 | 必须动态覆盖成本和安全余量 |
| 超时退出 | 达到最长持有时间后按预设规则退出 | 禁止临时延长时间尺度掩盖失败 |

## 二、研究术语

| 术语 | 定义 |
| --- | --- |
| 研究假设 | 可被数据证伪的明确判断 |
| 基准方案 | 用于比较新方法是否真正有效的最简方案 |
| 样本外验证 | 使用未参与参数选择的数据进行验证 |
| 滚动验证 | 按时间顺序重复训练、验证和前推的过程 |
| 稳健性 | 结果在不同时间、标的、参数和市场状态下保持有效的程度 |
| 失效样本 | 信号出现但交易结果失败的案例 |
| 负面证据 | 反对某项交易或研究假设的证据 |
| 研究准入 | 研究结果达到最低证据标准后进入候选能力库 |
| 正式纳入 | 研究通过回测、成本、风控和运行验证后进入生产决策 |
| 淘汰 | 研究未证明增益、稳定性不足或成本过高，不进入系统 |
| 校准 | 预测概率与实际发生频率保持一致的程度 |
| 安全边际 | 超过盈亏平衡要求、用于吸收估计误差和状态变化的额外优势 |
| 事件时间 | 市场事件实际发生的时间 |
| 到达时间 | 数据被系统接收并可用于决策的时间 |
| 采集时间 | 采集程序记录、转换或持久化数据的时间 |
| 可重放 | 能够只使用某历史时刻之前已到达的数据重建当时决策输入 |
| 数据对象版本 | 一组原始或派生记录在明确模式、时间、作用域和内容指纹下的不可变身份 |
| 数据快照版本 | 为一次研究冻结的数据对象版本集合及其数据截止时间、质量和完整性指纹 |
| 实验方案版本 | 在读取受保护结果前冻结的假设、样本切分、参数、基准、成本和验收标准 |
| 实验运行记录 | 一次实验执行尝试所绑定的输入、代码、环境、状态、输出和审计记录 |
| 结果记录 | 由确切实验运行和评价合同派生的指标、反证、失败样本与验证判定 |
| 重放记录 | 使用原实验绑定版本复现实验并记录输入、输出差异和重放结论的不可变记录 |
| 验证批次 | 在冻结规则、输入、作用域和环境下执行的一次不可覆盖数据验证尝试 |
| 数据验证单元 | 按来源、市场、标的、数据对象、尺度、时间范围和版本独立判定的最小范围 |
| 数据可用性结论 | 对确切验证单元给出的可用、有限可用、不可用或无法判定状态及证据 |
| 允许研究范围 | 经数据验证冻结、明确列出可研究问题、标的、尺度、字段、时间与方法的上界 |

## 三、指标命名原则

1. 名称必须说明指标回答的问题，避免使用含义模糊的“综合指标”。
2. 名称优先使用“对象 + 含义”，例如“以太坊相对强度”“资金效率”“卖盘承接率”。
3. 时间尺度必须作为独立参数或名称后缀，例如“4小时资金之势”。
4. 所有评分统一使用 0～100，但不同评分不得被误认为同一概率口径。
5. 概率使用 0～1 或百分比，必须与主观评分分开。
6. 参数必须包含中文名称、定义、单位、默认值、允许范围和来源。
7. 禁止为了中文化而翻译第三方协议字段；原始字段保留，映射层提供中文解释。

## 四、禁止使用的模糊表达

以下表达不得作为正式决策输出：

- 可能上涨
- 大概率
- 感觉偏强
- 看起来不错
- 可以考虑
- 适当仓位
- 注意风险

必须替换为可执行信息，例如：

- 交易许可：禁止
- 确定性：62
- 预测胜率：未校准
- 建议仓位：0%
- 否决质量门：样本门
- 失效条件：ETH 1小时相对强度连续两个周期低于 BTC
- 最长持有时间：8小时
