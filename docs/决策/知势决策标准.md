# 《知势决策标准》V1

> **宁可错过，不做低胜率交易。**

## 一、目的

本标准定义《知势》如何从数据与研究证据形成唯一、可执行、可审计的交易结论。

它不是某一个模型的说明书，而是所有规则、统计方法、机器学习模型和人工复核都必须遵守的决策合同。

第一阶段适用范围：

- 标的：BTC、ETH、SOL。
- 市场：优先以币安 USDT 本位永续合约为执行参考，现货与其他市场用于验证和补充。
- 时间尺度：4小时、8小时、24小时、48小时。
- 频率：每日 0～2 次。
- 默认结果：禁止交易。
- 目标：捕捉能够覆盖全部成本、风险边界清晰的小段波动，不追求吃完整段行情。

## 二、最高决策原则

1. 没有可证明的优势，默认禁止交易。
2. 不因已经错过一段上涨而降低下一笔交易标准。
3. 不以交易次数、单日收益或短期暴利作为系统优化目标。
4. 不把“确定性”冒充“真实胜率”。
5. 不把高杠杆或大仓位当作高信心的表达方式。
6. 任一硬质量门失败，最终交易许可必须为“禁止”。
7. 任何允许交易的结论，都必须同时给出失效条件、退出条件和风险预算。

## 三、四个必须分离的概念

| 概念 | 定义 | 禁止混用 |
|---|---|---|
| 确定性 | 当前支持证据的一致性、完整度与冲突程度 | 不等于历史成功概率 |
| 预测胜率 | 历史同类、样本外、计入成本后的成功概率估计 | 不得由主观评分直接替代 |
| 赔率 | 预期净盈利与预期净亏损的比例 | 高赔率不代表高胜率 |
| 证据完整度 | 必要数据、特征和风险检查是否齐全 | 数据齐全不代表方向正确 |

预测胜率必须同时记录：

- 点估计。
- 样本数量。
- 适用市场状态。
- 置信区间或重采样区间。
- 最近校准日期。
- 与实际结果的校准误差。

未经校准的“70%”“80%”等数字只能作为研究假设，不能成为生产承诺。

## 四、决策输入合同

每次决策必须冻结一个“决策时刻”，并保存该时刻系统真实可见的信息。

### 1. 基础信息

- 决策编号。
- 决策时间。
- 决策时区。
- 目标时间尺度。
- 数据截止时间。
- 数据版本。
- 规则版本。
- 模型版本。

### 2. 必要市场数据

至少包括：

- BTC、ETH、SOL 最新可交易价格。
- 现货与永续合约成交量、成交额。
- 未平仓合约量及变化。
- 资金费率及变化。
- 标记价格、指数价格和基差。
- 主动买卖成交或可验证的替代指标。
- 订单簿状态；若缺失，必须明确降级。
- 波动率、流动性与预估滑点。

### 3. 必要比较信息

- BTC、ETH、SOL 的绝对收益。
- ETH 相对 BTC 收益。
- SOL 相对 BTC 收益。
- SOL 相对 ETH 收益。
- 相对强度变化速度。
- 相对强度持续性。
- 相关状态与相关性变化。
- 市场是否处于资金扩散、资金集中或混沌状态。

### 4. 数据健康状态

必须记录：

- 缺失率。
- 延迟。
- 乱序。
- 重复。
- 异常值。
- 数据源是否降级。
- 是否能证明不存在未来信息。

关键数据健康状态不合格时，禁止交易。

## 五、七道交易许可质量门

### 质量门一：数据门

通过条件：

- 决策时刻可重放。
- 关键数据齐全且延迟在已验证范围内。
- 时间戳、时区和到达时间明确。
- 不存在无法解释的数据跳变。

失败结果：禁止交易。

### 质量门二：样本门

通过条件：

- 当前市场状态位于研究验证范围内。
- 同类历史样本数量达到研究设定的最低要求。
- 样本外结果可用。
- 结果不是由极少数异常交易贡献。

失败结果：禁止交易或仅进入影子决策。

### 质量门三：优势门

通过条件：

- 首选标的相对另外两个标的存在可解释优势。
- 净期望收益为正。
- 优势高于基准方案。
- 主要支持证据与主要反证均已记录。

净期望的基本表达：

```text
净期望 = 预测胜率 × 平均净盈利
       - (1 - 预测胜率) × 平均净亏损
```

“净盈利”和“净亏损”必须已经扣除手续费、滑点、资金费率和执行延迟影响。

### 质量门四：成本门

通过条件：

- 目标波动覆盖预估往返手续费。
- 覆盖预估滑点。
- 覆盖持仓期资金费率。
- 覆盖安全余量。

最小可交易波动不是固定 1%，而是根据标的波动、流动性和成本动态计算。

### 质量门五：风险门

通过条件：

- 止损与失效条件可执行。
- 单笔最大允许损失未超限。
- 单日累计风险未超限。
- BTC、ETH、SOL 同方向相关风险未超限。
- 距离强平价格有足够缓冲。
- 没有触发重大事件、异常波动或流动性否决。

风险门拥有一票否决权。

### 质量门六：执行门

通过条件：

- 目标市场可交易。
- 预估下单冲击在允许范围内。
- 入场方式、止损、退出和超时规则完整。
- 订单精度、最小数量和保证金约束满足。
- 当前价格未显著偏离信号生成价格。

### 质量门七：频率与纪律门

通过条件：

- 当日交易次数未超限。
- 不属于追回亏损、追回踏空或情绪性加仓。
- 新交易没有与现有风险敞口冲突。
- 交易依据不是“今天必须赚钱”。

## 六、盈亏平衡胜率与安全边际

交易是否值得做，不能只看预测胜率。

若平均净盈利为 `G`，平均净亏损为 `L`，盈亏平衡胜率为：

```text
盈亏平衡胜率 = L ÷ (G + L)
```

允许交易至少应满足：

```text
预测胜率的保守下界
>
盈亏平衡胜率 + 经历史验证的安全边际
```

其中：

- “保守下界”优先使用置信区间下界或保守校准值。
- “安全边际”必须通过历史研究确定，不能凭感觉设定。
- 样本过少时，不得用高点估计掩盖不确定性。

## 七、标的排序规则

每个时间尺度分别对 BTC、ETH、SOL 进行比较。

排序至少考虑：

- 方向优势。
- 相对强度。
- 相对强度加速度。
- 持续性。
- 成交扩张。
- 资金效率。
- 承接能力。
- 持仓量变化质量。
- 资金费率健康度。
- 相关状态。
- 目标波动与成本覆盖。
- 主要反证强度。

第一阶段不得预先固化永久权重。权重、阈值和组合方式必须经过研究准入。

最终只能出现以下结果之一：

1. BTC 为唯一首选。
2. ETH 为唯一首选。
3. SOL 为唯一首选。
4. 无标的达到许可标准，空仓。

若第一名与第二名优势差异不足，结果必须为空仓，而不是强行选择。

## 八、时间尺度选择

系统可同时生成 4小时、8小时、24小时和48小时判断，但最终交易必须选定一个主时间尺度。

选择原则：

- 历史样本有效。
- 净期望最高且稳健。
- 成本覆盖充分。
- 最大不利波动可承受。
- 与执行方式一致。

禁止在入场后随意把 4 小时失败交易改称为 48 小时持仓。

若达到最长持有时间而目标未完成，必须按预设超时规则退出或重新申请交易许可。

## 九、目标波动与退出

### 1. 目标波动

目标波动采用动态方式，至少参考：

- 当前真实波动范围。
- 历史同状态波动分布。
- 流动性和预估冲击。
- 往返成本。
- 时间尺度。

第一阶段研究重点是捕捉当期可交易波动的一部分，而不是预测最高点。

### 2. 失效条件

失效条件必须：

- 在入场前定义。
- 可以实时观测。
- 与原交易假设直接相关。
- 不得仅写成任意价格百分比。

价格止损可以是执行手段，但逻辑失效应同时包含结构或资金证据。

### 3. 退出条件

至少包含：

- 目标退出。
- 失效退出。
- 风险退出。
- 超时退出。
- 数据异常退出。

分批退出和移动止损只有在回测证明增益后才进入正式规则。

## 十、禁止交易的标准情况

出现以下任一情况，默认禁止交易：

- 关键数据缺失、异常或延迟超限。
- 当前市场状态未被研究覆盖。
- BTC、ETH、SOL 排名差异不足。
- 支持证据与反证严重冲突。
- 预测胜率无法校准。
- 净期望不为正。
- 目标波动不能充分覆盖成本。
- 失效条件或退出条件不完整。
- 风险预算不足。
- 当日交易频率或累计亏损达到上限。
- 信号出现后价格已经过度兑现。
- 交易动机属于踏空焦虑、追回亏损或强制完成每日目标。

## 十二、可追溯与复盘

每次决策必须保存：

- 原始数据引用。
- 决策时刻特征快照。
- 各质量门结果。
- 标的排序过程。
- 最终许可与否决原因。
- 建议与实际执行差异。
- 最大有利波动。
- 最大不利波动。
- 最终结果。
- 错误归因。

复盘不得只判断“赚了还是亏了”，还必须判断：

- 决策过程是否合规。
- 数据是否可靠。
- 失效条件是否合理。
- 退出是否符合规则。
- 是否存在正确过程但随机亏损。
- 是否存在错误过程但偶然盈利。

## 十三、版本与变更

- 本标准的变更必须通过 Pull Request。
- 任何新质量门必须说明解决的错误类型。
- 任何放宽门槛的变更必须提供样本外证据。
- 任何生产门槛必须记录来源、适用范围和版本。
- 真实资金交易许可默认关闭，只有模拟交易和影子决策达到独立验收标准后才能另行开启。

《知势》的目标不是让系统每天都给出交易，而是让每一次“允许交易”都经过足够严格的审查。
