# 成本、流动性与执行数据合同 V1.0

<!-- markdownlint-disable MD013 -->

> 没有同一历史现场、确切版本和成本证据，不把毛观察解释为净优势。

## 一、固定研究边界

本合同只处理BTC、ETH，分别形成证据。主研究尺度固定为4小时、8小时、24小时、48小时；
15分钟和1小时只能作为事后结果观察窗口，不能成为市场状态尺度、事件探测尺度或交易许可尺度。
成本登记按交易场所、市场、精确合约、方向（做多/做空）、阶段（入场/退出）和历史时点精确分组，
任何未知维度不得跨组补偿。

## 二、输入与可信版本链

唯一前序输入是任务-000032最终可信重放批次`replay-20260805T013610+0800-4492706a9320`，
配置冻结其验证清单、逐成员结果、SHA-256和合并提交。成本来源登记必须另行提供手续费、
买卖价差、深度、冲击、资金费率、执行延迟和可成交量的来源身份、版本、数据截止时间和可见性证据。
当前成本来源登记不存在；不得用实时当前值、账户等级、文件名或猜测补写历史成本。

## 三、状态与硬门

成本成员状态只允许`拒绝`、`无法判定`、`失败`、`未成熟`、`失效`和`通过`。来源或历史现场
输入身份漂移固定拒绝；缺少任一成本输入或三类时间合同固定无法判定；没有完整手续费、价差、
深度、冲击、资金费率、延迟和可成交量版本链，不得进入通过状态。每个可信重放成员必须有一条
成本结果，BTC和ETH分别计数且守恒。

## 四、安全边界

只读访问固定逻辑别名`ubuntu`的Python预检，不读取业务正文、数据库记录、账户余额或专属费率，
不远端落盘，不修改原始数据、生产服务、权限或防火墙。资源包括批次、成员、输出、日志和内存上限，
超限失败关闭。正式产物不保存原始行、凭据、主机地址、订单、方向结论、胜率、收益或交易许可。

## 五、输出与完成定义

`artifacts/数据/成本执行/<批次>/`保存确定性成员结果CSV、验证清单和报告；根目录批次索引只追加。
输出保存来源/历史现场/规则/代码/输入/结果指纹、成本各字段状态、分组维度和解除条件。批次不可覆盖，
旧证据不改写。数据缺失可以完成为无法判定，不得虚构通过；任务PR合并后才能标记任务-000033已完成并解锁任务-000034。
