# 可信重放来源与历史决策现场合同 V1.0

<!-- markdownlint-disable MD013 -->

> 只有获批来源登记、确切版本和历史可见性证据同时存在，才允许进入重放；证据不足保持无法判定。

## 一、目的与固定边界

本合同为任务-000032建立历史现场重放的可信来源入口。它只加载任务-000029来源身份批次和
任务-000031最终质量批次的已发布证据，不接受调用方自报来源、指纹、到达时间、决策编号或
通过状态。

标的固定为BTC、ETH，分别形成证据，不互相补偿。主研究尺度固定为4小时、8小时、24小时、
48小时；缺少确切尺度合同时，成员不得被提升到任何主研究尺度。15分钟和1小时不是本合同的
市场状态、事件探测或交易许可尺度。

## 二、唯一输入与版本链

配置文件`config/审计/可信重放来源.json`冻结：

1. 任务-000029的`source-identity-1.0`身份清单、完整字节SHA-256和630个确定性成员；
2. 任务-000031合并提交`bf8a00f95cdf5be9d56b963e6fa8f29807dbb918`；
3. 任务-000031最终质量验证清单、质量结果CSV、各自字节SHA-256和315个质量单元；
4. 历史决策登记路径及其“未登记”状态；未登记时不得创建空记录或smoke-only替代品；
5. 资源、SSH白名单、标的、主尺度和安全边界。

加载器只接受普通文件、精确合同版本、精确SHA-256、唯一资产编号和确定性成员顺序。任一
输入漂移、成员重复、标的越界、数量不符或字段合同不符，整批失败关闭，不发布部分结果。

## 三、可信来源加载规则

来源成员必须来自任务-000029身份清单，保留来源成员编号、资产编号、标的、来源身份状态、
来源成员指纹、来源提供者、场所、市场、精确合约、数据对象、Schema版本和授权边界。身份
状态为`拒绝`，或任务-000031质量批次标记`输入漂移`时，第一门结论固定为`拒绝`，原因码为
`input_identity_drift`；其他没有历史决策证据的成员为`无法判定`，原因码为
`decision_record_missing`。

加载器不读取白名单资产正文、不读取数据库业务记录、不读取环境变量或凭据。远端只执行固定
Python标准输入预检，使用逻辑别名`ubuntu`；预检失败即停止，不把失败转换为通过。

## 四、历史决策与可见性硬门

历史决策登记必须逐条提供：决策记录编号、决策时间、数据截止时间、事件时间、到达时间、
采集时间、输入数据版本、输入数据SHA-256、规则版本、代码版本和输出版本。所有时间必须
带时区，所有版本必须不可变；`latest`、`current`、文件修改时间和当前时间都不能替代它们。

只有`到达时间 <= 决策时间`的记录可以进入历史可见集合，边界为闭区间。晚到或修订记录必须
进入新版本，不能覆盖旧现场。确定性重放必须使用冻结业务键稳定排序，并连续执行两次比较
可见记录数量和输出指纹；不一致时固定拒绝，不重试猜测。

本批次历史决策登记不存在，因此没有成员进入第二门。受控测试可以使用明确标记的
`smoke-only`记录验证未来数据拒绝，但该记录不得写入正式批次、报告或统计。

## 五、输出与状态守恒

每个来源成员必须恰好一行，按资产编号、标的、来源成员编号升序。正式输出包括：

- `artifacts/审计/历史现场重放/<批次>/逐成员结果.csv`：来源、质量、时间、版本链、第一门、
  确定性、未来数据拒绝状态、重放结论、原因码和解除条件；
- `验证清单.json`：批次、输入指纹、代码指纹、成员顺序、资源、远端预检和状态计数；
- `验证报告.md`：BTC/ETH独立结论、限制和解除条件；
- 根目录追加式`批次索引.csv`：只追加批次身份和摘要，不覆盖历史批次。

正式结论只允许`拒绝`、`无法判定`、`通过`。本合同没有可证明决策记录时不得出现`通过`。
不保存原始业务记录、网络地址、账户信息、凭据或未脱敏样本；CSV单元格阻止公式前缀。

## 六、安全边界与停止条件

禁止访问服务器业务正文、数据库业务记录和真实市场数据；禁止修改、删除、迁移或覆盖原始
数据；禁止模型训练、回测、胜率收益计算、方向、仓位、订单和交易许可。成员超时、输出超限、
身份漂移、输入缺失、资源不足或发布冲突时失败关闭。找不到合格历史记录不是阻塞条件，应
如实输出零通过及明确解除条件。

## 七、完成定义

已批准来源入口、版本链、时间可见性过滤、确定性函数、负向测试和一次真实只读预检批次全部
形成；所有成员覆盖；报告保持BTC/ETH分别无法判定或拒绝；验证命令通过；任务文件与看板
更新并创建引用任务-000032的PR。PR合并后，任务-000032才能闭环为已完成并解除任务-000033。
