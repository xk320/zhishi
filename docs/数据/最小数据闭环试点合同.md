# 最小数据闭环试点合同

<!-- markdownlint-disable MD013 -->

## 目的

本合同定义任务-000035的隔离试点和真实零成员拒绝路径。它只消费任务-000034已经冻结的
BTC、ETH逐尺度聚合证据，不读取服务器、数据库或真实市场数据正文。

## 事前选择规则

1. 输入批次、成员文件路径和SHA-256必须在配置中冻结；来源路径只能位于批准的聚合证据目录，
   输入字节数有硬上限且读取前后指纹一致。
2. 只接受BTC、ETH；主研究尺度固定为4小时、8小时、24小时、48小时；15分钟和1小时
   只能作为事后结果观察窗口。
3. 叶子必须具有非未知的标的、交易场所、市场类型、精确合约、数据对象和时间范围；
   `尺度证据状态`必须为`通过`。
4. 门1至门6必须全部为`通过`，最终状态只能为`可用`或`有限可用`。
5. 按标的、资产编号、主研究尺度、交易场所、市场类型、精确合约、数据对象、时间范围
   和成员指纹排序，只选择排序后的首个成员；不事后寻找最佳样本。

## 输出与不可变性

- 试点批次位于隔离目录`artifacts/数据/最小闭环试点/<批次>/`。
- `候选评估.csv`保留每个候选的维度、六门状态和拒绝原因；`成员.csv`只保存被规则选中的
  成员，零成员时只保留表头。
- `血缘.csv`、`验证报告.json`和`清单.json`记录来源批次、输入指纹、规则指纹、实现脚本、
  查询脚本、环境和输出指纹。
- 已存在的批次一律拒绝覆盖；旧批次只读。输出总字节数不超过配置上限。
- 构建器在读取、评估和发布阶段检查总运行秒数与进程内存MiB上限；任一资源门失败即拒绝
  发布并清理未完成批次目录。
- 查询器只读取`成员.csv`，并按标的、市场、合约、尺度和时间范围边界返回结果；零成员
  批次必须返回空集和拒绝原因。

## 安全边界与完成定义

不修改原始数据，不建立数据库、常驻服务或生产写入，不训练模型、不回测、不计算胜率收益，
不生成方向、仓位、订单或交易许可。只有试点或真实零成员拒绝批次、报告、实现、测试和验收
记录全部形成后，任务才能进入待评审；零成员必须如实标记为拒绝，不能写成成功闭环。
