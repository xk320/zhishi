# 模拟委托生命周期数据合同 V1.0

<!-- markdownlint-disable MD013 -->

> 模拟成交只证明状态机和证据链可运行，不等于真实交易所成交、延迟、胜率、收益或交易许可。

## 一、身份与输入

当前正式批次为`stage1-simulated-lifecycle-20260812T185838Z-8d1a58bd8a0a`，上游固定绑定任务-000100正式批次、清单和摘要SHA-256。来源固定为逻辑别名`ubuntu`、数据库`orderbook`、表`order_book_raw_snapshots`、标的BTCUSDT/ETHUSDT和索引`idx_raw_snapshot_symbol_capture(symbol,capture_ts_ms)`。

每个标的只执行一条业务`SELECT`，脱敏前按原始`capture_ts_ms+snapshot_id`降序验证唯一全序，脱敏后保存顺序序号与身份指纹，最多256条；复合身份重复、顺序漂移、无索引计划、未来时间或资源超限均失败关闭。当前批次BTCUSDT与ETHUSDT各256条，总计512条，数据库响应6,735,570字节。

## 二、四类时间

- 市场事件时间：固定映射`payload.last_event_time_ms`；不得由`capture_ts_ms`替代。
- 系统到达时间：固定映射`payload.last_local_recv_ts_ms`；必须不早于市场事件时间。
- 批次采集时间：本地完整收到有界查询结果后的UTC时间，只证明本批次观测时点。
- 模拟生命周期时间：在已确认可见时间之后按固定基准/压力偏移生成，只表示审计场景。

时间语义固定绑定仓库内不可变证据`config/模拟交易/任务-000103订单簿生产者时间语义证据.json`（SHA-256=`96771a789beb74a79aa806553e241699051a71aa94a58cfd9af66d881bbe198a`）和订单簿源码快照提交`030499faca3d6955d75c75cbc59656a4981f6c05`：`real_orderbook.py` SHA-256=`fdb17777bd325aa52b55a5b03af5187ebc5804ded8ab3cde81237561be17639e`，`storage.py` SHA-256=`d4fed7bf0fc89666a9836a17f144ef41d2a6d13d829124437032c9787bf9b05d`。前者将Binance深度增量事件`E`写入`last_event_time_ms`，并在`apply_diff`处理时调用`now_ms()`写入`last_local_recv_ts_ms`；后者把`source=canonical_book`、`snapshot_schema_version=1`的完整快照写入`payload_json_full`。仓库证据、来源标志、版本或指纹不匹配时，时间门保持`unknown`且不得生成任何模拟动作。

当前512个成员的来源标志、市场事件时间、系统到达时间和本批次可见边界均满足单调与未来数据硬门。`capture_ts_ms`仅参与成员选择和唯一全序，不冒充市场事件时间或真实委托延迟。

## 三、状态机与场景

唯一状态转移为：

```text
created → sent → acknowledged → evaluated → filled / canceled / unknown
```

固定场景为做多/做空、进取型市价/进取型限价/被动限价撤销，以及基准/压力两个未校准审计时钟。进取型场景只根据同一冻结快照的有效最优档和正数量进入模拟`filled`；被动限价没有逐笔队列身份，必须进入`canceled`并记录`QUEUE_IDENTITY_UNAVAILABLE`，禁止用后续价格穿越倒推成交。

结果按标的、Binance、USDⓈ-M永续合约、独立合约身份、方向、生命周期阶段、场景、时钟、4/8/24/48小时主尺度和结果状态形成1056个精确分组。每个阶段都显式保留`unknown`桶，已观察总和恒等于候选分母；每组完整保存七种状态计数以及候选、已观察、失败、未成熟和失效计数；BTC与ETH分别保存分母，不互相补偿。

## 四、脱敏与不可变性

原始payload、价格、数量、档位和名义金额只在单进程内存中校验，不写本地文件或Git。冻结输入仅保存快照身份SHA-256、payload SHA-256、顺序序号、四类时间、来源字段、可成交布尔事实和分母。

`simulate`、`replay-1`和`replay-2`为独立进程；三次规范结果SHA-256必须完全一致。SSH与远端MySQL输出增量读取，超过上限立即终止；远端地址空间限制为256MiB，并记录每个本地阶段和远端查询的独立峰值。批次完成精确文件集、清单自洽、生命周期、重放、摘要语义和资源复算后，以同文件系统no-replace原子发布；旧批次不得覆盖。

## 五、安全与解释边界

- 不发送网络委托或交易所模拟委托，不访问账户、签名端点或API Key。
- 不写Ubuntu、数据库、订单簿文件、原始数据、服务、权限或防火墙。
- 不训练模型、不正式回测、不生成方向、仓位、订单、胜率、收益或交易许可。
- 模拟`filled`不证明真实成交、真实排队、真实滑点、真实延迟或多年成本覆盖。
- 多年历史手续费、资金费率、深度、冲击和可成交量仍保持未知；阶段1与阶段2不得因本合同单独放行。

## 六、验证与回滚

执行器固定运行`prepare → probe → plan → collect → simulate → replay-1 → replay-2 → validate`。任一阶段失败不得发布为正式批次。回滚仅删除或回滚仓库内配置、执行器、测试、文档和脱敏派生证据；远端与数据库没有写入，无需数据回滚。
