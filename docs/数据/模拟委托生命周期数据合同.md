# 模拟委托生命周期数据合同 V1.0

<!-- markdownlint-disable MD013 -->

> 模拟成交只证明状态机和证据链可运行，不等于真实交易所成交、延迟、胜率、收益或交易许可。

## 一、身份与输入

当前正式批次为`stage1-simulated-lifecycle-20260812T175300Z-0638c3587854`，上游固定绑定任务-000100正式批次、清单和摘要SHA-256。来源固定为逻辑别名`ubuntu`、数据库`orderbook`、表`order_book_raw_snapshots`、标的BTCUSDT/ETHUSDT和索引`idx_raw_snapshot_symbol_capture(symbol,capture_ts_ms)`。

每个标的只执行一条业务`SELECT`，按`capture_ts_ms+snapshot_id`降序形成唯一全序，最多256条；复合身份重复、顺序漂移、无索引计划、未来时间或资源超限均失败关闭。当前批次BTCUSDT与ETHUSDT各256条，总计512条，数据库响应6,730,102字节。

## 二、四类时间

- 市场事件时间：固定映射`payload.last_event_time_ms`；不得由`capture_ts_ms`替代。
- 系统到达时间：固定映射`payload.last_local_recv_ts_ms`；必须不早于市场事件时间。
- 批次采集时间：本地完整收到有界查询结果后的UTC时间，只证明本批次观测时点。
- 模拟生命周期时间：在已确认可见时间之后按固定基准/压力偏移生成，只表示审计场景。

当前512个成员的市场事件时间、系统到达时间和本批次可见边界均满足单调与未来数据硬门。`capture_ts_ms`仅参与成员选择和唯一全序，不冒充市场事件时间或真实委托延迟。

## 三、状态机与场景

唯一状态转移为：

```text
created → sent → acknowledged → evaluated → filled / canceled / unknown
```

固定场景为做多/做空、进取型市价/进取型限价/被动限价撤销，以及基准/压力两个未校准审计时钟。进取型场景只根据同一冻结快照的有效最优档和正数量进入模拟`filled`；被动限价没有逐笔队列身份，必须进入`canceled`并记录`QUEUE_IDENTITY_UNAVAILABLE`，禁止用后续价格穿越倒推成交。

结果按标的、Binance、USDⓈ-M永续合约、方向、场景、时钟和4/8/24/48小时主尺度精确分组。BTC与ETH分别保存分母，不互相补偿。

## 四、脱敏与不可变性

原始payload、价格、数量、档位和名义金额只在单进程内存中校验，不写本地文件或Git。冻结输入仅保存快照身份SHA-256、payload SHA-256、四类时间、来源字段、可成交布尔事实和分母。

`simulate`、`replay-1`和`replay-2`为独立进程；三次规范结果SHA-256必须完全一致。批次完成语义回读、资源硬门和文件清单后，以同文件系统no-replace原子发布；旧批次不得覆盖。

## 五、安全与解释边界

- 不发送网络委托或交易所模拟委托，不访问账户、签名端点或API Key。
- 不写Ubuntu、数据库、订单簿文件、原始数据、服务、权限或防火墙。
- 不训练模型、不正式回测、不生成方向、仓位、订单、胜率、收益或交易许可。
- 模拟`filled`不证明真实成交、真实排队、真实滑点、真实延迟或多年成本覆盖。
- 多年历史手续费、资金费率、深度、冲击和可成交量仍保持未知；阶段1与阶段2不得因本合同单独放行。

## 六、验证与回滚

执行器固定运行`prepare → probe → plan → collect → simulate → replay-1 → replay-2 → validate`。任一阶段失败不得发布为正式批次。回滚仅删除或回滚仓库内配置、执行器、测试、文档和脱敏派生证据；远端与数据库没有写入，无需数据回滚。
