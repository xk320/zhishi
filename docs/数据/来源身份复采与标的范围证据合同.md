# 来源身份复采与标的范围证据合同

<!-- markdownlint-disable MD013 -->

本合同对应任务-000072。它只补齐来源身份与标的范围的可复算证据，不改变任务-000029历史合同、
历史批次或阶段1最终审计结论。

## 固定身份键

每个BTC或ETH成员由以下键唯一确定，并按资产编号、标的确定性排序：

```text
资产编号 + 标的 + 输入成员SHA-256
```

只有以下字段全部有当前版本结构化证据时，成员才可标记为`已证明`：来源提供者、交易场所、市场类型、
标的身份、精确合约、数据对象、Schema确切版本、授权边界和字段中文映射。证据记录必须逐字段绑定资产、
标的、成员指纹、证明字段和不可变定位；缺证据、冲突或探针失败保持`无法判定`或`拒绝`。

## 输入与冻结

`config/数据/来源身份复采.json`冻结资产清单、历史来源合同、任务-000071结构合同、阶段1最终审计报告和
缺口清单的SHA-256。执行器同时冻结合同、执行器、任务-000072和全部输入字节；任一字节漂移即失败关闭。
资产类型仅允许候选数据文件和数据库元数据，标的只允许BTC、ETH，不跨标的补偿缺失。

## 远端边界

复采只能通过逻辑别名`ubuntu`执行标准输入探针。探针只允许白名单文件的`stat`和
`information_schema.TABLES/COLUMNS`元数据读取，禁止读取业务记录、环境变量、凭据或远端临时文件，
并以串行成员超时、批次超时、输出和日志上限约束资源。探针结果必须覆盖冻结资产全集，遗漏、额外成员、
未知状态或敏感字段均拒绝发布。

## 批次与状态

批次目录位于`artifacts/数据/来源身份复采/<批次>/`，使用追加式、原子、不可覆盖发布，保存：

- 合同、执行器、任务、输入、成员和结果内容指纹；
- BTC、ETH分别的候选资产总体、身份成员总体和`已证明/拒绝/无法判定`计数；
- 每个成员的状态、证据定位、限制、解除条件和远端元数据指纹；
- 远端写入、业务记录读取、敏感信息和结论边界声明。

`已证明`只说明来源身份合同成立，不代表数据质量、时间可见性、历史覆盖、研究准入、预测优势、胜率、
收益或交易许可。主研究尺度仍固定为4小时、8小时、24小时、48小时；15分钟和1小时只能作为事后结果
观察窗口，不得升级为市场状态、事件探测或交易许可尺度。

## 缺口处理

批次只能对`ZS-DATA-GAP-001`给出精确的标的、交易场所、合约、数据对象、Schema版本、批次和指纹范围。
没有当前结构化证据的成员继续阻塞；不得通过路径、表名、字段名、市场常识或描述性差异补齐身份，不得关闭
其他P0缺口或解除阶段2门禁。
