# 来源身份输入指纹修复与复采合同

<!-- markdownlint-disable MD013 -->

本合同对应任务-000075，目标是把任务-000072历史复采的输入漂移与当前来源身份证据分开裁决。它不覆盖任务-000029、
任务-000072的合同或批次，也不把输入重签解释为来源身份通过。

## 版本与范围

- 合同版本：`source-identity-input-drift-recapture-1.0`
- 任务：任务-000075
- 标的：BTC、ETH，分别统计，禁止跨标的补偿
- 主研究尺度：4小时、8小时、24小时、48小时
- 15分钟、1小时：仅为事后结果观察窗口，不是状态、事件或交易许可尺度
- 允许身份状态：`已证明`、`拒绝`、`无法判定`

## 输入冻结

执行器必须同时保存当前输入和历史批次输入的SHA-256、文件字节、规范化比较结果、成员顺序、任务文件指纹、
规则指纹、执行器指纹和资源策略。当前输入发生任何变化时，必须停止发布并重新建立批次；历史批次只读保留。

漂移分类固定为：`未漂移`、`仅换行规范化差异`、`内容变化`、`输入缺失`、`路径越界`、`无法判定`。分类仅描述输入差异，
不能推导来源、标的、合约、质量、时间或研究准入。

## 来源身份证据

每个候选成员必须逐项绑定：来源提供者、交易场所、市场类型、标的身份、精确合约、数据对象、Schema确切版本、
授权边界、字段中文映射、当前输入成员指纹和证据定位。仅当所有字段具备当前版本结构化证据时才可标记`已证明`；
证据冲突、缺失、漂移或远端无法证明时保持`拒绝`或`无法判定`。

## 远端与安全

只允许白名单逻辑目标`ubuntu`和固定版本只读探针；数据库范围仅为`information_schema.TABLES`、
`information_schema.COLUMNS`。禁止读取业务正文、环境变量、凭据、原始市场记录，禁止远端写入、数据库写入、
原始数据修改、生产服务或权限变更。远端输出只保留脱敏指纹、计数、状态、原因码和证据定位。

## 批次与失败安全

批次必须串行、资源有界、追加式、原子发布且不可覆盖，保存输入/规则/授权/执行器指纹、成员顺序、结果摘要、
漂移分类和安全声明。输入漂移、成员遗漏、跨标的补偿、越权、未来数据、超时、输出超限或敏感信息均失败关闭，
不得用默认值、文件路径、表名、字段名或文件修改时间补齐身份。

## 结论边界

本合同只回答当前版本来源身份证据是否可复算，不产生质量、三类时间、历史重放、成本、容量、恢复、模型、回测、
胜率、收益、因果、预测优势、研究准入、方向、仓位、订单或交易许可结论。任何部分解除必须精确到标的、交易场所、
合约、数据对象、Schema版本和输入批次；未列范围继续阻塞。
