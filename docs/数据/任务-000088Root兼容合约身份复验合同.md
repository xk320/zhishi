# 任务-000088：root兼容合约身份复验合同

<!-- markdownlint-disable MD013 -->

## 目的

在任务-000084已经批准的受控合同内，复验固定 Ubuntu 入口在实际 UID=0 时是否存在可脱敏、可复算的合约身份候选。root 只表示属主身份事实，不等价于 UID=1001 专用只读证明，也不解除任务-000084、`ZS-DATA-GAP-001`或阶段1门禁。

## 固定输入与边界

- 远端目标只能是逻辑别名 `ubuntu`，固定 SSH 探针为 `ssh -o BatchMode=yes -o ConnectTimeout=15 -o ServerAliveInterval=5 -o ServerAliveCountMax=1 ubuntu python3 -`。
- 只扫描 `/opt/binance-event`、`/opt/celueqing`、`/opt/crypto-radar`、`/opt/event-prob-lab`、`/opt/orderbook-intelligence-service`、`/var/lib/mysql` 下八类固定文件名和 CSV/JSON/SQLite/DB 元数据；不跟随符号链接并排除 `/proc`、`/sys`、`/dev`、`/run`、`/tmp`、`/var/tmp`。
- 公开接口仅为 `https://fapi.binance.com/fapi/v1/exchangeInfo` 与 `https://dapi.binance.com/dapi/v1/exchangeInfo`，不发送凭据，不保留完整响应。
- 分母固定为任务-000083冻结的 BTC、ETH 各315个成员，九项身份字段和成员SHA-256逐项绑定，禁止跨标的补偿。
- 主研究尺度固定4小时、8小时、24小时、48小时；15分钟和1小时仅可作为事后观察窗口。

## root兼容语义

批次必须记录 `uid=0`、`访问模式=root兼容只读`、协议 `zhishi-binance-contract-probe/1`、扫描完整性、失败安全、失败原因指纹和资源事实。输出中的 `扫描是否专用只读` 必须为 `false`；不得伪造 UID=1001，不得把root结果解释为专用只读来源证明。

## 失败安全与不可变性

身份、协议、固定路径、权限、成员顺序、计数、指纹、时间或资源任一漂移时，清空候选并记录失败原因；不以部分候选生成来源身份证据。批次只能在本地以唯一目录追加发布，历史目录不可覆盖。只有全部630个成员均具备完整九字段、当前成员SHA-256、Schema/授权/字段中文映射和唯一证据定位时，才允许生成任务-000084来源身份声明输入；否则任务-000084继续阻塞。

## 不在范围

不创建或修改用户、SSH权限、数据库授权、生产服务、防火墙或订单簿逻辑；不读取价格、成交、订单簿、账户、凭据、环境变量或未登记路径；不写远端、不改数据库、不删除或迁移原始数据；不训练模型、回测、模拟或真实交易，不产生方向、仓位、订单、胜率、收益、因果或交易许可结论。

## 可验证输出

- 批次清单、Binance接口摘要、Ubuntu候选摘要、成员状态摘要和输入/规则/执行器/授权指纹。
- BTC、ETH分别保留候选总体、已观察、已证明、拒绝、无法判定、失败、未成熟、失效计数及守恒结果。
- 所有输出经敏感扫描；验证命令、资源事实、限制和回滚记录随PR提交。
