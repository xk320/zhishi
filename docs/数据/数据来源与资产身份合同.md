# 《知势》数据来源与资产身份合同 V1.0

<!-- markdownlint-disable MD013 -->

> 没有可验证的来源与资产身份，不进入时间、质量、重放、成本或研究链路。

- 合同版本：`source-identity-1.0`
- 任务编号：`任务-000029`
- 现行标的：BTC、ETH，分别形成证据，不得互相补偿
- 冻结规则：`config/数据/数据来源与资产身份.json`
- 执行入口：`scripts/数据/冻结数据来源身份.py`
- 批次根目录：`artifacts/数据/来源身份/<来源身份批次>/`

## 一、目的与边界

本合同把既有清单中的候选数据文件和数据库元数据对象登记为版本化、内容寻址、
不可覆盖的来源身份成员。登记回答“现有证据能否证明该资产属于指定标的的指定来源、
场所、市场、合约、数据对象和 Schema”，不回答数据质量、时间可见性或研究价值。

不得从路径、文件名、字段或常识猜测身份。既有清单中的`标的范围`仅是历史候选映射，
不得自动写入`标的身份`；服务名、表名、文件名、后缀和字段相似度也不得自动成为
来源提供者、交易场所、市场类型、精确合约、数据对象或字段业务语义。

本合同禁止采集和补采市场数据，禁止修改、清洗、去重、迁移或删除原始数据；不完成
三类时间、质量统计、历史重放、成本、流动性、模型、回测、胜率、收益或交易许可。

## 二、冻结输入与内容寻址

正式配置逐项冻结以下输入的 SHA-256：

1. `artifacts/审计/数据源清单.csv`；
2. `docs/审计/数据源清单.md`；
3. `docs/审计/数据资产审计报告.md`；
4. `docs/审计/数据缺口与补采清单.md`；
5. `scripts/审计/发现数据资产.py`。

配置同时冻结以下治理基线，执行器必须复核键名和值完全一致，并从对应提交读取
`docs/研发中心/任务/任务-000029.md`重新计算基线内容 SHA-256：

- `main`基线提交：`c7763a411ba6c239ddecb923bf04ebbbec5eebf3`；
- 任务-000028 合并提交：`e138bd589a5bde38c81f48d38b7c449f6f13df37`；
- 任务-000038 合并提交：`b49cf2fabfbbb2968dc18efba80121de0d7601e8`；
- 任务-000029 基线路径：`docs/研发中心/任务/任务-000029.md`；
- 任务-000029 基线内容 SHA-256：
  `025f6498fa29edc5fc6c1cdb8214a1215b3e0fe7869bdb543a9ceb440e56d560`。

任一文件不是普通文件、发生指纹漂移、路径越出仓库或合同出现未知字段时，批次失败且
不发布。配置文件 SHA-256 是规则 SHA-256；排序后的冻结成员规范 JSON 形成成员
SHA-256；排序后的身份记录规范 JSON 形成清单内容 SHA-256。当前执行任务文件按执行时
内容单独计算 SHA-256 并写入清单，但不作为普通冻结输入，避免任务状态记录变化导致
输入合同递归漂移。CSV 文件另算输出 SHA-256。

执行器在加载合同前保存配置字节、执行器、当前任务文件和全部冻结输入的字节指纹，资产
与成员只从该执行前内存清单构建；批次合同校验、结构化证据解析、成员和探针构建均不得
再次读取业务路径，从而排除文件瞬时 A→B→A 的错版窗口。完成合同加载和成员构建后、启动 SSH 前必须复算一次；
远端结束后、写出暂存文件前和原子发布前再次复算。任一指纹漂移整批失败且不发布，清单
只能记录执行前保存的指纹，不得在远端返回后首次读取这些指纹。

批次载荷由合同版本、任务编号、治理基线、输入 SHA-256、规则 SHA-256、执行器
SHA-256、当前执行任务文件 SHA-256、成员 SHA-256、清单内容 SHA-256 和结果摘要组成。
载荷按规范 JSON 计算非递归 SHA-256，不包含冻结时间、批次编号、输出 SHA-256 或
批次载荷 SHA-256 自身；`身份清单.json载荷`指纹即批次载荷 SHA-256。

来源身份批次编号为：

```text
source-identity-<带时区冻结时间>-<批次载荷SHA-256前12位>
```

暂存目录必须创建在批次根目录内，批次目录使用同文件系统目录级原子 no-clobber 发布：
macOS 使用`renameatx_np(RENAME_EXCL)`，Linux 使用`renameat2(RENAME_NOREPLACE)`；不支持
的平台失败关闭，不得回退到先检查再替换。目标目录或符号链接已经存在时拒绝执行。
历史批次不可覆盖。失败、超时、输出超限或合同漂移均不得留下半批次。

## 三、候选成员与确定性顺序

候选资产只包括资产清单中的`候选数据文件`和`数据库元数据`。每个候选资产分别生成
一个 BTC 成员和一个 ETH 成员，因此：

```text
身份成员总体 = 候选资产总体 × 2
```

成员编号由资产编号、标的和冻结输入成员 SHA-256 内容寻址生成。身份声明必须显式绑定
同一资产的当前`输入成员SHA-256`，陈旧指纹不得生效。同一冻结输入不依赖
CSV 原始行顺序。最终成员按以下键升序排列：

1. 来源提供者；
2. 交易场所；
3. 市场类型；
4. 标的；
5. 精确合约；
6. 数据对象；
7. Schema 确切版本；
8. 资产编号；
9. 成员编号。

## 四、身份字段与中文字段映射

每个成员必须逐项记录：来源提供者、交易场所、市场类型、标的身份、精确合约、
数据对象、Schema 确切版本、授权边界和字段中文映射。没有证据的字段写`未知`，不得用
默认值补齐。

已证明的字段中文映射中，每个原始字段必须同时登记：中文名称、类型、单位、精度和
空值语义。字段名本身不证明业务语义；只有配置中绑定冻结证据 SHA-256 的映射可以进入
`已证明`记录。

未来需要新增非空身份声明时，必须新增用途以`身份合同证据:`开头的冻结 JSON 输入，不能
使用本合同 Markdown、普通审计文档或自述 smoke 证据替代。结构化证据固定版本为
`source-identity-evidence-1.0`，顶层只包含`证据版本`和`记录`。每条记录只包含：
`证据记录编号`、`资产编号`、`标的`、`输入成员SHA-256`、`证明字段`和`声明值`。
声明中的证据定位必须精确命中唯一记录，并逐条匹配资产、标的、输入成员、唯一证明字段
及声明值；`字段中文映射`按规范 JSON 精确比较。拒绝声明必须命中
`证明字段=拒绝结论`且`声明值=拒绝`的结构化记录。

## 五、三态判定与计数守恒

成员状态只能是：

- `已证明`：只读元数据复核成功；身份声明完整；声明绑定当前输入成员 SHA-256 和本批次
  远端元数据 SHA-256；数据库对象同时绑定相同 Schema SHA-256；每个身份字段都有且仅有
  一条专用身份合同证据，证据用途、非空定位和证据文件 SHA-256 与冻结输入一致。
- `拒绝`：资源不存在、越出白名单、成为符号链接、冻结元数据漂移、身份声明与本批次
  元数据或 Schema 冲突，或存在绑定当前输入成员、专用身份合同证据和`拒绝结论`的明确
  拒绝声明。有效拒绝声明优先于探针失败或超时，避免已知拒绝被降级为无法判定。
- `无法判定`：只读复核失败或超时、现有证据仅证明候选资源存在、身份字段不完整，或
  没有满足`已证明`与`拒绝`条件。未知不是通过，也不自动升级为拒绝。

总体和 BTC、ETH 分标的都必须满足三态计数守恒：

```text
已证明 + 拒绝 + 无法判定 = 身份成员总体
BTC三态合计 = 候选资产总体
ETH三态合计 = 候选资产总体
```

任何成员静默遗漏、重复、出现第四种状态或计数不守恒时拒绝发布整个批次。BTC 结果
不能补偿 ETH，ETH 结果也不能外推给 BTC。

## 六、只读元数据复核合同

正式入口只接受 SSH 逻辑别名`ubuntu`，使用无交互、无本地 shell 的固定命令执行

```text
env -i PATH=<固定系统路径> HOME=/nonexistent LANG=C.UTF-8 LC_ALL=C.UTF-8 PYTHONDONTWRITEBYTECODE=1 python3 -I -B -
```

命令参数顺序固定，不拼接可变 shell 文本；
`env -i`与 Python 隔离模式阻止本地或远端继承的`PYTHONPATH`、启动脚本和用户级模块
进入探针。探针脚本从标准输入执行，不创建远端临时文件，也不生成 Python 字节码，远端
不落盘。

文件成员只允许在冻结白名单根目录内执行`lstat/stat`元数据复核，不读取文件正文；只有
普通文件可成为`已观察`，其元数据指纹必须包含文件类型和权限模式，目录或其他文件类型
一律拒绝。
数据库成员只允许通过无默认配置的本地套接字查询获批的
`information_schema.TABLES`和`information_schema.COLUMNS`元数据；不得读取数据库业务记录，
不得读取环境变量、配置凭据、令牌或密钥。数据库资产成为`已观察`时必须同时返回非空的
元数据 SHA-256 和 Schema SHA-256，后续身份声明必须逐项匹配；文件资产不得伪造
Schema SHA-256。表与列元数据必须由一次精确过滤的 JOIN 查询取得；Schema 指纹覆盖表
引擎、排序规则、行格式、创建选项，以及列序、名称、类型、可空、默认值、字符集、排序
规则、键、数值精度、小数位、时间精度、额外属性、生成表达式和注释。文本使用 HEX
无歧义编码，NULL 显式标记；固定列数、编码、列序、唯一性、非空列集或 LIMIT 任一校验
失败时相关数据库成员只能为`无法判定`。

冻结资源上限包括批次总超时、逐成员超时、最大成员数、最大输出字节数和最大日志
字节数。本地 SSH 和远端 MySQL 都必须边产生边读取输出，在超时或任一输出上限触发时
立即终止子进程；不得先把无界输出读入内存。任一上限触发后失败安全，不把超时、命令
失败或输出缺失映射为`已证明`。远端未知字段、非法 JSON、命令不可用和系统错误只返回
固定脱敏错误，不回显远端正文、字段名、主机、用户名或异常参数。本地和远端有界子进程
在 Popen 成功后必须立即进入最外层 try/finally；选择器构造、缓冲区、截止时间、注册与读取
全部位于该保护范围内。finally 必须终止仍存活进程并无条件 wait/reap，并独立关闭已构造的
选择器、标准输出和标准错误管道；任何 BaseException 都不得遗留活进程、僵尸或未关闭管道。

CLI 失败只输出固定中文公开错误码和类别。合同、JSON、路径、权限、系统错误和未知运行时
异常的正文及 cause 均不得进入标准输出或标准错误；未列入白名单的运行时错误统一映射为
`ZI-SI-2999`。非法整数、未知参数或缺少必填参数统一映射为`ZI-SI-1000`，不得输出
usage、原始参数、参数名或参数值。

## 七、输出合同

每个成功批次只发布：

- `来源身份清单.csv`：确定性排序的逐成员中文字段清单；
- `身份清单.json`：冻结时间、治理基线、输入 SHA-256、规则 SHA-256、执行器 SHA-256、
  当前执行任务文件 SHA-256、成员 SHA-256、清单内容 SHA-256、非递归批次载荷及其
  SHA-256、输出 SHA-256、候选资产总体、三态汇总、BTC/ETH 独立汇总、成员顺序和
  安全声明。

输出不得记录主机地址、用户名、凭据、令牌、私钥、环境变量、完整配置或原始业务记录。
CSV 单元格阻止公式前缀执行。远端失败详情不进入异常文本或批次产物。

## 八、当前冻结结论

正式配置的`身份声明`为空，也没有把本合同 Markdown 伪装为身份合同证据输入，因为既有
审计只证明候选资源和部分元数据存在，没有形成
提供者、交易场所、市场、标的、合约、数据对象、Schema 业务合同、授权边界和字段
中文映射的完整证据。因此真实批次必须按只读复核结果如实生成`拒绝`或`无法判定`，
不得为了形成已证明成员而解释路径或字段。

这项登记减少的是“把名称相似或位置相邻的候选资源误当成 BTC/ETH 正式研究输入”的
错误，并增强来源身份和研究准入风险约束。它不解除阶段 2 门禁。

## 九、复验命令

目标测试：

```bash
python3 -m unittest tests/数据/test_冻结数据来源身份.py -v
```

真实只读批次由主执行器在获得当前任务授权后串行执行：

```bash
python3 scripts/数据/冻结数据来源身份.py \
  --contract config/数据/数据来源与资产身份.json \
  --ssh-target ubuntu \
  --batch-root artifacts/数据/来源身份 \
  --timeout 600
```

命令成功只证明该批次按本合同完成登记，不证明数据质量、研究价值、收益或交易许可。
