## 一、缺口优先级

- `P0`：阻断来源、时间、质量、重放、成本或闭环硬门。

## 三、补采与修复顺序

按硬门依赖顺序推进：

```text
来源与标的身份
  → 三类时间、频率、业务键和修订合同
  → 输入身份与完整质量审计
  → 真实决策记录和可信重放入口
  → 成本、流动性和执行数据
  → BTC、ETH独立闭环
  → 容量试采、备份和恢复
  → 新的最终审计与允许研究范围
```

后序工作可以为诊断提前收集只读证据，但不能将前序缺口标记为已解除。

## 四、补采合同最低字段

任何未来补采任务至少必须预先冻结：

```text
任务编号与获批唯一方案
来源版本、提供者、交易场所、市场、标的和合约
字段中文映射、类型、单位、精度和空值语义
事件、到达、采集时间、时区和数据截止时间
频率、延迟、迟到、补录、修订和撤销规则
业务键、排序、重复和异常规则
数据范围、样本范围和明确排除范围
原始段、标准化、质量、成本、血缘和快照版本
只读安全、资源预算、超时、失败与回滚方式
交付物、验证命令和解除条件
```

缺少上述字段的补采事项应保持阻塞，不能因服务器可访问而直接运行。

## 五、禁止的补采方式

- 通过文件名、目录、表名或字段相似度猜来源、标的和时间语义；
- 用文件修改时间替代到达时间；
- 把事后补采记录写入旧快照或旧决策现场；
- 覆盖、删除、重排或静默去重原始版本；
- 读取凭据、环境变量、完整配置或未授权业务正文；
- 用BTC或ETH数据补足另一标的，或用未限定数据补足任一标的；
- 为得到足够样本而降低质量、成本、重放或研究门槛；
- 用容量规划假设宣称磁盘、备份或恢复已经通过；
- 在没有任务文件的情况下执行本清单中的候选建议。

## 六、解除与关闭规则

1. 缺口只能由新的不可变证据关闭，不能仅凭评论、Issue、PR描述或口头说明。
2. 关闭记录必须引用任务编号、输入批次、输出版本、指纹和验收结果。
3. 部分解除必须精确限定标的、市场、字段、尺度和时间范围，未列范围继续阻塞。
4. 新数据、修订、规则或代码变化后重新打开受影响缺口并创建新验证批次。
5. 所有P0缺口关闭且六道门通过前，基准模型阶段保持禁止。

## 七、数据与安全影响

本清单的初始记录未执行采集、补采、服务器访问、数据库读取、数据迁移、模型训练、回测或交易；后续任务的实际动作以各自追加记录为准。它不包含网络地址、凭据、原始记录或未脱敏样本，也不构成任何生产操作授权。
