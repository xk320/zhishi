# 《知势研究数据合同与实验记录规范》V1.0

<!-- markdownlint-disable MD013 -->

> 研究结论必须能够回到当时可见的数据、冻结的实验方案和不可变结果；不能重放的结论不得进入决策链路。

- 文档性质：研究数据、实验运行、结果与重放的版本合同
- 适用对象：BTC、ETH、SOL；4小时、8小时、24小时、48小时研究
- 当前阶段：理论规范；数据资产审计、存储、运行器和重放器尚未实现
- 真实资金状态：关闭

## 一、目标、边界与职责

### 1.1 目标

本规范建立从研究假设到研究结果的不可变版本链，使《知势》能够回答：

1. 一项研究使用了哪个来源、哪个数据版本和哪个数据截止时间；
2. 在实验开始前冻结了哪些假设、样本切分、参数、基准、成本和验收标准；
3. 一次实验由什么代码、配置、环境、随机种子和依赖版本运行；
4. 结果由哪些输入和运行记录派生，是否包含失败样本、反证和无法判定；
5. 历史重放是否只加载原实验绑定的版本，而不是事后“最新版本”；
6. 数据或结果失效后，哪些研究、知识、决策和复盘对象受到影响。

本规范减少数据版本混用、事后调参、结果覆盖、时间穿越和只有结论没有依据的错误研究，
增强数据门、样本门、优势门和成本门的风险约束。它不证明任何市场优势。

### 1.2 不在范围

本规范不：

- 采集、清洗、修订、删除、覆盖或迁移市场数据；
- 选择数据库、对象存储、表结构、文件格式或实验平台；
- 实现数据管道、特征平台、实验运行器、模型训练或回测系统；
- 规定未经真实数据验证的参数、阈值、胜率或收益目标；
- 自动修改研究生命周期、知识关系、激活清单或交易许可；
- 接入交易所、生产数据库、真实交易账户或下单接口；
- 把理论字段示例冒充真实数据、实验记录或验证结果。

### 1.3 与既有合同的职责边界

| 合同 | 负责 | 本规范负责的连接 | 本规范不得替代 |
| --- | --- | --- | --- |
| 《知势研究准入规范》 | 研究问题、可证伪假设、生命周期和准入门槛 | 为研究版本提供精确数据、实验和结果引用 | 不裁决研究准入、淘汰或失效 |
| 《知识图谱运行时设计》 | 知识对象、证据状态、血缘和激活清单 | 提供可登记为证据引用的数据与结果版本 | 不发布知识快照或升级关系 |
| 《知势交易许可协议》 | 冻结决策上下文、七道质量门和二元许可 | 允许许可反查研究所绑定的数据与结果 | 不生成允许许可或仓位 |
| 《知势研究与决策复盘规范》 | 过程、结果、偏差、反证和反馈评价 | 为复盘提供原始研究现场与重放记录 | 不改写复盘结论或历史许可 |
| 本规范 | 数据、实验、参数、结果与重放记录的身份、版本和血缘 | 保证研究依据可追溯、可校验、可重放 | 不运行研究或批准结论 |

发生冲突时，资金与数据安全、原始数据只读、当时可见性、不可变历史、研究准入和交易
许可硬门优先。

## 二、核心不变量

未来实现必须同时满足：

1. **原始数据只读：** 已登记原始记录不得覆盖；修订、补录和纠错形成新数据版本。
2. **版本精确：** 引用必须指向唯一版本标识和完整性指纹，不能使用名称、路径、
   创建时间或“最新”推断版本。
3. **时间完整：** 涉及市场数据时必须记录事件时间、到达时间、采集时间和数据截止时间。
4. **当时可见：** 决策或研究现场只能使用到达时间不晚于数据截止时间的数据。
5. **先冻结后运行：** 假设、样本切分、参数、基准、成本和验收标准必须在读取受保护
   结果前冻结。
6. **一次运行一个身份：** 每次执行都生成独立实验运行记录；重试不能覆盖失败或中止记录。
7. **参数有版本：** 参数名称、类型、单位、精度、值、允许范围和来源共同构成参数版本。
8. **结果只追加：** 成功、失败、中止、无法判定和反对假设都是正式结果，不得删除或改写。
9. **运行与结论分离：** 运行技术成功不等于假设成立，运行失败也不能写成反对假设。
10. **支持与反证并存：** 结果必须同时保留支持证据、主要反证、失败样本和异常引用。
11. **作用域不外推：** 标的、尺度、市场状态、时间范围和数据版本不匹配时不得复用结论。
12. **重放不漂移：** 重放使用原绑定版本；使用事后修订或当前版本不构成原现场重放。
13. **血缘双向可查：** 能从结果反查全部输入，也能从失效数据版本查询受影响的下游对象。
14. **实验不授予许可：** 任一实验或结果状态都不能跳过研究准入、知识治理和七道质量门。
15. **缺失安全停止：** 必需引用缺失、冲突、指纹不一致或时间不可证明时，结果为无法判定，
    预测性使用默认禁止。

## 三、对象模型、身份与版本

### 3.1 核心对象

| 对象 | 作用 | 稳定身份 | 不可变版本身份 |
| --- | --- | --- | --- |
| 数据来源记录 | 描述提供者、市场、接口、授权和时间语义 | 数据来源逻辑标识 | 数据来源版本标识 |
| 数据对象版本 | 描述一组原始或派生记录的确切内容与边界 | 数据对象逻辑标识 | 数据对象版本标识 |
| 数据快照版本 | 冻结一次研究允许读取的数据对象版本集合 | 数据快照逻辑标识 | 数据快照版本标识 |
| 研究假设版本 | 冻结决策问题、方向、作用域和反证条件 | 研究编号 | 研究版本 |
| 实验方案版本 | 冻结方法、切分、基准、成本、参数和验收标准 | 实验方案逻辑标识 | 实验方案版本标识 |
| 参数集合版本 | 冻结一次方案使用的全部参数 | 参数集合逻辑标识 | 参数集合版本标识 |
| 代码与环境版本 | 冻结可执行代码、依赖、运行时和硬件语义 | 环境逻辑标识 | 环境版本标识 |
| 实验运行记录 | 记录一次不可覆盖的执行尝试 | 实验运行标识 | 记录版本标识 |
| 结果记录 | 记录一次运行派生的指标、反证和判定 | 结果逻辑标识 | 结果版本标识 |
| 重放记录 | 记录对原运行的复现请求、差异和结论 | 重放标识 | 重放记录版本标识 |

逻辑标识用于说明“这是同一个业务对象”，版本标识用于说明“这是当时使用的确切内容”。
任何下游引用都必须使用版本标识。

### 3.2 标识建议

研究编号沿用：

```text
ZS-研究-年份-四位序号
```

未来实现可以采用以下可读前缀，但具体编码由独立实现任务确定：

```text
ZS-数据来源-...
ZS-数据对象-...
ZS-数据快照-...
ZS-实验方案-...
ZS-实验运行-...
ZS-研究结果-...
ZS-实验重放-...
```

前缀不构成版本身份。真实身份还必须包含不可歧义的版本标识和完整性指纹。不得通过
版本号排序、文件路径、时间戳或提交消息猜测当前有效版本。

### 3.3 对象关系

```text
研究假设版本
    ↓ 冻结
实验方案版本 ──→ 参数集合版本
    ↓ 绑定              ↓
数据快照版本 ──→ 代码与环境版本
    ↓                  ↓
           实验运行记录
                  ↓
              结果记录
                  ↓
       研究评审 / 知识证据候选
                  ↓
     历史重放与研究、决策复盘
```

一条结果记录必须且只能指向一次实验运行记录；一次运行可以因不同的冻结评价合同生成
多个结果版本，但每个结果必须说明评价合同版本，且不能覆盖旧结果。

## 四、数据版本合同

### 4.1 数据来源记录

每个数据来源版本至少记录：

```text
数据来源逻辑标识
数据来源版本标识
提供者与市场
接口、文件或频道标识
原始字段与中文语义映射版本
时间语义与时区
价格、数量、金额和比例的单位与精度
采集频率与预期延迟
修订、补录和撤销语义
授权与使用边界
有效时间与失效条件
完整性指纹
```

凭据、令牌、密码、账户密钥和不必要的个人信息不得进入来源记录、日志或指纹输入。
授权记录只保存可审计的授权引用和边界，不保存秘密值。

### 4.2 数据对象版本最小合同

每个原始或派生数据对象版本至少记录：

| 字段 | 要求 | 缺失时处理 |
| --- | --- | --- |
| 数据对象逻辑标识与版本标识 | 唯一且不可复用 | 拒绝登记 |
| 数据层级 | 原始、标准化、派生或冻结快照成员 | 无法判定血缘 |
| 数据来源版本 | 指向确切来源版本 | 不得用于正式实验 |
| 模式与字段映射版本 | 字段、类型、单位、精度、空值语义 | 不得进入数据快照 |
| 标的、市场与时间粒度 | 明确适用范围 | 禁止跨范围使用 |
| 事件时间范围 | 最早、最晚及边界包含规则 | 不得进行时间研究 |
| 到达时间范围 | 最早、最晚及可见性语义 | 不得证明无时间穿越 |
| 采集时间范围 | 采集或持久化时间 | 标记时间血缘不完整 |
| 数据截止时间 | 本版本允许包含的到达时间上界 | 不得冻结研究现场 |
| 记录数与分区清单 | 精确计数和成员边界 | 无法校验完整性 |
| 质量摘要版本 | 缺失、延迟、乱序、重复、异常和修订统计 | 数据质量状态未知 |
| 派生血缘 | 上游版本、公式、代码、参数和执行记录 | 派生对象无效 |
| 内容指纹 | 对规范化内容或清单计算 | 拒绝冻结 |
| 创建与冻结时间 | 使用统一时区并区分业务时间 | 仅作审计，不作为版本身份 |

原始记录集合不能被派生结果替代。派生对象必须保留到全部上游版本的完整血缘；只保存
摘要、截图、查询文本或网页链接不构成可重放数据版本。

### 4.3 三类时间与数据截止时间

- **事件时间：** 市场事件实际发生的时间；
- **到达时间：** 数据已被系统接收并可供研究或决策读取的时间；
- **采集时间：** 采集、转换或持久化动作被记录的时间；
- **数据截止时间：** 本次实验允许读取数据的到达时间上界。

历史研究的可见集合必须满足：

```text
到达时间 <= 数据截止时间
```

事件时间早于截止时间但到达时间晚于截止时间的数据属于事后到达数据，不能进入原研究
现场。时区、夏令时、交易所时钟和时钟漂移处理必须版本化；不允许用本地显示时间代替
带时区的标准时间。

### 4.4 质量与异常合同

每个数据对象版本必须显式记录：

| 质量维度 | 必需记录 |
| --- | --- |
| 缺失 | 缺失字段、时间段、标的、原因状态和处理方式 |
| 延迟 | 到达延迟分布、超时阈值版本和超时记录 |
| 乱序 | 乱序数量、允许窗口和排序规则版本 |
| 重复 | 重复判定键、数量、去重策略和保留记录引用 |
| 异常 | 异常规则版本、原值、处置和是否保留 |
| 修订 | 前序版本、修订来源、差异清单和影响范围 |
| 覆盖 | 实际范围与合同范围差异 |
| 一致性 | 跨字段、跨分区和跨来源校验结果 |

质量处置不得静默修改原始版本。删除重复、填补缺失、校正异常或重排记录均生成新的
标准化或派生版本，并保留原始值、规则版本和处置血缘。

### 4.5 数据快照版本

数据快照用于冻结一次实验可读取的数据边界，至少包含：

```text
数据快照逻辑标识与版本标识
研究编号与研究版本
数据截止时间
数据对象版本有序集合
模式与字段映射版本集合
质量摘要版本集合
作用域：标的、市场、时间尺度、市场状态与时间范围
纳入与排除规则版本
记录数、分区数与成员清单指纹
快照完整性指纹
冻结时间
冻结者或自动化主体引用
```

冻结后不能向快照补入晚到数据。需要补录、修订、扩大范围或改变排除规则时，生成新
快照版本，并明确前序快照和差异。

## 五、实验方案与参数合同

### 5.1 预注册实验方案

读取受保护验证集、样本外结果或未来窗口结果前，必须冻结：

1. 研究编号、研究版本和可证伪假设；
2. 预期减少的错误交易、提升的净期望或增强的风险约束；
3. 标的、时间尺度、市场状态、时间范围和不适用范围；
4. 数据需求、数据截止语义和允许的数据质量状态；
5. 样本内、验证集、样本外和前推窗口的划分；
6. 无策略或简单方法基准；
7. 特征、标签、目标、公式、单位、精度和计算顺序；
8. 参数集合及参数搜索边界；
9. 手续费、滑点、资金费率、执行延迟和安全余量；
10. 随机过程、种子策略和重复次数；
11. 必报指标、分组维度、失败样本和反证提取方法；
12. 支持假设、反对假设和无法判定的预注册标准；
13. 稳健性、校准、置信区间和敏感性方法；
14. 停止条件、异常处理和不得放宽的风险门槛；
15. 允许查看结果后的变更类型及新版本规则。

若在读取受保护结果后改变假设、标签、切分、参数空间、基准、成本或验收标准，必须生成
新的研究版本和实验方案版本；旧运行及其结果继续保留。

### 5.2 参数集合版本

每个参数至少记录：

```text
参数中文名称
协议或代码字段名
数据类型
单位与精度
冻结值
允许范围或枚举
默认值是否实际使用
来源与选择方法
敏感性检查范围
```

参数集合还必须记录有序参数清单、序列化规则和完整性指纹。未使用的参数不得以默认值
悄悄进入运行；自动搜索生成的每组参数必须有独立身份，并能反查搜索空间与选择规则。

### 5.3 样本切分与防泄漏

样本切分合同至少定义：

- 每个区间的事件时间、到达时间和边界包含规则；
- 特征观察窗口、标签窗口、持有窗口和冷却窗口；
- 训练、验证、样本外和前推顺序；
- 标签成熟时间与数据可见时间；
- 重叠样本、清洗间隔和隔离间隔处理；
- 市场状态分层规则版本；
- BTC、ETH、SOL是否共享特征或标签，以及同源关系；
- 禁止随机打乱时间序列替代前推验证。

无法证明特征和标签在实验时点可见时，实验不得形成预测性结论。

## 六、实验记录合同

### 6.1 运行前冻结输入

一次运行开始前必须绑定：

```text
实验运行标识
研究编号与研究版本
实验方案版本
数据快照版本
参数集合版本
代码版本
配置版本
环境版本
随机种子或确定性声明
基准版本
成本与执行假设版本
请求时间与执行主体
输入集合完整性指纹
```

代码版本优先记录不可变提交 SHA。工作区有未提交改动时必须记录差异指纹并标记
`非冻结代码`；非冻结代码运行不得作为准入证据。

### 6.2 环境记录

环境版本至少记录：

- 操作系统、架构、运行时和时区；
- 直接与传递依赖的锁定版本；
- 计算库、硬件和数值精度语义；
- 容器或环境镜像指纹（如使用）；
- 线程、并行、确定性和随机数实现配置；
- 关键外部服务或不可封装依赖的版本；
- 环境清单完整性指纹。

环境记录不得包含凭据、令牌、密钥、账户秘密或不必要的个人信息。

### 6.3 运行状态

实验运行状态只能为：

| 状态 | 含义 | 能否生成研究判定 |
| --- | --- | --- |
| 已登记 | 输入已登记，尚未冻结 | 否 |
| 已冻结 | 输入完整性通过，尚未执行 | 否 |
| 运行中 | 正在执行 | 否 |
| 技术成功 | 按方案完成并产出可校验结果 | 可以进入结果评价 |
| 技术失败 | 因代码、环境、资源或依赖失败 | 否 |
| 已中止 | 因人工、安全门或停止条件终止 | 否 |
| 重放不一致 | 重放超出预注册允许差异 | 否，进入调查 |

技术状态与研究验证结果必须分离。`技术成功`不能自动写为`支持假设`，`技术失败`不能
写为`反对假设`或`淘汰`。

### 6.4 运行结束记录

每次尝试都必须追加记录：

```text
开始时间、结束时间与持续时间
最终运行状态
实际加载的输入版本集合
实际环境版本
输出对象版本集合
运行日志版本与审计事件
资源与异常摘要
停止代码和中文原因
输出集合完整性指纹
```

相同输入重试必须生成新实验运行标识，并引用被重试的运行。幂等请求可以返回已有运行
身份，但不能生成无法区分的重复记录或覆盖失败记录。

## 七、结果记录合同

### 7.1 结果身份与最小字段

每个结果版本至少包含：

```text
结果逻辑标识与版本标识
实验运行标识
研究编号与研究版本
实验方案与评价合同版本
数据快照、参数、代码、配置和环境版本
适用范围与不适用范围
验证结果
基准结果
成本前与成本后结果
分组结果
稳健性与校准结果
支持证据引用
主要反证与失败样本引用
异常与排除样本引用
限制与失效条件
结果完整性指纹
生成时间与冻结时间
```

验证结果只能为：

- `支持假设`；
- `反对假设`；
- `无法判定`。

研究生命周期状态和准入结论由《知势研究准入规范》另行裁决，不能从验证结果自动推导。

### 7.2 必报指标

只要研究涉及交易结果，至少报告：

| 指标 | 必需语义 |
| --- | --- |
| 交易次数 | 样本、标的、尺度、方向和排除规则一致 |
| 空仓比例 | 分母、观察窗口和无信号语义明确 |
| 胜率 | 与成功定义、成本和持有窗口绑定 |
| 盈亏比 | 使用成本后平均净盈利与平均净亏损 |
| 单笔净期望 | 计入手续费、滑点、资金费率和延迟 |
| 最大回撤 | 口径、复利方式和时间范围明确 |
| 净收益 | 不得替代风险、样本量和不确定性 |
| 校准指标 | 仅在输出概率时必需，附区间与样本量 |

还必须报告基准、样本内、验证集、样本外、分市场状态和预注册稳健性结果。指标不适用时
写`不适用`并说明原因；样本不足或数据不完整时写`无法判定`，不得填入推测值。

### 7.3 分组、反证与失败样本

结果必须按任务适用范围中的标的、尺度、市场状态和时间阶段分组，不得用总体平均隐藏
局部失效。至少保存：

- 每个分组的样本量、指标和不确定性；
- 最差分组和性能崩溃区域；
- 主要失败样本的精确数据与运行引用；
- 反对假设的结果版本；
- 同源支持证据关系；
- 被排除样本及预注册排除规则；
- 参数、成本、时间、标的和重采样敏感性。

只展示最佳参数、最佳时间段、最佳标的或少数异常盈利不构成合格结果。

### 7.4 结果修订

以下任一变化必须创建新结果版本：

- 修正评价代码、指标公式、单位或精度；
- 改变排除样本、分组、成本、基准或置信区间；
- 发现数据、参数、代码、环境或血缘错误；
- 增加新结果窗口或新复盘证据；
- 修改验证结果、限制、反证或失效条件。

新结果必须引用前序结果、变更原因、差异清单和影响范围。旧结果保持可查询，并根据治理
结论标记后续发现的问题，不得原地覆盖。

## 八、完整性指纹与血缘

### 8.1 指纹规则

完整性指纹必须基于确定性规范化内容计算，并同时记录：

- 指纹算法与版本；
- 规范化和字段排序规则；
- 字符编码、数值精度和时间格式；
- 分区或大对象成员清单的组合方式；
- 指纹覆盖和明确排除的字段。

时间戳、文件名、数据库自增编号或云存储地址不能替代内容指纹。算法升级时生成新指纹
记录并保留旧指纹，不能重新解释旧身份。

### 8.2 血缘记录最小合同

```text
血缘记录标识
上游对象类型、逻辑标识与版本标识
下游对象类型、逻辑标识与版本标识
变换类型与目的
代码、公式、配置与参数版本
事件时间、到达时间、采集时间和数据截止时间
执行主体与执行时间
输入、输出完整性指纹
异常、排除与质量处置引用
```

血缘必须支持：

1. 从研究结果反查数据来源、快照、参数、代码、环境和运行记录；
2. 从数据修订、来源失效或代码缺陷正向查询受影响的结果、研究、知识和决策；
3. 区分原始数据、标准化数据、派生特征、实验输出和评价结果；
4. 识别循环依赖、版本缺失、指纹冲突和作用域不一致。

## 九、历史重放合同

### 9.1 重放输入

重放必须加载原运行绑定的：

- 研究假设与实验方案版本；
- 原始、标准化、派生数据对象和数据快照版本；
- 数据截止时间及三类时间；
- 参数、代码、配置、环境、随机种子和基准版本；
- 样本切分、标签、特征、成本、延迟和风险假设；
- 评价合同与预注册允许差异；
- 原运行与结果完整性指纹。

任一必需版本无法取得、内容指纹不一致或到达时间晚于原截止时间时，重放结果必须为
`无法重放`，不得自动改用替代版本。

### 9.2 重放结果

重放结论只能为：

| 结论 | 条件 |
| --- | --- |
| 完全一致 | 预注册要求完全相同的输出和指纹均一致 |
| 允许差异内一致 | 非确定性指标在运行前冻结的容差和重复统计内 |
| 不一致 | 超出容差、指标、样本或血缘不同 |
| 无法重放 | 必需输入、环境、权限或版本不可取得 |

容差必须在读取重放结果前定义，至少说明适用指标、绝对或相对误差、重复次数、随机种子
策略和统计判定。事后放宽容差必须创建新的重放方案版本，不能改变旧重放结论。

### 9.3 重放记录

每次重放保存：

```text
重放标识与记录版本
原实验运行与结果版本
重放方案版本
请求原因
实际加载的全部版本
输入指纹比较
输出指纹与指标差异
重放结论
异常、停止代码与中文原因
开始、结束和冻结时间
```

重放成功只证明在约定条件下可复现，不证明假设正确、关系已验证或交易许可允许。

## 十、与研究准入、知识图谱和复盘的连接

### 10.1 研究准入

研究准入记录必须引用：

- 研究版本和实验方案版本；
- 数据快照和质量摘要版本；
- 参数、代码、配置、环境和运行版本；
- 结果、反证、失败样本和重放记录版本；
- 审查时仍未解决的数据、血缘和复现问题。

只有技术成功、结果完整、重放满足预注册要求且研究最低验收全部通过时，才可以申请研究
状态升级。申请不等于批准；结果为支持假设也不能跳过候选和试运行。

### 10.2 知识图谱

数据对象和研究结果只以证据引用进入知识图谱：

- 数据对象版本可以支持字段语义、作用域和可见性；
- 结果版本可以申请支持待验证假设、相关观察或已验证关系；
- 血缘记录连接来源、研究、结果、知识对象和使用该证据的决策；
- 数据或结果版本失效时，只生成影响记录、降级或撤出申请，不改写历史知识快照；
- 研究状态和结果判定不能自动升级关系证据状态或进入激活清单。

### 10.3 交易许可

实验结果不能直接成为`交易许可：允许`。未来作为优势证据至少还须满足：

1. 研究生命周期、关系证据状态和激活清单均已通过各自治理；
2. 研究、数据、结果、知识和决策作用域完全匹配；
3. 数据、成本、校准、风险和执行条件在许可时刻仍有效；
4. 没有未解决的反证、失效、重放失败或版本冲突；
5. 七道质量门全部独立通过。

任一条件缺失：

```text
交易许可：禁止
建议仓位：0
```

### 10.4 研究与决策复盘

复盘引用原数据、实验和结果版本，只能追加：

- 当时过程是否符合预注册和数据可见性；
- 后续数据是否形成新反证或失效触发；
- 结果差异来自数据、方法、参数、执行、环境还是无法判定；
- 是否需要新研究版本、数据审计或重放修复任务。

复盘不能修改原数据快照、实验运行、结果判定、研究状态、知识关系或交易许可。

## 十一、技术中立接口合同

未来实现至少提供以下语义能力，名称与技术可以不同：

| 能力 | 必需输入 | 输出 | 失败时 |
| --- | --- | --- | --- |
| 登记数据版本 | 来源、模式、时间、质量、成员和指纹 | 不可变数据版本身份 | 拒绝部分登记 |
| 冻结数据快照 | 研究版本、截止时间、对象版本集合 | 快照版本与指纹 | 不生成半套快照 |
| 冻结实验方案 | 假设、切分、参数、基准、成本和标准 | 方案与参数版本 | 保持未冻结 |
| 创建实验运行 | 全部冻结版本和输入指纹 | 唯一运行身份 | 不启动执行 |
| 完成实验运行 | 实际输入、输出、状态和审计记录 | 不可变运行记录 | 保存失败或中止 |
| 冻结结果 | 运行、评价合同、指标、反证和指纹 | 结果版本 | 输出无法判定 |
| 请求重放 | 原运行、重放方案和全部版本 | 重放身份 | 列出缺失版本 |
| 查询血缘 | 精确版本和查询方向 | 版本化路径与断点 | 不使用名称猜测 |
| 标记后续失效 | 目标版本、证据和影响范围 | 新失效事件 | 不覆盖原对象 |

写入必须支持幂等请求、基于前序版本的条件写入和完整失败回滚。禁止只写入部分引用却
返回成功。

## 十二、异常处理与安全降级

| 异常 | 处理 | 研究与决策结果 |
| --- | --- | --- |
| 数据来源或版本不存在 | 停止冻结并记录缺失身份 | 无法判定；不得准入 |
| 三类时间或截止时间不完整 | 标记时间血缘断点 | 不得证明无时间穿越 |
| 内容指纹冲突 | 隔离冲突版本并停止运行或重放 | 不得沿用旧结论 |
| 晚到数据进入原快照 | 拒绝快照或生成修订版本 | 原现场不得补写 |
| 实验方案未冻结 | 拒绝读取受保护结果 | 保持提议或验证中 |
| 运行实际输入与冻结输入不同 | 技术失败或中止并保留审计记录 | 不生成支持结论 |
| 结果样本不足 | 记录样本与解除条件 | 验证结果无法判定 |
| 重放不一致 | 保留差异并调查数据、环境和代码 | 停止预测性使用 |
| 上游数据或代码后续失效 | 正向查询影响并提出复验或降级 | 新许可默认禁止 |
| 并发写入冲突 | 拒绝覆盖，基于同一前序版本重提 | 历史记录保持不变 |
| 未知异常 | 记录审计事件并安全停止 | 不猜测、不自动重试为成功 |

日志、记录和错误输出不得包含密钥、密码、令牌、账户凭据或不必要的个人信息。

## 十三、未来实现验收场景

未来实现至少覆盖：

1. 数据对象缺少来源版本、模式版本或内容指纹时拒绝登记；
2. 原始数据修订生成新版本且旧版本仍可查询；
3. 事件时间早但到达时间晚于截止时间的数据不能进入原快照；
4. 缺失、延迟、乱序、重复和异常均有显式记录及处置血缘；
5. 数据快照冻结后不能补入晚到或修订数据；
6. 实验方案未冻结时不能读取受保护验证集结果；
7. 修改假设、切分、参数空间、基准、成本或标准会生成新方案版本；
8. 参数缺少类型、单位、精度或来源时不能冻结参数集合；
9. 非冻结代码和未锁定环境运行不能作为研究准入证据；
10. 同一输入的重试生成新运行身份且保留失败记录；
11. 技术成功不会自动生成支持假设或准入结论；
12. 技术失败不会被写成反对假设；
13. 样本不足、数据不完整或血缘冲突时结果为无法判定；
14. 结果同时保留基准、成本、分组、失败样本和主要反证；
15. 修改指标或排除样本会生成新结果版本而不覆盖旧版本；
16. 能从结果反查全部数据、方案、参数、代码、环境和运行版本；
17. 能从失效数据版本查询受影响的研究结果、知识证据和决策引用；
18. 重放拒绝使用事后修订数据或当前“最新版本”；
19. 非确定性重放只使用预注册容差，不能事后放宽；
20. 重放成功不自动升级研究状态或关系证据状态；
21. 结果支持假设也不能直接生成交易许可允许；
22. 版本、指纹、作用域或时间任一冲突时预测性使用默认禁止；
23. BTC或ETH结果不能替代SOL证据，跨尺度和跨市场状态不能静默外推；
24. 失败、中止、无法判定、反证和淘汰记录在新版本产生后仍可查询；
25. 真实资金关闭时任何实验或结果都不能触发账户写入。
