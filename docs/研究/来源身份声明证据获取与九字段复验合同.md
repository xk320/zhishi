# 来源身份声明证据获取与九字段复验合同

## 目的

本合同定义任务-000081对来源身份声明证据的唯一复验口径。它只判断当前是否存在可验证的显式来源身份声明，不把目录、路径、文件名、服务名称、表名、结构相似性或历史聊天解释为来源身份。

## 固定范围

- 标的：BTC、ETH；分别统计，不跨标的补偿。
- 主研究尺度：4小时、8小时、24小时、48小时。
- 15分钟、1小时：仅作为事后结果观察窗口，不得升级为市场状态、事件探测或交易许可尺度。
- 候选成员：任务-000080最终批次冻结的630个成员，BTC与ETH各315个。

## 九字段与证据合同

每个成员必须有以下九个身份字段：来源提供者、交易场所、市场类型、标的身份、精确合约、数据对象、Schema确切版本、授权边界、字段中文映射。

完整声明还必须绑定：

1. 声明入口版本、用途和唯一证据定位；
2. 声明内容或证据文件SHA-256；
3. 当前成员输入SHA-256；
4. Schema指纹和授权快照SHA-256；
5. 撤销事实及有效期语义；
6. 确定性成员顺序、规则指纹和执行器指纹。

入口只允许来自任务合同登记的结构化配置或白名单只读入口。任务开始时必须把已登记声明入口冻结到`config/数据/任务-000081来源身份声明输入快照.json`，批次只绑定该快照及其来源文件指纹；后续审计台账、任务状态和看板追加不得成为批次输入，避免自引用哈希循环。入口为空时，入口状态为`未登记`；字段缺失为`入口不完整`；证据存在但无法与当前成员逐项匹配为`无法判定`。只有九字段、所有指纹和撤销事实均匹配的成员才可标记`已证明`。

同一成员存在多个完整声明且规范化内容不唯一时，必须输出`IDENTITY_DECLARATION_CONFLICT`并保持`无法判定`；不得按排序任选一个声明证明成员。

## 状态与计数

每个BTC/ETH成员必须保留候选分母、入口状态、可定位状态和以下最终状态之一：`已证明`、`拒绝`、`无法判定`、`失败`、`未成熟`、`失效`；入口状态另行记录`未登记`、`入口不完整`或`已登记`，可定位状态必须显式记录`已定位`或`不可定位`。批次摘要必须按BTC、ETH分别给出候选总体、入口状态计数、可定位计数、九字段状态计数和最终身份状态计数，零值也要保留；每组计数均须等于315，禁止删除失败样本、缩小分母或跨标的补偿。

## 远端与数据边界

远端只允许使用逻辑别名`ubuntu`的既有专用只读入口，且只读取合同登记的声明元数据、Schema摘要和授权快照。禁止业务正文、价格、成交、订单簿、账户、环境变量、凭据、未登记路径和任何写入。服务器、数据库、原始数据、生产服务、权限和订单簿逻辑不得修改。

## 失败安全与解除

- 入口为空或字段缺失：按成员记录`未登记`/`入口不完整`，`ZS-DATA-GAP-001`保持阻塞。
- 指纹漂移、授权不明、撤销状态不明、超时、越界或敏感输出：记录`无法判定`或`失败`并停止相关发布。
- 完整九字段和全部指纹匹配：只对对应BTC或ETH成员形成精确解除范围；不自动解除其他缺口或阶段门。
- 任何描述性差异不得推导因果、预测优势、胜率、收益、研究准入或交易许可。

## 批次要求

批次必须包含输入/规则/执行器/资源指纹、入口清单、逐成员清单、计数摘要、失败原因、解除条件和安全声明。批次目录追加式、原子发布、不可覆盖；历史目录字节不变。
