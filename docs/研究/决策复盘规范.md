# 《知势研究与决策复盘规范》V1.0

<!-- markdownlint-disable MD013 -->

> 复盘不是用结果替历史决定辩护，而是用不可变证据识别过程偏差、适用边界和新的可证伪问题。

- 文档性质：研究、决策与交易许可的事后评价和反馈合同
- 适用范围：BTC、ETH；4小时、8小时、24小时、48小时
- 当前阶段：理论规范；不表示历史重放、模拟交易或结果采集已经实现
- 真实资金状态：关闭

## 一、目标与边界

### 1.1 目标

本规范建立从研究结论、冻结决策上下文、交易许可到实际结果的可追溯反馈路径，使
《知势》能够回答：

1. 研究是否按预注册合同执行，结论是否仍受证据支持；
2. 决策是否只使用当时可见、版本一致且作用域匹配的信息；
3. 交易许可是否忠实应用七道质量门、主要反证、风险与执行约束；
4. 实际结果与原判断之间出现了什么偏差；
5. 偏差来自数据、研究、决策、许可、执行、纪律还是暂时无法判定；
6. 是否形成需要通过任务中心登记并重新进入研究准入的新问题。

复盘的价值是减少结果倒推、幸存者偏差、重复犯错和错误规则继续扩散。复盘本身不证明
市场优势，不授予交易许可，也不能把偶然盈利解释为正确过程。

### 1.2 不在范围

本规范不：

- 采集、修订或覆盖市场数据；
- 实现历史重放器、回测系统、模拟交易或模型训练；
- 自动修改研究状态、知识关系、质量门、阈值、风险参数或交易规则；
- 自动创建、执行或完成研发任务；
- 修改历史决策卡、评议报告或交易许可；
- 接入交易所、下单接口、生产数据库或真实资金账户；
- 用事后已知结果补写决策时刻缺失的信息；
- 因一次盈利、亏损、踏空或未成交直接得出稳定胜率或收益结论。

### 1.3 与既有合同的职责边界

| 合同 | 负责 | 复盘不得替代的事项 |
| --- | --- | --- |
| 《知势研究准入规范》 | 研究生命周期、版本、验证、准入、淘汰与失效 | 复盘不能直接升级、复活或纳入研究 |
| 《知势知识图谱》 | 节点、关系、证据状态和`进入复盘`关系 | 复盘不能直接改写节点、关系或证据状态 |
| 《知识图谱运行时设计》 | 不可变版本、血缘、激活清单、快照和回滚 | 复盘不能修改历史快照或自动发布新清单 |
| 《知势决策委员会》 | 十个评议单元及硬否决职责 | 复盘不能重新投票或覆盖原裁决 |
| 《知势交易许可协议》 | 冻结上下文、七道质量门、最终许可与消费边界 | 复盘不能把禁止改为允许或复活过期许可 |
| 本规范 | 分层评价过程、结果、偏差、反证和反馈建议 | 不执行上游或下游变更 |

发生冲突时，资金与数据安全、不可变历史、当时可见性、七道质量门和任务文件合同优先。

## 二、核心不变量

任何未来实现必须同时满足：

1. **原记录不可变：** 研究版本、知识快照、评议报告、决策卡和交易许可不得由复盘覆盖。
2. **追加而非改写：** 复盘以新记录追加；勘误或重新评价生成新复盘版本并引用前序版本。
3. **过程与结果分离：** 决策过程合规不等于结果盈利，结果盈利也不能证明过程合规。
4. **时间分区：** 现场重放只使用决策时刻已到达的信息；结果评价使用的数据必须单独标记为事后结果数据。
5. **版本精确：** 所有输入引用确切版本，禁止使用“当前”“最新”或同名对象猜测绑定。
6. **作用域一致：** 标的、方向、时间尺度、市场状态、观察窗口和许可有效窗口必须明确。
7. **无交易也复盘：** 允许、禁止、空仓、未消费、模拟未成交和执行失败都不能因没有盈亏而省略。
8. **反证必须保留：** 新支持证据不能删除原反证，新反证也不能抹去原决策当时的可见事实。
9. **单例不改规则：** 单次结果只能形成样本或问题，不得直接改变规则、参数或研究状态。
10. **无法判定是正式结论：** 数据缺失、窗口未结束、血缘断点或版本冲突时不得猜测归因。
11. **反馈无写权限：** 复盘只能提出新研究、重新评议、失效审查或治理变更建议。
12. **真实资金关闭：** 复盘完成不启用真实交易，也不构成启用证据。

## 三、复盘对象、身份与时间

### 3.1 复盘对象

复盘对象分为三层：

| 层级 | 必须评价的对象 | 核心问题 | 不负责 |
| --- | --- | --- | --- |
| 研究复盘 | 冻结研究版本、验证结果、支持证据、反证和状态转换 | 假设、方法、证据与适用范围是否仍成立 | 直接修改研究状态 |
| 决策复盘 | 冻结决策上下文、知识快照、九份前置报告、最终裁决报告 | 当时可见信息是否被完整、合规地处理 | 用事后信息重做旧决策 |
| 许可复盘 | 交易许可、消费或未消费记录、模拟执行记录、结果窗口 | 许可边界是否正确、是否被遵守及结果如何 | 改写许可或授权新交易 |

三层可以由同一复盘批次关联，但必须分别形成结论。研究问题错误、决策过程错误和执行
偏离是不同事实，不得合并为一个笼统的“预测错误”。

### 3.2 身份与版本

每份复盘记录至少具有：

```text
复盘编号
复盘版本
前序复盘版本
复盘层级集合
原始研究编号与研究版本
决策编号
交易许可编号与协议版本
知识快照版本
证据版本集合
复盘创建时间与冻结时间
结果观察窗口
结果数据截止时间
完整性指纹
```

不适用的引用必须明确写`不适用`并说明原因。必需引用缺失时，复盘不能冻结为完整记录。

复盘编号标识同一复盘问题，复盘版本标识一次不可变评价。补充结果窗口、纠正引用、
改变分类或加入新反证时必须生成新版本，旧版本继续可查询。

### 3.3 三类时间与两个信息集合

复盘必须区分：

- 事件时间：市场事件实际发生的时间；
- 到达时间：信息进入系统并可被使用的时间；
- 采集时间：信息被采集、转换或持久化的时间。

同时必须分离两个信息集合：

| 信息集合 | 时间边界 | 允许用途 | 禁止用途 |
| --- | --- | --- | --- |
| 决策现场集合 | 到达时间不晚于原决策数据截止时间 | 重放原研究、评议、质量门和许可 | 用事后数据补强旧许可 |
| 事后结果集合 | 原决策之后、结果数据截止时间之前的版本化信息 | 评价实际结果、失效触发和执行偏差 | 冒充当时可见证据 |

结果观察窗口必须在查看结果前由原研究、交易许可或独立复盘计划确定。若没有预先定义，
只能记录探索性观察，不能据此宣称原规则有效或失效。

## 四、输入合同

### 4.1 任务必需输入

每次复盘必须引用：

| 输入 | 最小内容 | 缺失或冲突时处理 |
| --- | --- | --- |
| 原始研究编号 | 研究编号、冻结版本、生命周期状态、验证结果与适用范围 | 研究层结论无法判定 |
| 决策编号 | 决策时间、数据截止时间、标的范围、主尺度和规则版本 | 决策层结论无法判定 |
| 知识快照版本 | 激活清单、节点、关系、证据和血缘版本 | 停止完整性评价 |
| 证据版本 | 支持证据、主要反证、来源、时间与作用域 | 不得评价证据充分性 |
| 交易许可结果 | 许可编号、允许或禁止、否决代码、边界、有效窗口和复盘要求 | 许可层结论无法判定 |
| 当时有效的风险约束 | 风险预算、止损、组合风险、仓位上限和纪律状态版本 | 不得评价风险合规 |

输入必须来自不可变记录。摘要、截图、人工回忆或网页链接不能替代原版本。

### 4.2 结果与执行输入

有结果评价时还必须引用：

- 预先定义的结果观察窗口和评价指标；
- 结果数据版本、三类时间、数据截止时间和质量状态；
- 允许状态对应的模拟消费、未消费、未成交、退出或执行失败记录；
- 禁止或空仓状态对应的同口径观察记录；
- 实际手续费、模拟滑点、资金费率和执行延迟；没有发生时写`不适用`；
- 逻辑失效、价格止损、退出和许可有效窗口触发记录；
- 数据、规则、风险和执行状态在观察期内的变化；
- 结果记录与决策、许可、模拟执行之间的血缘。

本阶段没有市场数据或模拟执行记录时，只能制定合同，不能虚构实例、结果或分类。

### 4.3 输入完整性门

复盘开始前必须检查：

1. 研究、决策、许可和知识引用是否属于同一决策链；
2. 决策现场集合是否只含当时已经到达的信息；
3. 事后结果集合是否与决策现场集合物理或逻辑分区；
4. 标的、方向、尺度、市场状态和窗口是否一致；
5. 内容指纹和血缘是否完整；
6. 原记录是否存在事后覆盖或无法解释的版本变化；
7. 结果数据是否达到预定观察窗口且质量足以评价。

任一必需条件不满足时，必须列出缺口并把相关结论记为`无法判定`，不能用旧数据、
相邻标的、其他尺度或人工估计补齐。

## 五、三层复盘合同

### 5.1 研究复盘

研究复盘必须检查：

1. 决策问题和可证伪假设是否在验证前冻结；
2. 数据、样本切分、基准、成本、参数和准入标准是否按原合同执行；
3. 是否只使用当时允许使用的数据，是否存在未来数据或时间穿越；
4. 支持证据、主要反证、失败样本和无法判定结果是否完整保留；
5. 标的、尺度、市场状态和有效时间是否被静默外推；
6. 研究结论是否优于简单基准且覆盖全部成本和风险；
7. 后续结果是否触发原失效条件，或形成新的可证伪反证；
8. 当前研究状态与证据状态是否仍需由独立评审重新评价。

研究复盘允许输出：

- 保持原研究状态的建议；
- 创建新研究版本并补充验证的建议；
- 发起淘汰或失效审查的建议；
- 登记新的反证、失败样本或适用边界候选；
- 提出新的研究任务候选。

研究复盘不得直接执行以上状态变化。

### 5.2 决策复盘

决策复盘分别评价过程完整性和判断质量：

| 检查域 | 必须核对 |
| --- | --- |
| 数据与时间 | 来源、三类时间、数据截止时间、质量与重放一致性 |
| 知识与版本 | 激活清单、知识快照、证据、规则、模型和风险版本 |
| 报告完整性 | 九份前置报告和最终裁决报告是否齐全、未超时、同上下文 |
| 证据使用 | 支持与反证是否同时处理，预测性关系是否达到允许状态 |
| 作用域 | 标的、方向、主尺度、市场状态和有效时间是否匹配 |
| 质量门 | 七道门是否逐一执行，否决与无法判定是否完整保留 |
| 裁决规则 | 是否坚持唯一许可、硬门优先和默认禁止 |
| 可解释性 | 判断依据、冲突处理、恢复条件和未知项是否清楚 |

复盘不能因为事后行情有利就把当时缺失的报告视为“实际上通过”，也不能因为行情不利
就把当时合规的禁止许可改成允许。

### 5.3 许可复盘

许可复盘必须覆盖全部最终许可状态和消费情况：

| 原许可或消费情况 | 复盘重点 |
| --- | --- |
| 允许且被模拟消费 | 标的、方向、尺度、仓位、窗口、止损、退出和成本是否在许可内 |
| 允许但未消费 | 未消费原因是否来自更保守判断、窗口失效、执行失败或记录缺失 |
| 允许但未成交 | 模拟价格、深度、冲击和有效窗口是否真实满足，是否应更早禁止 |
| 禁止或空仓 | 否决是否由当时事实支持，恢复条件是否明确，是否出现新研究问题 |
| 执行失败 | 许可是否错误评估执行条件，还是下游未遵守已有边界 |
| 许可过期或失效 | 是否停止消费并创建新决策，是否存在旧许可复用 |

禁止或空仓不能用“后来上涨”单独判定为错误。只有在预先定义、同口径、可重放的
反事实评价合同存在时，才能记录机会成本；该记录仍不能绕过研究准入。

## 六、过程与结果分类

### 6.1 两轴分类

复盘必须先评价过程，再评价结果。两个维度的取值为：

```text
过程评价：合规 / 不合规 / 无法判定
结果评价：有利 / 不利 / 中性 / 无法判定
```

“有利”或“不利”必须相对于原决策预先定义的方向、观察窗口、成本、风险和退出合同，
不能只看最终价格或账户盈亏。

### 6.2 正确与错误判断分类

| 分类 | 条件 | 正确解释 | 禁止解释 |
| --- | --- | --- | --- |
| 正确且结果有利 | 过程合规，判断在原合同内得到支持，结果有利 | 一项支持样本 | 已证明长期有效 |
| 正确但结果不利 | 过程合规，风险和反证处理正确，结果不利 | 可接受的不利样本或需检查校准 | 一次亏损即规则错误 |
| 正确且结果中性 | 过程合规，结果符合预先定义的中性区间或没有可执行机会 | 合规的空仓或中性样本 | 没有盈亏所以无需复盘 |
| 错误但结果有利 | 过程不合规或违反硬门，结果有利 | 危险的偶然成功 | 盈利证明可以放宽门槛 |
| 错误且结果不利 | 过程不合规，结果也不利 | 明确错误样本，需定位来源 | 只归因于市场运气 |
| 错误且结果中性 | 过程不合规，结果处于中性区间 | 仍需修复过程错误 | 没有损失所以过程可以保留 |
| 无法判定 | 过程或结果证据不足、冲突、未到窗口或不可重放 | 正式保留缺口与解除条件 | 猜测填入正确或错误 |

判断“正确”至少要求过程合规、版本一致、作用域匹配且没有违反硬门。结果有利只是辅助
证据，不能单独把错误过程变为正确。

### 6.3 禁止许可的评价

禁止许可的过程评价遵循同一标准：

- 当时存在硬门失败、证据不足、版本冲突或无法判定时，输出禁止属于合规；
- 后续出现有利行情不改变原禁止许可的历史正确性；
- 若后续证据表明原否决来自数据错误、错误版本、规则缺陷或执行条件误判，应记录为
  新反证和改进候选；
- 只有经过足够同类样本、同口径反事实和研究准入，才能评价某类禁止是否系统性错失
  净期望，不得用单次踏空降低准入门槛。

## 七、偏差与错误来源

### 7.1 错误来源分类

每个偏差可以关联多个来源，但不得用一个宽泛原因隐藏其他独立问题：

| 来源 | 判定依据 | 典型影响 |
| --- | --- | --- |
| 数据与时间 | 缺失、异常、延迟、乱序、重复、三类时间错误或未来数据 | 数据门、重放和全部下游失真 |
| 身份、版本与血缘 | 引用错误、指纹不匹配、快照断点或使用“最新版本” | 历史上下文无法证明 |
| 研究设计 | 假设不可证伪、基准不足、过拟合、成本遗漏或样本外错误 | 错误优势或错误淘汰 |
| 作用域 | 跨标的、尺度、市场状态或有效时间外推 | 局部结论被误作通用结论 |
| 证据评价 | 同源证据重复、反证遗漏、假设冒充已验证关系 | 优势门判断错误 |
| 决策与质量门 | 报告缺失、硬门未执行、冲突处理或默认禁止失效 | 最终裁决不合规 |
| 成本 | 手续费、滑点、资金费率、延迟或安全余量遗漏 | 名义优势不等于净优势 |
| 风险 | 风险预算、止损、组合风险或仓位推导错误 | 损失边界失真 |
| 执行 | 深度、冲击、精度、价格偏离、退出或窗口判断错误 | 理论机会不可成交 |
| 纪律 | 超频、暂停、累计风险、重新入场或日志不合规 | 合规许可被错误消费 |
| 结果随机性 | 过程合规且无已识别结构性错误，但单次结果不利或有利 | 需要样本积累，不能立即改规则 |
| 未知 | 当前证据不能安全归类 | 停止推断并提出解除条件 |

### 7.2 偏差分析要求

偏差分析必须写明：

1. 预期与实际分别是什么；
2. 差异出现在哪个对象、版本、时间和作用域；
3. 哪些事实支持该来源，哪些事实反对该来源；
4. 是否属于单次噪声、重复模式或当前无法判定；
5. 影响哪些研究、知识关系、质量门、许可或未来决策；
6. 在修复前的安全降级方式；
7. 解除“无法判定”所需的新证据。

不得使用“市场异常”“模型失灵”或“黑天鹅”等未给出证据和边界的词语替代归因。

## 八、反证合同

### 8.1 反证记录

每项新反证至少记录：

```text
反证编号与版本
反对的研究、关系、判断或许可字段
来源与证据版本
事件时间、到达时间、采集时间和数据截止时间
适用标的、尺度、市场状态和有效时间
反证强度所依据的可观察事实
与既有支持证据的独立性或同源关系
可能触发的失效条件
当前结论：支持失效审查 / 支持补充验证 / 无法判定
```

反证不能直接改写被反对对象。它先进入复盘记录，再按权限边界形成研究、知识治理或
决策协议的变更候选。

### 8.2 支持与反证冲突

冲突处理不得使用简单计票：

1. 检查来源独立性和同源重复；
2. 检查版本、时间、作用域和数据质量；
3. 检查是否触发预先定义的硬失效条件；
4. 分离过程错误与结果随机性；
5. 无法解释时保留冲突并停止升级；
6. 影响当前预测性关系时，建议从后续激活清单撤出并进入独立评审。

历史知识快照和许可仍引用当时版本，不因新反证被事后重写。

## 九、输出合同

### 9.1 必需输出

每个冻结复盘版本必须包含：

```text
复盘编号与版本
复盘层级
原始研究、决策、知识快照、证据和许可引用
判断依据
实际结果
过程评价与结果评价
正确与错误判断分类
偏差分析
错误来源
反证情况
影响范围
安全降级方式
是否需要新的研究任务
建议的反馈路径
无法判定项与解除条件
评审引用
完整性指纹
```

任务要求的六项输出解释如下：

| 输出 | 必需内容 |
| --- | --- |
| 判断依据 | 原决策时刻可见事实、版本、主要支持、主要反证和质量门 |
| 实际结果 | 预定窗口、同口径指标、结果数据版本、成本和执行情况 |
| 偏差分析 | 预期与实际差异、影响对象、证据和安全影响 |
| 错误来源 | 第七节分类、支持事实、反对事实和无法判定项 |
| 反证情况 | 新反证、同源关系、失效触发和待审查影响 |
| 是否需要新的研究任务 | `是`、`否`或`无法判定`，并给出理由和解除条件 |

### 9.2 新研究任务判定

只有满足以下任一条件时，复盘可以输出`是否需要新的研究任务：是`：

- 出现可证伪且不属于原研究范围的新问题；
- 同类偏差重复出现并有足够版本化证据；
- 原失效条件触发，需要新版本重新验证；
- 数据、成本、风险、执行或市场状态变化使原结论不再适用；
- 错误来源无法由现有任务合同安全修复，需要独立范围与验收。

该输出只是任务候选。后续必须：

1. 按`docs/研发中心/任务规范.md`创建独立任务文件；
2. 让任务文件先进入`main`；
3. 明确输入、输出、范围、安全边界和验收标准；
4. 再由执行器按任务中心选择规则执行。

复盘记录、GitHub Issue、评论或PR描述都不能替代任务文件。

## 十、反馈路径与权限

### 10.1 允许提出的反馈

| 发现 | 允许提出 | 必须经过 |
| --- | --- | --- |
| 新可证伪问题 | 新研究任务候选 | 任务中心与研究准入 |
| 新反证或失效触发 | 研究失效审查、关系降级或撤出候选 | 研究评审与知识治理评审 |
| 规则或质量门缺陷 | 新协议或规则版本候选 | 独立任务与架构评审 |

### 10.2 禁止的自动反馈

复盘不得自动：

- 把研究从淘汰或失效改为已纳入；
- 把待验证假设或相关观察升级为已验证关系；
- 修改激活清单、知识快照或历史血缘；
- 更改七道质量门、阈值、否决代码或风险预算；
- 调整模型参数、权重、仓位或交易频率；
- 把历史禁止改为允许；
- 创建真实交易订单或启用账户权限。

任何建议未通过对应评审前，当前安全结果保持不变；影响预测性证据时，未来许可默认禁止。

## 十一、历史重放与模拟交易复盘

### 11.1 决策现场重放

历史重放必须加载原决策绑定的：

- 数据快照和三类时间；
- 研究、知识、证据、规则、模型和风险参数版本；
- 激活清单与知识快照；
- 九份前置评议报告和最终裁决报告；
- 七道质量门、否决代码、仓位和许可边界；
- 完整性指纹。

至少比较输入引用、报告、门结果、最终许可、否决原因和仓位上限是否一致。使用事后
修订数据或当前版本得到相同结果，不能证明原现场可重放。

### 11.2 模拟交易复盘

未来模拟交易复盘必须：

1. 只引用明确标记为模拟的执行记录；
2. 验证执行是否在许可标的、方向、尺度、仓位、价格和时间边界内；
3. 分离许可错误、执行偏离、未成交和市场结果；
4. 计入模拟手续费、滑点、资金费率和延迟；
5. 保存未消费、拒绝消费、部分消费、退出和执行失败；
6. 不把模拟结果写回原许可或冒充真实成交；
7. 不以模拟通过作为真实资金启用条件。

### 11.3 样本级与集合级复盘

单条复盘只描述一个冻结对象链。需要评价校准、错误率、空仓质量、系统性踏空或规则
稳定性时，必须另行定义集合级研究：

- 固定样本选择和排除规则；
- 同口径比较允许、禁止、空仓和未执行；
- 报告样本量、观察窗口、成本、分布和不确定性；
- 按标的、尺度和市场状态分层；
- 防止只选择盈利、亏损或显著案例；
- 重新进入研究准入，不能由复盘记录直接形成生产结论。

## 十二、异常处理与安全降级

| 异常 | 复盘处理 | 后续安全结果 |
| --- | --- | --- |
| 必需引用缺失 | 列出对象与字段，不猜测补齐 | 相关结论无法判定 |
| 版本或指纹冲突 | 停止冻结并保留冲突集合 | 不提出规则放宽 |
| 决策现场不可重放 | 标记血缘或时间问题 | 进入数据审计候选 |
| 结果窗口未结束 | 保持观察，不提前分类 | 不改研究或许可 |
| 结果数据质量不足 | 保存现有事实与解除条件 | 结果评价无法判定 |
| 支持与反证冲突 | 保留双方版本并停止升级 | 预测性使用默认禁止 |
| 复盘版本并发冲突 | 拒绝覆盖，基于同一前序版本重提 | 旧版本保持有效历史 |
| 未知异常 | 记录审计事件并安全停止 | 不沿用旧许可或推测结论 |

复盘记录和日志不得包含密钥、密码、令牌、账户凭据或不必要的个人信息。

## 十三、未来实现验收场景

未来实现至少覆盖：

1. 缺少原始研究编号时研究复盘结论无法判定；
2. 决策、知识快照和许可不属于同一链路时拒绝冻结；
3. 决策现场重放拒绝数据截止时间后才到达的信息；
4. 事后结果数据不能进入旧决策现场集合；
5. 结果窗口未结束时不能提前分类为正确或错误；
6. 合规许可单次亏损可以分类为正确但结果不利；
7. 违反硬门但偶然盈利必须分类为错误但结果有利；
8. 合规空仓或中性结果可以分类为正确且结果中性；
9. 禁止许可不能仅因后续上涨被判定错误；
10. 允许、禁止、空仓、未消费、未成交和执行失败都有复盘入口；
11. 研究、决策和许可三层分别形成结论；
12. 同一偏差可以关联多个错误来源且保留各自证据；
13. 新反证不会覆盖旧支持证据或历史知识快照；
14. 修改已冻结复盘会生成新版本并保留前序版本；
15. 复盘不能直接修改研究状态、证据状态、规则或许可；
16. 新研究任务建议在没有任务文件进入`main`前不可执行；
17. 集合级结论必须重新进入研究准入；
18. 缺少市场数据时不会生成虚构实际结果；
19. 真实资金关闭时任何复盘结果都不能触发账户写入。

《知势》的复盘体系不奖励事后解释能力，而是约束系统诚实地区分：当时是否做对、
后来结果如何、为什么出现差异，以及证据是否足以采取下一步行动。

过程不合规时，盈利不能洗白错误；过程合规时，单次亏损不能迫使系统降低门槛。只有
可追溯、可重放、跨样本且重新通过研究准入的证据，才有资格推动规则和能力迭代。
