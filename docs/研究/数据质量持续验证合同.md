# 《知势》数据质量持续验证合同

> **没有当前批次证据，不沿用旧报告；质量通过不等于研究或交易放行。**

## 一、目的

本合同定义任务-000027的数据质量持续验证入口、冻结方案、批次身份、状态、比较、失效
和安全边界。持续验证复用既有`scripts/审计/审计数据质量.py`，每次显式调用生成一个
不可覆盖批次，不建立第二套扫描器，也不引入常驻调度系统。

持续验证只回答：冻结资产清单中的数据对象在本批规则和已观察范围内出现了哪些质量
事实、哪些事实无法判定，以及与身份完全一致的前一批次相比发生了什么变化。它不回答
市场方向、胜率、收益、研究准入或交易许可。

## 二、冻结方案

正式方案位于`config/审计/数据质量持续验证.json`。任何远端读取开始前必须校验并冻结：

- 方案版本和完整方案SHA-256；
- 底层审计规则版本和审计器SHA-256；
- 资产清单SHA-256；
- 检查项、状态映射和作用域SHA-256；
- SSH逻辑目标；
- 批次总超时、单成员超时、最大成员数、最大内存、最大输出字节数和最大日志字节数；
- 禁止远端写入、业务数据库正文、自动数据修复及自动下游放行的安全边界。

方案包含未知字段、缺少字段、清单指纹漂移、规则版本漂移或资源边界漂移时，入口必须
在SSH调用前失败，不得使用默认值继续。

## 三、只读执行链路

```text
冻结方案与资产清单
    ↓
生成确定性成员顺序
    ↓
调用既有审计器执行Schema阶段
    ↓
既有审计器冻结规则
    ↓
调用既有审计器执行质量阶段
    ↓
校验三份CSV与报告身份
    ↓
形成结果摘要与前序比较
    ↓
原子发布不可变批次和追加式索引
```

执行入口只使用Python标准库，通过参数数组启动底层审计器。底层审计器继续承担全部
远端扫描职责：SSH目标只允许逻辑别名`ubuntu`，远端程序通过标准输入执行且不落盘，
文件和SQLite只读，MySQL仅查询元数据。持续验证层不得复制、放宽或扩展远端探针。

当前阶段由Codex或人工显式调用一次入口产生一次批次；不新增守护进程、Cron、队列、
外部告警平台、GitHub密钥或生产调度服务。

## 四、成员身份与作用域

成员顺序固定按资产编号、逻辑主机、服务或项目、位置和格式排序。每个成员保存资产
编号、资产类型、逻辑主机、服务或项目、位置、格式和候选标的范围，但不从路径、文件名
或字段名猜测交易场所、市场类型、精确合约、主研究尺度或Schema业务语义。

正式作用域固定为：

- 标的：BTC、ETH分别保留候选覆盖，禁止跨标的补偿；
- 主研究尺度：4小时、8小时、24小时、48小时；
- 事后结果观察窗口：15分钟、1小时；
- 分组身份：标的、交易场所、市场类型、精确合约、数据资产和Schema确切版本。

现有资产清单不能证明精确场所、合约和尺度时，成员的精确作用域状态保持`无法判定`。
15分钟和1小时不得成为Market Regime分类、Market Event探测、主研究或交易许可尺度。

## 五、批次身份与不可变产物

每个验证批次使用以下内容生成内容寻址标识：

- 带时区冻结时间；
- 底层审计批次；
- 方案、规则、清单、Schema和作用域指纹；
- 四份底层聚合输出的文件指纹。

批次目录位于`artifacts/审计/数据质量持续验证/<验证批次>/`，必须包含：

- `验证清单.json`；
- `数据质量结果.csv`；
- `数据断档结果.csv`；
- `数据异常结果.csv`；
- `验证报告.md`。

`artifacts/审计/数据质量持续验证/批次索引.csv`只追加新批次身份与摘要。目标批次或
索引身份已经存在时必须失败，不得覆盖、合并或原地补写。发布前所有文件先在本机临时
目录完成列、行、身份、大小、指纹和敏感信息检查；失败不得发布半批次。

## 六、状态与计数守恒

每个成员只能得到一个主状态：

| 状态 | 判定 |
| --- | --- |
| 通过 | 全部必需检查完成，身份稳定，且底层结论为可用 |
| 拒绝 | 输入漂移、有限可用、不可用或其他已证明合同违反 |
| 无法判定 | 缺少形成通过或拒绝所需的时间、Schema、作用域或质量证据 |
| 失败 | 执行错误、超时、输出不完整或资源边界失败 |
| 未成熟 | 冻结观察窗口尚未结束 |
| 失效 | 已发布结论因上游版本、晚到数据、指纹冲突或规则变化不再有效 |

批次摘要必须保存候选总体、已观察和六种状态计数，六种状态之和必须等于候选总体。
记录数、结构缺失数、精确重复数、断档数和异常数量分别保存已知合计及无法判定成员数；
未知值不得补零。输入漂移优先判为拒绝，超时或执行失败不得被底层可用性文字覆盖。

## 七、前序比较与失效

只有方案、规则、Schema、资产清单和作用域五类指纹完全一致时，新批次才能与索引中的
前一批次比较。比较输出只保存预先定义的计数变化，不搜索最佳标的、状态、事件或窗口。

任一身份不同必须输出`不可比较`及不一致字段；没有前序批次时输出`无前序批次`。
不得因当前批次失败而返回旧报告。晚到数据、上游失效、规则或Schema变化需要新批次和
追加式失效记录，不得改写原批次。

## 八、资源与安全边界

- 底层审计器和持续验证层均设置有界的总超时与单成员超时；超时不自动重试为成功。
- 远端只读程序通过`RLIMIT_AS`执行冻结的内存上限；本地编排器记录子进程峰值RSS，超过上限
  或无法测量时失败关闭，不发布批次。
- 底层数据逐对象流式扫描；持续验证层只读取聚合CSV，不把市场数据集载入本机内存。
- 成员、单成员超时、内存、聚合输出和日志均受冻结上限约束；当前配置最多500个成员、
  单成员30秒、512 MiB地址空间、10 MiB输出和4 KiB日志。
- 仓库只保存聚合计数、状态、原因、时间范围、版本、成员元数据和SHA-256，不保存
  原始市场记录、查询结果正文、IP地址、远端用户名、密码、令牌或私钥。
- 禁止清洗、填补、删除异常、去重、重排、迁移、覆盖或修复原始数据。
- 禁止修改数据库、服务器、服务、权限、防火墙、生产配置或真实账户。
- 禁止模型训练、回测、胜率收益计算、交易判断、方向、仓位、订单或真实资金下单。

任何质量结果，包括`通过`，都不能自动升级研究生命周期、允许模型训练、形成预测优势
或授予交易许可。

## 九、复现入口

```bash
python3 scripts/审计/持续验证数据质量.py \
  --inventory artifacts/审计/数据源清单.csv \
  --plan config/审计/数据质量持续验证.json \
  --ssh-target ubuntu \
  --batch-root artifacts/审计/数据质量持续验证 \
  --timeout 3600
```

每次成功调用都必须返回新验证批次。相同内容在相同冻结时间形成相同身份并触发拒绝
覆盖；不同时间的新调用只能追加，不能修改历史批次。
