# 《知势数据验证阶段执行规范》V1.0

<!-- markdownlint-disable MD013 -->

> 数据验证决定哪些问题有资格被研究，不负责替数据、模型或结果背书。

- 文档性质：数据真实性验证阶段的执行、判定与输出合同
- 适用范围：BTC、ETH；4小时、8小时、24小时、48小时研究
- 当前状态：理论规范；外部状态以任务-000031最新脱敏执行记录为准，当前白名单逻辑别名`ubuntu`不可达，
  任务-000031及其后继仍阻塞；历史只读验证批次不代表当前环境恢复，阶段1证据门仍未通过
- 真实资金状态：关闭

## 一、目标、边界与职责

### 1.1 目标

本规范把数据资产发现、数据质量审计、历史现场重放和最小数据闭环连接为一套可执行的
阶段门，使每次数据验证都能回答：

1. 哪个来源、市场、标的、数据对象、时间范围和版本接受了验证；
2. 原始记录、字段语义、三类时间、质量、修订和血缘是否可证明；
3. 历史现场能否只使用当时已经到达的数据重放；
4. 哪些研究问题、标的和时间尺度被允许，哪些只能有限研究或必须停止；
5. 阻塞来自数据缺失、质量、时间、重放、成本、闭环还是证据本身不足；
6. 新数据到达或缺陷修复后，需要重跑哪些验证，而不是沿用旧结论。

本规范减少时间穿越、错误拼接、数据替代、范围外推和在证据不足时强行进入模型研究的
风险。它不证明任何指标、模型、胜率、收益或交易优势。

### 1.2 不在范围

本规范不：

- 访问服务器、数据库、对象存储、接口或真实市场数据；
- 采集、清洗、修订、删除、覆盖或迁移原始数据；
- 设计数据库表、部署服务、修改权限或配置防火墙；
- 实现数据发现、质量审计、历史重放或最小闭环程序；
- 训练模型、运行正式回测、模拟交易或真实资金交易；
- 用示例字段、推测值或相邻标的结果补齐验证结论；
- 把数据可用性结论自动升级为研究准入、知识关系或交易许可。

## 二、核心不变量

数据验证阶段必须同时遵守：

1. **任务顺序不可跳过：** 数据资产清单、质量审计、历史重放和最小闭环按依赖顺序执行。
2. **原始数据只读：** 验证不得为了提高通过率修改原始记录；修订必须形成新版本。
3. **精确版本引用：** 输入和输出引用版本标识与完整性指纹，不使用“最新”推断。
4. **三类时间完整：** 事件时间、到达时间和采集时间缺少任一必需语义时，不得证明无时间穿越。
5. **可见性优先：** 历史现场只允许读取到达时间不晚于数据截止时间的记录。
6. **验证单元独立：** 不同来源、市场、标的、数据对象、尺度和时间范围分别判定。
7. **关键硬门不可补偿：** 高质量价格数据不能补偿缺失到达时间，BTC与ETH不能互相补偿。
8. **部分可用必须限界：** 只有预先定义且经过验证的降级路径才能形成有限研究范围。
9. **证据不足不同于失败：** 无法取得或校验证据时输出`无法判定`，不能写为通过或不通过。
10. **结论只追加：** 新数据、修订或规则变化生成新验证批次，不覆盖旧报告。
11. **审计通过不等于优势：** 数据具备研究资格，不表示任何假设、关系或模型有效。
12. **默认安全停止：** 版本、时间、质量、重放、作用域或血缘冲突时，预测性研究停止。
13. **范围不得外推：** 标的、市场、方向、尺度、市场状态和时间范围必须逐项匹配。
14. **失败和阻塞保留：** 不可用、无法判定、阻塞与淘汰都是正式证据。
15. **交易许可隔离：** 任何数据验证结论都不能越过样本、优势、成本、风险、执行和纪律门。

## 三、验证对象、身份与粒度

### 3.1 验证批次

每次完整或局部验证创建独立验证批次，至少记录：

```text
验证批次标识
前序验证批次标识
触发原因
任务与执行主体引用
规则版本
输入集合版本与指纹
目标标的、市场、数据对象、尺度和时间范围
数据截止时间
开始、结束与冻结时间
运行环境与代码版本
验证单元清单
输出集合版本与指纹
异常、停止与未完成原因
```

相同输入重试也必须生成新批次，并引用前序失败或中止批次。幂等请求可以返回既有批次
身份，但不能生成无法区分的重复结论。

### 3.2 数据验证单元

最小判定粒度为：

```text
数据来源版本
市场与交易场所
标的与合约定义
数据对象版本
字段集合版本
研究时间尺度
事件时间范围
到达时间范围
数据截止时间
```

一个验证单元只产生一个数据可用性结论。若同一对象在不同时间段、来源、市场或尺度上的
证据不同，必须拆分单元；不得用整体平均掩盖局部断档或时间语义差异。

### 3.3 结论身份

数据可用性结论至少由以下内容共同限定：

- 验证批次与验证单元标识；
- 输入数据、规则、代码、配置和环境版本；
- 标的、市场、数据族、字段、尺度和时间范围；
- 数据截止时间及三类时间语义；
- 质量、重放和闭环证据版本；
- 结论生成时间、有效条件和失效条件。

任何限定条件变化都产生新结论版本。结论名称或创建时间不能替代版本身份。

## 四、进入验证阶段的输入合同

### 4.1 数据资产清单

每个验证单元必须引用任务-000003形成的数据资产清单版本，至少包含：

| 输入 | 必需内容 | 缺失时处理 |
| --- | --- | --- |
| 来源身份 | 提供者、接口、目录或频道的版本身份 | 无法判定 |
| 市场定义 | 现货、永续、交割、计价和合约语义 | 不得跨市场使用 |
| 标的身份 | BTC或ETH及精确合约 | 不得以名称猜测 |
| 字段合同 | 原始字段、中文映射、类型、单位和精度 | 不得进入质量验证 |
| 更新与修订 | 频率、预期延迟、补录、撤销和修订行为 | 不得证明实时可用 |
| 权限边界 | 只读访问方式和使用限制的引用 | 不得绕过权限 |
| 故障模式 | 中断、降级、重复和上游依赖 | 风险未知 |

数据服务器、数据库、表、目录或文件存在，只能证明资产被发现，不能证明数据可用。

### 4.2 数据版本与时间范围

必须冻结：

- 数据对象逻辑标识和版本标识；
- 内容或成员清单指纹；
- 事件时间、到达时间、采集时间及其时区；
- 数据截止时间；
- 记录数、分区和边界包含规则；
- 原始、标准化、派生层级及完整血缘；
- 纳入、排除、修订和异常处置规则版本。

无法证明某字段何时到达时，该字段不能进入正式历史研究。

### 4.3 数据质量结果

必须引用任务-000004形成的质量结果版本，至少覆盖：

```text
缺失与断档
到达延迟与超时
乱序
重复与去重血缘
异常及处置
修订与补录
字段、分区与跨来源一致性
实际覆盖范围
质量规则、阈值和统计口径版本
```

质量阈值必须在读取验证结果前冻结。事后改变阈值、排除异常区间或缩短时间范围，必须
生成新验证批次。

### 4.4 历史重放结果

必须引用任务-000005形成的重放结果版本，证明或否定：

1. 原现场只加载到达时间不晚于数据截止时间的记录；
2. 晚到、补采和事后修订数据不会进入旧现场；
3. 输入版本、配置、代码和环境可以取得且指纹一致；
4. 确定性输出完全一致，非确定性输出在预注册容差内；
5. 缺失输入、版本冲突和未来数据注入能够被拒绝；
6. 重放失败会保留差异、停止代码和中文原因。

没有正式重放证据时，价格或指标与事后数据相同也不能证明原现场可重放。

### 4.5 最小数据闭环结果

必须引用任务-000006的历史基线，以及任务-000029至任务-000036形成的新闭环证据，
由任务-000037最终审计至少覆盖：

- 来源、原始记录、质量、标准化、派生、快照和研究输入的完整血缘；
- 数据进入、失败、重试、修订、冻结、查询和失效路径；
- 成本、流动性及执行相关数据的最低闭环；
- 容量、保留、备份、恢复和完整性校验要求；
- 可重复执行的审计入口和版本；
- 是否允许进入简单基准模型阶段的明确结论。

任务-000029至任务-000036任一必需证据缺失时，任务-000037不能形成`可用`结论。

## 五、数据资产审计流程与阶段执行

### 5.1 阶段门顺序

```text
门0：执行资格与只读安全检查
    ↓
门1：数据资产身份与字段合同
    ↓
门2：版本、三类时间与数据截止时间
    ↓
门3：质量、覆盖与异常处置
    ↓
门4：历史现场重放与未来数据拒绝
    ↓
门5：最小数据闭环、成本和血缘
    ↓
门6：允许研究范围与阻塞项冻结
```

每道门都输出`通过`、`有限通过`、`失败`或`无法判定`及证据引用。后续门可以为了收集
诊断证据而运行，但不能覆盖前序硬门失败。

### 5.2 门0：执行资格与只读安全

开始真实验证前必须确认：

- 相关任务文件已获执行资格，依赖和服务器条件满足；
- 工作范围、目标环境、数据对象和只读方式明确；
- 不需要修改数据库、权限、防火墙、服务或原始数据；
- 日志和报告不会记录密钥、令牌、密码或账户凭据；
- 验证代码、配置、依赖和环境能够冻结版本；
- 失败时能够停止且不留下半套结论。

任一条件不满足，验证批次状态为`阻塞`或`已中止`。

### 5.3 门1至门5

| 阶段门 | 核心问题 | 不可补偿失败 |
| --- | --- | --- |
| 资产门 | 来源、市场、标的、合约和字段是否唯一可识别 | 来源或市场定义冲突 |
| 时间门 | 三类时间、时区、截止时间和可见性是否完整 | 到达时间缺失或无法证明 |
| 质量门 | 缺失、延迟、乱序、重复、断档、异常和修订是否量化 | 关键字段不可用或处置无血缘 |
| 重放门 | 原现场是否只使用当时可见版本并拒绝未来数据 | 未来数据进入或必需版本漂移 |
| 闭环门 | 来源到研究输入及成本证据是否完整可追溯 | 原始引用、成本或关键血缘断裂 |

### 5.4 门6：冻结允许研究范围

只有前序证据完整后，才能按验证单元冻结允许研究范围。冻结后新增数据、修订、补采、
阈值变化或重放器变化不会自动扩大范围，必须创建新验证批次。

## 六、数据可用性判定

### 6.1 四种结论

| 结论 | 条件 | 允许动作 | 禁止动作 |
| --- | --- | --- | --- |
| 可用 | 全部必需硬门通过，任务-000037明确允许进入基准阶段 | 在冻结范围内申请简单基准研究 | 宣称已有优势或直接进入交易许可 |
| 有限可用 | 硬门未失败，仅非关键数据受限，且存在预注册、已验证的降级路径 | 只执行明确列出的描述性或有限基准研究并补采 | 代理缺失关键字段、扩大标的或尺度 |
| 不可用 | 任一关键硬门失败，或已证明数据不满足合同 | 修复数据闭环、质量或重放问题 | 预测性研究、正式回测和生产使用 |
| 无法判定 | 必需证据缺失、冲突、未完成或无法校验 | 保留现有事实并列出解除条件 | 猜测通过、猜测失败或借用其他证据 |

`有限可用`不是较低质量的`可用`。它必须明确允许的问题、字段、时间范围、方法和停止
条件；未列出的用途全部禁止。

### 6.2 判定规则

1. 任一不可补偿硬门失败，结论为`不可用`；
2. 任一必需证据缺失或冲突且尚未证明失败，结论为`无法判定`；
3. 只有非关键输入缺失、降级路径已预注册并有验证证据时，才可为`有限可用`；
4. 只有所有必需条件通过且最终闭环审计明确放行，才可为`可用`；
5. 多个验证单元不能取平均、投票或使用最高状态形成总体通过；
6. 汇总结论不得高于其所依赖的最低关键单元状态。

### 6.3 关键判定矩阵

| 维度 | 可用最低证据 | 失败或缺失时 |
| --- | --- | --- |
| 来源与授权 | 来源版本、市场定义、只读边界完整 | 无法判定或不可用 |
| 字段语义 | 中文映射、类型、单位、精度和空值明确 | 相关字段不可用 |
| 三类时间 | 事件、到达、采集时间可区分且带时区 | 预测性研究不可用 |
| 数据截止 | 可重复构造当时可见集合 | 无法重放 |
| 质量 | 关键缺失、延迟、乱序、重复、断档和异常已量化 | 限定范围或不可用 |
| 修订血缘 | 原值、修订原因、规则和新版本可追溯 | 不得使用修订结果 |
| 样本覆盖 | 标的、尺度、方向、状态和时间范围达到预注册要求 | 无法判定或限定研究 |
| 历史重放 | 原版本可取得、指纹一致并拒绝未来数据 | 不可用 |
| 成本数据 | 手续费、滑点、资金费率和延迟有可靠版本依据 | 不得形成成本后结论 |
| 最小闭环 | 来源到研究输入双向可查且最终审计放行 | 不得进入基准阶段 |

## 七、允许研究范围合同

### 7.1 最小字段

每条允许研究范围至少记录：

```text
允许研究范围标识与版本
验证批次和验证单元引用
数据可用性结论
研究问题
标的、市场和合约
数据族与字段集合
4小时、8小时、24小时或48小时时间尺度
事件时间范围、到达时间范围和数据截止时间
允许的方法：描述性分析 / 简单基准 / 不允许预测性研究
允许的特征、标签和成本输入
禁止用途
质量、重放和闭环证据引用
限制、停止与失效条件
复验触发条件
冻结时间
```

未在范围中明确允许的用途，默认禁止。

### 7.2 数据状态到研究动作

| 数据状态 | 研究动作 |
| --- | --- |
| 数据够用 | 仅在冻结范围内进入简单基准研究，并重新通过研究准入 |
| 数据部分可用 | 限定研究问题、标的、尺度、字段和时间范围，同时提出补采或修复任务候选 |
| 数据不可严格重放 | 停止预测性研究，优先修复时间语义、版本和数据闭环 |
| 数据不可用 | 不进入模型或正式回测，只保留失败证据和解除条件 |
| 数据无法判定 | 不推断可用性，补齐必需输入后创建新验证批次 |

### 7.3 第一阶段范围边界

- BTC、ETH分别形成独立结论；
- 4小时、8小时、24小时、48小时分别证明覆盖和标签成熟条件；
- 现货、永续、其他交易所和不同合约不得静默拼接；
- 做多与做空所需成本、流动性和标签条件分别检查；
- 某时间段可用不代表更早或更晚时间段可用；
- 数据可用不代表所有市场状态样本充足。

## 八、禁止外推与标的扩展

### 8.1 BTC、ETH

禁止：

- 用BTC或ETH的数据质量、重放或研究结果替代另一标的证据；
- 用BTC的市场代表性叙事替代其自身数据审计；
- 用ETH生态叙事补齐无法映射的数据字段；
- 用总体相关性把一个标的的样本、成本或风险结论复制给另一个标的；
- 用较短尺度通过替代较长尺度的样本和标签成熟要求。

若任一标的数据不足，允许结论是`有限可用`、`不可用`或`无法判定`，并相应缩小
研究范围。不得为了保持两个标的齐全而降低门槛，也不得借用另一标的证据。

### 8.2 新增标的或市场

新增标的、交易场所、市场类型或时间尺度必须：

1. 形成独立任务文件；
2. 重新执行资产、时间、质量、重放和闭环验证；
3. 独立证明成本、流动性、样本与风险边界；
4. 说明新增范围减少哪类错误交易、提升哪类净期望或增强哪项风险约束；
5. 不复用原范围的`可用`状态作为新范围证据。

## 九、输出合同

### 9.1 数据验证报告

每个验证批次输出不可变报告，至少包含：

```text
报告标识与版本
验证批次、规则、代码、配置和环境版本
输入清单与完整性指纹
验证范围与明确排除范围
各阶段门结果和证据引用
各验证单元的数据可用性结论
允许研究范围版本
阻塞项和解除条件
异常、失败、无法判定和未执行项
已知限制
数据与安全影响
报告冻结时间
```

报告必须分别列出事实、判定和建议，不得把计划中的验证写成已经执行。

### 9.2 数据可用性结论

每条结论至少包含：

| 字段 | 要求 |
| --- | --- |
| 结论状态 | 可用、有限可用、不可用或无法判定 |
| 精确作用域 | 来源、市场、标的、数据对象、字段、尺度和时间范围 |
| 依据 | 资产、质量、重放和闭环证据版本 |
| 限制 | 缺失、降级、禁止用途和不适用范围 |
| 失效条件 | 来源、版本、质量、时间、规则或环境变化 |
| 解除条件 | 从有限、不可用或无法判定进入新验证所需证据 |

### 9.3 允许研究范围

允许研究范围使用第七节合同，并必须与研究版本绑定。范围变更生成新版本，不能补写旧
实验或旧研究记录。

### 9.4 阻塞项清单

每个阻塞项至少记录：

```text
阻塞标识

阻塞类别
支持证据
当前状态
安全降级
解除条件
建议责任任务
复验入口
```

阻塞类别至少包括：访问、来源、字段、时间、质量、重放、成本、闭环、权限、版本、
环境和未知。

### 9.5 后续数据任务建议

建议必须说明问题、证据、影响、解除条件、交付物和验收入口。建议本身不能直接执行；
只有形成`docs/研发中心/任务/任务-NNNNNN.md`并进入`main`后，才成为可执行任务。

## 十、报告生成与冻结流程

1. 冻结验证规则和全部输入版本；
2. 检查输入完整性，缺失项先记录为`无法判定`；
3. 按验证单元执行阶段门，保留失败和中止记录；
4. 生成单元级结论，禁止先写总评再补证据；
5. 从单元结论推导允许研究范围，使用最低关键状态；
6. 汇总阻塞项和解除条件；
7. 运行完整性、时间穿越、外推和敏感信息检查；
8. 冻结报告、范围、阻塞清单和输出指纹；
9. 登记复验触发条件；
10. 经独立评审后，只有任务-000037可以决定是否进入基准模型阶段。

## 十一、与下游治理的连接

### 11.1 研究准入

研究准入只能在允许研究范围内接收数据，并仍需独立验证：

- 可证伪假设和决策问题；
- 样本切分、简单基准和样本外方法；
- 手续费、滑点、资金费率和执行延迟；
- 主要反证、失败样本、稳健性和校准；
- 标的、尺度、市场状态和有效时间。

数据`可用`不能自动把研究状态升级为候选、试运行或已纳入。

### 11.2 知识图谱

数据验证报告和可用性结论只作为版本化证据引用。它们可以说明来源、字段、质量和
可见性，不证明预测性关系成立，也不能把关系加入激活清单。

### 11.3 交易许可

数据验证只为数据门提供输入。即使数据门通过，样本、优势、成本、风险、执行、频率与
纪律门仍须独立通过。任一必需数据结论为有限、不可用、无法判定或超出允许范围时：

```text
交易许可：禁止
建议仓位：0
```

### 11.4 研究与决策复盘

复盘引用原验证批次、结论和范围版本，只能追加后续评价。新数据或后续修订不得回填旧
验证现场；如触发失效条件，创建失效记录和新验证批次。

## 十二、复验与失效

以下任一事件触发复验：

- 数据来源、接口、市场或合约定义变化；
- 字段、单位、精度、时区或时间语义变化；
- 补采、回补、修订、异常处置或去重规则变化；
- 关键缺失、延迟、乱序、重复或断档超过原边界；
- 重放代码、配置、环境、容差或指纹算法变化；
- 成本、流动性或执行数据来源变化；
- 发现未来数据、血缘断点、版本冲突或错误外推；
- 扩大标的、市场、尺度、时间范围或研究问题；
- 研究或复盘产生新的反证。

失效只影响未来使用。历史报告、研究和决策继续引用原版本，并明确记录当时状态。

## 十三、异常处理与安全降级

| 异常 | 处理 | 研究结果 |
| --- | --- | --- |
| 服务器或来源不可访问 | 记录访问阻塞和解除条件 | 无法判定 |
| 权限不足 | 停止，不修改权限或防火墙 | 无法判定 |
| 数据版本或指纹冲突 | 隔离冲突并停止相关单元 | 不可用或无法判定 |
| 到达时间缺失 | 不以事件时间代替 | 预测性研究不可用 |
| 晚到数据进入旧现场 | 判定重放失败并调查 | 不可用 |
| 关键字段断档 | 保留范围和质量证据 | 限定范围或不可用 |
| 非关键字段缺失 | 仅使用已验证降级路径 | 有限可用或无法判定 |
| 成本数据不足 | 不计算推测成本后优势 | 不得进入优势研究 |
| 任一标的证据不足 | 缩小对应标的范围 | 不借用另一标的证据 |
| 输出写入部分失败 | 整批不冻结，保留失败记录 | 无法判定 |
| 未知异常 | 安全停止并登记未知项 | 无法判定 |

日志、报告和指纹输入不得包含密钥、密码、令牌、账户凭据或不必要的个人信息。

## 十四、未来实现验收场景

未来执行至少覆盖：

1. 缺少数据资产清单版本时不会开始质量验证；
2. 数据库或文件存在不会自动形成可用结论；
3. 来源、市场、合约或字段身份冲突时相关单元停止；
4. 三类时间缺少到达时间时不能证明无时间穿越；
5. 晚到或补采数据不能进入原历史现场；
6. 原始数据修订生成新版本且旧版本可查询；
7. 缺失、延迟、乱序、重复、断档和异常均有量化证据；
8. 质量阈值事后变化会生成新验证批次；
9. 重放使用原绑定版本而不是当前最新版本；
10. 未来数据注入会被自动拒绝并记录失败；
11. 确定性与非确定性重放按预注册规则判定；
12. 关键血缘或成本数据缺失时不能进入基准阶段；
13. 每个验证单元只形成一个四态结论；
14. 多单元汇总不能使用平均或投票覆盖硬门失败；
15. 有限可用结论明确允许问题和禁止用途；
16. 无法取得证据时输出无法判定而不是猜测；
17. BTC与ETH分别形成结论；
18. BTC与ETH结果不能互相补齐证据；
19. 4小时通过不能自动外推到8小时、24小时或48小时；
20. 现货与永续不能在缺少映射时直接拼接；
21. 数据可用不会自动升级研究或知识关系状态；
22. 数据门通过不会自动生成交易许可允许；
23. 新来源、版本、规则或范围变化触发复验；
24. 后续修订不会改写旧验证、研究或决策现场；
25. 真实资金关闭时任何验证结果都不能触发账户写入。
