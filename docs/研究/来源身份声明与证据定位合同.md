# 来源身份声明与证据定位合同

## 目的

本合同为任务-000079的结构化来源身份声明输入和当前证据复采定义唯一格式。它只回答“某个候选成员的来源身份是否被当前证据逐字段证明”，不回答数据质量、预测优势、研究准入或交易许可。

## 固定研究边界

- 仅覆盖BTC、ETH；主研究尺度固定为4小时、8小时、24小时、48小时。
- 15分钟、1小时只能作为事后结果观察窗口，不能升级为市场状态、事件探测或交易许可尺度。
- BTC和ETH分别统计，缺失证据不得跨标的补偿。

## 身份声明字段

每条声明必须同时包含以下字段：来源提供者、交易场所、市场类型、标的身份、精确合约、数据对象、Schema确切版本、授权边界、字段中文映射。字段值必须来自已登记的结构化声明来源，不得从路径、文件名、服务名、表名或历史聊天推断。

## 证据定位与指纹

声明记录必须绑定任务合同版本、成员编号、资产编号、当前输入成员SHA-256、声明来源路径和字节指纹、字段定位、Schema指纹、授权快照指纹、采集时间及撤销事实。声明缺少任一绑定时，字段值统一为`未知`，状态只能为`无法判定`；历史`拒绝`状态不得被复采覆盖为通过。

## 复采与状态

远端只允许通过`ubuntu`逻辑别名执行无交互、串行、资源有界的脱敏只读探针。探针可观察白名单文件的stat元数据，但不得读取业务正文、价格、成交、订单簿、账户、凭据或生产数据库记录。数据库对象只允许保留已批准的元数据范围摘要；结构观察不能证明来源身份。

状态集合为`已证明`、`拒绝`、`无法判定`、`失败`、`未成熟`、`失效`。只有九个身份字段、当前输入成员、Schema和授权证据全部匹配才能进入`已证明`；本任务没有完整声明时，成功批次也必须是失败安全的`无法判定`或历史`拒绝`。

## 批次与撤销

批次使用临时目录写入，完成校验后以原子且不可覆盖方式发布；批次清单记录输入、规则、探针、执行器、授权和输出指纹。输入漂移、越权、敏感输出、超时、状态不守恒或历史目录存在时拒绝发布。任何新证据冲突都通过追加批次表达，不覆盖历史批次。

## 结论边界

描述性身份差异不能推导因果关系、预测优势、胜率、收益、研究准入或交易许可。本合同完成不代表`ZS-DATA-GAP-001`关闭，也不代表阶段1或阶段2放行。
