# 知势

> **宁可错过，不做低胜率交易。**

知势是一套以“识势而动”为核心方法的智能交易决策系统。

它不追求预测全部行情，不追求提高交易频率，也不以捕捉最大涨幅为目标。知势只寻找具有统计优势、风险边界清晰、逻辑可以验证的交易机会；当优势不足时，默认空仓。

## 项目使命

- 预测资金行为，而不是机械预测价格。
- 从 BTC、ETH 中寻找未来4小时、8小时、24小时与48小时内最值得交易的标的。
- 每日只筛选0～2次高质量机会。
- 优先捕捉风险可控的短周期波动，而不是追逐偶发性暴涨。
- 将每一项研究转化为可验证、可回测、可否决的决策依据。

## 核心原则

1. 宁可错过，不做低胜率交易。
2. 预测资金，而不是预测价格。
3. 没有可证明的优势，默认空仓。
4. 先定义损失边界，再讨论潜在收益。
5. 决策质量高于交易频率。
6. 长期复利高于短期暴利。
7. 每个指标必须回答一个明确问题，否则不纳入系统。
8. 不设置强制每日收益目标，不因踏空或亏损降低准入标准。
9. 任何结论都必须能够回到历史现场重新验证。

### 准入边界

《知势》把阶段1数据证据门、研究准入、单次交易许可和真实交易准入分开管理。数据
证据只决定缺口与适用范围；研究准入只决定研究版本能否推进；交易许可只裁决一个
冻结决策的`允许/禁止`；真实交易准入是独立的系统级能力门。任何层次都不能自动升级
下一层次，当前真实交易准入固定为`关闭`。阶段1未完成、阶段2被阻塞，研究、模拟、
影子决策和历史重放均不会开启真实资金交易。

标准闭环：

```text
架构层创建任务文件并进入main
    ↓
Codex读取任务中心
    ↓
独立分支执行、验证、提交和创建PR
    ↓
任务状态更新为待评审
    ↓
架构评审
    ├── 通过：受控合格PR按精确头SHA自动合并
    │          合并后通过独立状态闭环PR标记已完成
    └── 未通过：更新或创建修复任务文件并继续迭代
```

`任务登记`、任务交付和合并后状态闭环均由`main`可信规则复验。允许自动交付的任务类型
精确限定为文档、治理、研究规范、数据治理、数据审计、数据工程、基础设施验证、策略研究、
研究工程、模拟交易、测试和工具，并同时受路径、普通Git对象、文件数量、体积和敏感信息
硬门约束。当前系统只进行策略研究和基于实时数据的模拟交易，不连接真实资金；生产写入、
凭据、原始数据破坏和不可逆操作不在自动授权范围。完整规则见
[《PR自动合并策略》](./docs/治理/PR自动合并策略.md)。

没有Git提交不算完成；没有PR不算完成；没有验收不算完成；没有证据不算完成。

## 七道交易许可质量门

任何交易必须依次通过：

1. 数据门；
2. 样本门；
3. 优势门；
4. 成本门；
5. 风险门；
6. 执行门；
7. 频率与纪律门。

任一硬门槛失败：

```text
交易许可：禁止
建议仓位：0
```

知势不是让系统越来越会“看指标”，而是让系统越来越会做出可以解释、可以验证、可以约束风险的决策。
